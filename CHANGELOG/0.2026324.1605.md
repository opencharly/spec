# 0.2026324.1605 — feat(storeroot)!: add the data root, search paths, and cache-root builder paths

## Summary

Adds the durable data root, the XDG search paths and the injected resolver seam to the one
contract resolver, then routes every spec-owned host path through it.

- **`storeroot`** gains `RootData` (`$XDG_DATA_HOME/charly`), `DataDir()`, `Base()` (the
  unsuffixed XDG base for another application's directory), `BaseDirs()`/`Dirs()` (the
  `XDG_CONFIG_DIRS`/`XDG_DATA_DIRS` search path), `Search()`, and the `Resolver` type — the
  D-STORE-8 seam that resolves from injected bases and environment. `Dir`/`CacheDir` keep the one
  `CHARLY_CACHE_DIR` override and the documented runtime→state fallback. The existing `XDG()`
  implementation from #406 is the engine; no dependency is added.
- **Call sites** resolve through the resolver instead of hand-building paths: the runtime config
  (`hostenv`), the deploy overlay (`spec`), the quadlet/systemd directories (`spec`), the
  image/localpkg build locks (`lock`), and the builder cache mounts/env (`exec`). The builder's
  `PIXI_CACHE_DIR`/`RATTLER_CACHE_DIR` now follow the cache root, so `CHARLY_CACHE_DIR` relocates
  them with every store.
- **`spec/exec.UserScopeEnv`** now returns `(map[string]string, error)` because resolving the cache
  root can fail. Its two sdk call sites are updated in the sdk leg of
  opencharly/opencharly#1207.
- **Host directory names use `charly`, not `opencharly`**: the machine-venue env.d is
  `${XDG_CONFIG_HOME:-~/.config}/charly/env.d` (the preamble honors `XDG_CONFIG_HOME`), and the
  `opencharly/installed` comments are renamed. The sdk/charly/box occurrences follow in their
  producer legs under opencharly/opencharly#1207.
- The schema comments now name the XDG paths; `charly task cue-gen` is a no-op after the update.
- **Two incidental loop modernizations** in touched files, with no behavior change:
  `cache/cache.go` (`for i := range excess`) and `container/local_image_coneb.go`
  (`for line := range strings.SplitSeq(...)`). They were the linter's pre-existing suggestions in
  files this PR already edits.

## Change classification

**Breaking change + rollback:** `spec/exec.UserScopeEnv` now returns `(map[string]string, error)`;
its two sdk call sites (`sdk/deploykit/localpkg.go`, `sdk/deploykit/venue_builder.go`) are updated

`${XDG_CONFIG_HOME:-~/.config}/opencharly/env.d` to `.../charly/env.d`, so an operator's existing
env.d file must be moved; the preamble does not read the old path (no fallback, R5). `RootData`,
`DataDir`, `Base`, `BaseDirs`, `Dirs`, `Search` and `Resolver` are additive. The rollback is to
revert this commit; the old `UserScopeEnv` signature and the old env.d path return, and the sdk leg
must be reverted with it.
