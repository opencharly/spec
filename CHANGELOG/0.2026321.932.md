# 0.2026321.932 — feat(schema): port the secret delivery contract -- #SecretUse and #AbsPath (P07 unit 1)

## Summary

**Third time tonight, same gap.** `#SecretUse{src?, dst?, optional?}` and `#AbsPath` were declared in
`DESIGN.cue` (:474-480, :77) and in **no shipped schema**:

**At `main` before this PR**, \`#SecretUse\` appeared in neither the generated Go nor the shipped schema:

```console
# measured on origin/main, before this change
$ git show origin/main:spec/cue_types_gen.go | grep -c 'type SecretUse' ; git show origin/main:schema/secret.cue 2>&1 | head -1
0
fatal: path 'schema/secret.cue' exists on disk, but not in 'origin/main'
```

So the contract said **where a secret value goes** and no code could express it. This is a **port**, the
same class as `spec#344` (audit) and `spec#352` (bind) — and the third instance of one pattern: *a design
declaration is a promise; a shipped one is a capability.*

| shape | what it is |
|---|---|
| `#AbsPath` | a literal absolute path — `=~"^/[^\$]*$"` |
| `#SecretUse{src?, dst?, optional?}` | where the value comes from, where it lands, whether absence is allowed |

**Why the two paths are the whole point.** D-SEC-1 (`DESIGN.md:2511`): *"Secrets come only from the
configured backend; they never enter the store, artifacts, labels, **IR**, state or output."*
`DESIGN.md:2983` adds the other half: *"there is no `get`: a value reaches a consumer as a `secret:` need,
never as text."* So a secret `use:` carries **paths**, and offers nowhere to put a value — the same
structural guarantee `#Redacted` gives the audit record.

**And `[^\$]` is load-bearing rather than cosmetic.** It keeps a VARIABLE out of a path, so `src`/`dst`
can never expand into a value. That closes the leak **one layer down** — through the path instead of
through the value — which is a way a schema can undo its own guarantee while looking careful.

`optional` is the one behavioural flag: a missing source does not fail the deployment. It exists because
"this works without the credential" is a real intent, and the alternative — authoring a placeholder
secret to satisfy a required field — is exactly how a real credential ends up in an authored file.

Four tests, each driving a rule to both sides — and the first exists because the review caught the body
claiming a constraint was "load-bearing" while nothing tested it:

```console
$ go test -count=1 -v -run 'TestAbsPath|TestSecretUse|TestOptional|TestTheSecret' ./schema/
--- PASS: TestAbsPathRefusesAVariable (0.05s)
--- PASS: TestSecretUseHasNoValueBearingField (0.00s)
--- PASS: TestOptionalReachesTheWire (0.00s)
--- PASS: TestTheSecretContractIsDesigns (0.00s)
ok  	github.com/opencharly/spec/schema	0.065s
```

**`TestAbsPathRefusesAVariable` — the half that proves the guarantee, with its own R7 proof.** It compiles
the SHIPPED schema and refuses two inputs: a `$`-bearing path and a relative one. Weakening the definition
to the exact re-spelling the review named, then restoring it:

```console
$ sed -i 's|=~"^/[^$]*$"|=~"^/.*$"|' schema/secret.cue
$ go test -count=1 -run TestAbsPathRefusesAVariable ./schema/
--- FAIL: TestAbsPathRefusesAVariable (0.06s)
    secret_port_test.go:56: #AbsPath accepted a path carrying `$` — a secret value could be smuggled
      through variable expansion (D-SEC-1)

$ <restore>
$ go test -count=1 -run TestAbsPathRefusesAVariable ./schema/
ok  	github.com/opencharly/spec/schema	0.063s
```

**`TestSecretUseHasNoValueBearingField`** asserts on the TYPE'S FIELD SET, not on marshaled JSON. The first
version searched the output for `"value"` — and since every field here carries `omitempty`, a future
`Value string` left **unset** would be omitted and the search would not fire. It guarded only against a
value field *lacking* `omitempty`: a guard that reads as protection and provides none. Reflection catches
the field the moment it is declared, set or not.

**`TestOptionalReachesTheWire`** — a flag that cannot be expressed cannot be honoured.

**`TestTheSecretContractIsDesigns`** — the port's identity check: the wire keys are DESIGN's own
(`"src"`, `"dst"`).
