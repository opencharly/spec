# 0.2026328.920 — fix(refs): ClearCache clears the cache section, never the per-host deploy config

## Summary

`charly cache clear/refresh` **deleted the per-host deploy config**
(`~/.config/charly/charly.yml`) to clear a `cache:` section — taking every deploy, provides,
ledger and system entry with it. The next resolution's `save()` (correctly a preserving
yaml.Node read-modify-write) then rebuilt the file holding nothing but `cache:`.

Measured on a real host on 2026-11-24: after a `charly cache refresh` the file went from ~94 KB
with seven deploys to 50 KB of cache, while every deployed container kept running — the config was
gone but the machines were not. Only the containers' systemd quadlets still described them.

**Fix:** `ClearCache` clears the section through the **same writer `save()` uses** (set the maps
empty, then `save()` → the cache is rewritten empty, every other key preserved) and never removes
the file. The stale comment claiming a removal goes with it.

`charly cache refresh` behaviour changes once a spec release carrying this is pinned by charly;
the unit test is the gate here.
