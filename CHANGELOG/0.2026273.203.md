# 0.2026273.203 — feat(spec)!: ExtraCandyRef carries its SCOPE + ScopeIsBox conflict predicate (supersedes #187)

## Summary

Fixes `opencharly/charly#739`: a candy ref's **origin was lost** when appended to a flat
`[]string`, so the collector invented the **constant** label `"deploy=add_candy"` — collapsing every
deploy into one bogus scope.

**Change (the `spec` leg of `spec → sdk → charly`):**

- `ResolveOpts.ExtraCandyRefs` is now **`[]ExtraCandyRef`** — each entry carries the ref **and** the
  composition scope that named it (`"box=<qualified-name>"` | `"layer=<candy>"` |
  `"kind:local=<template>"` | `""`). CUE-sourced (`schema/buildwire.cue` `#ExtraCandyRef` →
  `cue_types_gen.go`, SDD).
- **`ScopeIsBox` / `ScopePrefixBox`** — the ONE predicate/prefix saying a **BOX is the only
  conflict-eligible composition unit** (a `layer=` / `kind:local=` / `deploy=` / `""` scope is
  informational). `BoxScope` / `LayerScope` / `KindLocalScope` construct the labels from the prefix.
  `ScopedExtraCandyRefs` is the ONE constructor; `ExtraCandyRefStrings` is the projection the
  plugin-word collectors use. The `sdk` arbiter consumes `ScopeIsBox` — no hardcoded prefix.

Successor of the auto-closed `#187` (same branch/head; its 6 verdicts were body-evidence findings,
all addressed below). The `sdk` and `charly` legs are the immediate successors of this cutover.
