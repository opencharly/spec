# 0.2026302.1756 — fix(refs): a transient git fault class was spelled out of the vocabulary, so it was never retried

## Summary

**What this changes.** `refs/git.go`'s transient-fault classifier — the vocabulary that decides whether a failed git subprocess is retried or given up on — missed an entire fault class, and the miss was invisible until a transient transport fault aborted a corpus regeneration at entity 253 of ~1400.

The classifier carried the pattern `http/2` — **with a slash**. Git writes `Error in the HTTP2 framing layer` — **without one**. The two never met, so curl's HTTP/2 framing fault was classified **permanent**: `runGitOp` broke out of its bounded retry at attempt 0, and the whole operation failed.

Head `4f6b5b9f8aeba4c3273750ff3c556b0a134ad7f7` — 4 files changed, +393 -11.

**What the fix is.** The one hand-written pattern becomes a **table of fault classes** (`gitOpTransientSignatures`), and the class names are the key a **recorded fixture table** is keyed by:

- `refs/git_transient_signatures_test.go` — new, +226 — the RECORD: one observed stderr string per fault class, with where it was seen, and the BEHAVIOUR the vocabulary must produce.
- `refs/git_transient_classes_test.go` — new, +84 — the accountability half: every recorded fault is classified under its own class, every recorded permanent failure is not, every class in the production table is backed by a record, and the failure names the class it carries.
- `refs/git.go` — +75 -11 — the class table, the classifier `transientFaultClass`, the retry decision, and the class named in the returned error.
- `AGENTS.md` — +8 -0 — the build section now names the toolchain the pinned linter must run under.

The behavioural file references **no new production symbol** — only `runGitOp`, which has existed unchanged since the runner was introduced — so it runs against **any** revision of `refs/git.go`. That is what makes it the red proof, and it is why the accountability file, which necessarily asserts the new vocabulary's internals, is a separate file.

The widening is bounded on the other side: the recorded permanent failures — a missing repository, a 403, a 404, a credential challenge — keep failing fast with exactly ONE request (the run is pasted below).

**Why it matters here.** The corpus regeneration in `opencharly/marketplace` (run 40922093306, attempt 1, 2026-10-29T17:36:44Z) died on exactly this string, and with it the job that owns the corpus, its deployment, and the auto-merge arm. **opencharly/spec#284** carries the full RCA.
