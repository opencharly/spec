# 0.2026321.1242 — fix(cue): give each #MountNeed boolean its own union line (D-PAT-3)

## Summary

D-PAT-3 judges a **line**: a `|` disjunction outside `or(...)` is a violation unless the line carries
exactly ONE, as a literal default — `scripts/design-dpat.sh`:

```awk
if (nbar == 1 && literal_default(barpos[1])) nbar = 0
if (nbar > 0) emit("union", ...)
```

`#MountNeed` packed two of them onto one line:

```cue
#MountNeed:    {host!: #AbsPath, path!: #AbsPath, writable: *false | bool, exclusive: *false | bool}
```

so the census counted a union finding at `schema/capability.cue:209`, and opencharly/opencharly could
not pin the commit that carried it — the same block that held `spec` back through three waves, one
layer down. Filed as opencharly/spec#364.

The shape is unchanged; the fields are written one per line, which is how its two siblings already
read:

```cue
#CountNeed:    {count!: #Count, exclusive: *false | bool}
#SizeNeed:     {size!: #Size, exclusive: *false | bool}
#MountNeed: {
	host!:      #AbsPath
	path!:      #AbsPath
	writable:   *false | bool
	exclusive:  *false | bool
}
```

`*false | bool` is the pre-existing spelling on every boolean field in this schema (17 sites across
`capability.cue` and `docs.cue`) and is deliberately not part of this change: it keeps validating as
before, and one literal default per line is exactly what the rule asks for.
