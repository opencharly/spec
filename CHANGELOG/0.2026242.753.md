# 0.2026242.753 — feat(distro): #DiskLayout — per-distro ESP mount point and btrfs subvolumes

## Summary

A distro whose **on-disk shape** is part of its identity had no way to say so. `#Distro`
could describe its bootloader, its bootstrap and its packages, but the disk a bootstrap VM
is built on was fixed: a bare root filesystem with the ESP at `/boot/efi`.

Omarchy needs both halves changed, and neither is cosmetic:

- **Its ESP mounts at `/boot`**, not `/boot/efi` — that is what `limine-entry-tool` and
  `ESP_PATH` assume. A loader written to the other path leaves an unbootable disk **while
  the build reports success**.
- **Its root is a `@`/`@home`/`@log`/`@pkg` subvolume set** on every install, and its
  `fstab` and limine cmdline reference `subvol=@`. A VM built on a bare btrfs filesystem
  can never be snapshotted, and is not the distro it claims to be.

Both were read off a real ISO-installed Omarchy 4.0.1 guest, not from documentation.

### Why no `#SchemaVersion` bump

Every bump recorded in `version.cue` is an authored wire-key **change or removal** that
needs a migration. This is a purely **additive optional field**: no existing manifest
changes shape, and there is nothing to migrate. The same reasoning applied to the `iso`
`#VmSource` arm added in #71, which also did not bump it.

### What is deliberately NOT in CUE

The rule *"exactly one subvolume mounts at `/`"* is left to `OpValidate`. "Exactly one
element of this list has field X = Y" is not expressible in a closed struct, and pretending
otherwise with a `matchN` would disable closedness — which is what catches the typo case
below. It is already enforced in `plugin-vm`'s `EmitDiskBuildScript`, which refuses a
layout with zero or two roots.

The **corpus** case is the exact Omarchy layout this def exists to express. The **teeth**
are the six ways to declare a layout that would build a disk nobody can boot:

| Rejected shape | Why it must be rejected |
|---|---|
| `esp_mount_point: "boot"` | relative — would resolve against the builder's cwd |
| `subvolume: [{name: "", …}]` | an unnamed subvolume cannot be created |
| `mount_point: "home"` | relative — would mount outside the guest tree |
| a subvolume with no `mount_point` | nowhere to mount it |
| a subvolume with no `name` | nothing to create |
| `esp_path: "/boot"` | a typo, caught only because the struct is closed |

`TestDiskLayout_ReachableFromDistro` asserts the field exists on **both** `#Distro` and
`#ResolvedDistro` — a def that validates beautifully but is unreachable from the type the
resolver actually returns would be useless, and the `Fields(cue.Optional(true))` iterator
is used because `LookupPath` does not return optional fields (the first version of that
test failed for exactly that reason).

`spec/cue_types_gen.go` is the output of `task cue:gen`, run after the schema edit, not a
hand transcription.
