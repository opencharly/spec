# 0.2026267.2121 — feat(schema): add CliRequest.env + ProvidedCapability.interactive

## Summary of changes

The spec-side legs of the plugin-native check-bed roster cutover. THREE changes, two additive wire additions and one namespace-aware resolver replacement.

1. `schema/seam.cue` — `#CliRequest` gains `env?: {[string]: string}`. The `cli` host-builder (M4) forks a `charly` child; the caller passes per-call environment variables as EXPLICIT DATA instead of mutating its own process env. This is what makes the cli host-builder placement-invariant: a compiled-in caller that `os.Setenv`s isolation vars (`CHARLY_REPO_OVERRIDE` / `CHARLY_DEPLOY_CONFIG` / `CHARLY_PREEMPT_LEASE`) only reaches the forked child when caller and child share a process; an out-of-process caller's `os.Setenv` lands in the WRONG process. Threading the vars on the request makes the child receive them identically in both placements. ADDITIVE.
2. `protocol/schema/plugin.cue` + `capability/capability.go` — `ProvidedCapability` gains `interactive` (proto field 14; Go field on the authoring struct). A `class=command` capability sets it when it needs a real terminal (`shell`, `logs -f`, `mcp serve --stdio`). Such a command keeps the process-replacing exec lane; every non-interactive command can dispatch through the broker-backed `Invoke(OpRun)` path, so a command behaves identically compiled-in and runtime-loaded. ADDITIVE.
3. `spec/loadmodel.go` — **replaces** the local-only `UnifiedFile.CheckBeds()` with the ONE namespace-aware bed resolver: `Beds()` (recursive local + `ns.name` enumeration via `collectBeds`), `ResolveBed(ref)` (local or `ns.bed`), and `BedScope(ref)` (returns the owning `UnifiedFile` so a namespaced bed's bare `from:` resolves against its own namespace). This fixes a real defect: a namespaced bed (`main.check-*`) currently VALIDATES (`loaderkit.bedRef` supports `ns.bed`) but CANNOT RUN (the run path looked it up locally only). `CheckBeds()` had three disagreeing consumers; this is the single replacement. RENAME/REMOVAL (see R5).

Regenerated: `proto/plugin.proto`, `proto/plugin.pb.go`, `spec/cue_types_gen.go` (via `task wire:gen` + `task cue:gen`).

New coverage: `spec/loadmodel_beds_test.go` covers `Beds()`/`ResolveBed()`/`BedScope()`.

**Additive wire fields only** for items 1–2; item 3 is a rename (`CheckBeds` → `Beds`) with NO `#SchemaVersion` bump (the authored `charly.yml` schema surface is unchanged — this is a Go API change, not a config-format change). No migration.

**Closes / relates to:** none (first legs of a cross-repo cutover; sdk + charly + plugin-check consumers follow). The rename's consumer updates are in the sdk leg (`ValidateCheckBeds`/`ResolveEntityRef` use `Beds()`/`ResolveBed()`) and land AFTER this is merged + tagged.

**Breaking change + rollback:** `CheckBeds()` is removed/renamed to `Beds()` — a Go API break for out-of-tree consumers of `spec.UnifiedFile`. Recovery: switch `uf.CheckBeds()` to `uf.Beds()` (the new names are namespace-qualified; a local-only caller gets the same local keys plus `ns.*` keys). Rollback is a revert of this PR.
