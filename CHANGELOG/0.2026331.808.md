# 0.2026331.808 — feat(spec)!: remove the Android substrate, its adb/appium verbs and the apk format

## Summary

Remove Android completely from the `spec` contract module — the `kind: android` body, the `deploy: android` venue, the `adb`/`appium` check-verb support and the Android APK (`apk:`) package format — per the operator decision of 2026-11-27 (no replacement). This is the `spec` leg of the approved multi-repo retirement.

Relates to opencharly/opencharly#1318.

**Removed (every def deleted; no shim, alias or dual path — D-LAW-1/D-LAW-2):**

| Surface | Removed |
|---|---|
| Authoring schema | `#Android`, `#AdbEndpoint`, `#GoogleAccount` (`schema/android.cue`); `#AndroidValue`; the `android` row of `#ResourceKind`, `#Deploy.target` and `#SubstrateKind` |
| Resolve / wire | `#ResolvedAndroid`, `#AndroidResolveInput`, `#AndroidResolveReply`, `#SubstrateTemplateResolveRequest.android`, `#ProjectTemplates.android`, `#AndroidDeployVenue` |
| Android APK package format | `#CandyApk`, `#Candy.apk`, `#CandyModel.apk`, `#InstallStepView.apk_packages`, the `#CandyApk.source` vocabulary |
| Go contract | `Android`, `ResolvedAndroid`, `AndroidSpec`, `ApkPackageSpec`, `ApkInstallStep`, `StepKindApkInstall`, `CandyReader.Apk()`, `UnifiedFile.Android()`, the `ValidateAndroidDevices` seam, `SubstrateAndroid` |
| Helper | `checkhost/apk.go` — the committed-APK resolver used by the adb/appium verbs |

**Deliberately kept (a different packaging concept, outside this removal):** the Alpine `apk` package format/manager (`_distroTraitFormat.apk`, `alpine: {format: "apk"}`, `_buildFormat.apk`, `_packageManager.apk`, the nFPM `apk` format, `candy add-apk`). Also kept: the generic `parent` venue and `none` transport, which any plugin-declared substrate may use. The R5 sweep below shows exactly these remaining `apk` hits and **zero** `android`/`appium` hits.

### Spike

Two candidates for removing a def from a CUE-single-source module:

1. **CUE-first** — delete the defs in `schema/*.cue`, regenerate with `charly task cue-gen`, and let the compiler enumerate every Go site (the single source of truth, D-SCH-1).
2. **Go-first** — hand-delete the generated/spec Go types first, then chase the CUE. Rejected: `spec/cue_types_gen.go` is regenerated from CUE, so a hand edit is destroyed by the next `cue-gen`, and there is no ground truth for completeness.

Candidate 1 was run against the real generator. Its first round (CUE defs deleted, hand-written Go not yet swept) produced exactly the compiler's complete site list, proving the mechanism:
