# 0.2026240.1719 — feat(service): wait_for — a declared readiness precondition on a service start

## Summary

The `spec` leg of batch **B2**'s last item, and the highest-leverage one: it exists to delete real
duplication rather than to add surface.

**Nine hand-rolled versions of the same poll exist in the candy corpus today** — labwc,
kde-selkies ×2, chrome-cdp, wayvnc ×3, swaync, waybar, waybar-labwc, sway — each re-deriving a
socket wait with its own hardcoded timeout, which is exactly the sleeps and magic numbers R4 forbids:

```
$ grep -rl 'while \[ ! -e\|until \[ -e\|while \[ ! -S' pod-*/ | wc -l
8      # 9 loops
```

**And one of them is already wrong.** `pod-labwc/labwc-wrapper`:

```sh
TIMEOUT=30
ELAPSED=0
while [ ! -e "$PIXELFLUX_SOCKET" ] && [ "$ELAPSED" -lt "$TIMEOUT" ]; do
    sleep 0.5
    ELAPSED=$((ELAPSED + 1))
done
```

It declares 30 seconds and sleeps 0.5s per iteration while counting `+1`, so it actually gives up
after **15**. That is the failure mode a hand-rolled loop has and a declared one cannot.

```yaml
wait_for: {paths: ["${XDG_RUNTIME_DIR}/wayland-1"], timeout: "30s"}
```

## Two design decisions worth stating

**`paths` is required and non-empty** (`paths!: [_, ...]`). A `wait_for` waiting for nothing is a
no-op that *reads* like a guard, which is worse than no guard at all.

That requirement is only enforceable under **final** validation — the structural form accepts the
empty case. My first version of the test used the structural helper and **passed vacuously**; it is
now `unifyDefFinal`, and it caught the schema genuinely not requiring the field until `paths!` was
used.

**Paths only, deliberately.** All nine existing loops wait on a filesystem path — a Wayland socket,
an IPC socket, a lock file — and **none** polls a TCP port. A `ports:` form would need a probe tool
the base images do not all carry, so it waits for a real second consumer rather than being designed
against a hypothetical one. R3's trigger is the *second* occurrence.

`timeout` accepts `"30s"` or a bare `30`, matching `stop_timeout` rather than inventing a second
convention.

## Not covered — and why the migration is separate

**The lowering.** Each init lowers this in its own idiom: systemd `ExecStartPre=`, supervisord a
rendered pre-exec ahead of `command=`, OpenRC `start_pre()`. That is the `plugin-init` + `charly`
legs, landing next, and the reason this PR claims nothing about emitted units.

The point of lowering it per-init rather than emitting a wrapper is that the wait becomes
**supervised**: a timeout fails the unit and surfaces in its status, instead of a wrapper exiting
non-zero and looking like a crash.

**Migrating the nine wrappers** is deliberately not bundled here. Their honest gate is
`check-selkies-labwc-pod` and friends staying green while the loops are deleted — beds that build
pixelflux from source and Chrome from the AUR. Bundling an unrunnable gate into this cutover would
make the whole thing unprovable; the migration is its own unit, and the `labwc` timeout bug above is
its first fix.
