# 0.2026324.2243 — feat(spec): carry a candy's declared var: on the resolved description

## Summary

**A candy's declared `var:` now rides the resolved description**, which is the shape a bed actually walks.

**Why here and not on the image metadata.** `opencharly/spec#403` added `#BoxMetadata.var?` and `opencharly/sdk#600` reads it — and the behaviour did not change, because **a container's metadata is decoded from its OCI labels and `var:` is deliberately not one** (`DeployOnlyCapabilityFields`). Nothing populates it, and both halves of that claim are pasted rather than described:

```console
$ git -C charly grep -rn 'Vars' origin/main -- 'charly/*.go' | grep -v _test \
    | grep -icE 'meta\.Vars|\.Vars\b.*meta'
0
$ git -C charly grep -c 'BoxMetadata{' origin/main -- '*.go'
origin/main:charly/service_test.go:3
```

**Zero readers of `meta.Vars` in charly's non-test code, and the only construction sites are in a `_test.go`.** So the field a merged PR adds and a merged PR reads has no producer anywhere — which is the whole reason this carrier is the wrong one.

**`#LabeledDescription` is the other carrier, and it is the right one.** It is the plan-shaped self-description a bed walks to dispatch its steps, built **from the project** — so it is where a candy's authored `var:` block already is. This adds the field; the next leg populates it and the one after merges it into the substitution env.

**`#Op`'s `config:` comment states the rule a `check:` step never received:** *"substitutes ${VAR} refs in content: at generate time (**candy var: ∪ auto-exports**)"*.

**No DESIGN change, and that is a correction worth stating.** I previously escalated this as needing a `DESIGN.cue` definition, and `opencharly/opencharly#1213` was **closed as a false blocker**. The evidence, pasted:

```console
$ git show origin/main:DESIGN.cue | grep -c 'LabeledDescription'
0
$ git show origin/main:DESIGN.cue \
    | grep -c 'LabeledDescription\|CandyHook\|VolumeMount\|CapabilityService\|LabelDescriptionSet'
0
```

**`#LabeledDescription` appears zero times in `DESIGN.cue`, and so do four comparable internal wire shapes.** DESIGN models authored shapes and the shared contract, not every internal wire struct — so this field needs no amendment, exactly as `#CandyHook` and `#VolumeMount` never did.
