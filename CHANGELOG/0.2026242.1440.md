# 0.2026242.1440 — fix(vm): remove install_timeout — declared and read by nothing

## Summary

`source.install_timeout` was declared on the `iso` arm with a doc comment describing a
"process-exit / marker POLL". **Nothing implemented it:**

```
$ grep -rn 'InstallTimeout' --include='*.go' plugin-vm/ sdk/ | grep -v _test
(only the generated struct field)
```

## Why it was added, and why that reason was wrong

It was added on the theory that an ISO install needs its own readiness deadline, because a
bed appeared to stall after the guest came up.

**That theory was wrong.** The bed was stalling on a **stale SSH host-key pin**: the live
installer environment generates its own host keys, charly's `accept-new` alias pins them,
and the reboot into the installed system then fails host-key verification forever —
a condition no amount of polling resolves. Root-caused and fixed in plugin-vm. The existing
remote readiness cap covers a ~5-minute install with room to spare.

So the field never had a job.

## Why removal rather than implementation

R5. A declared field with no consumer silently does nothing, and this cutover has already
paid for exactly that twice: spec's own `ResolveInherits` and plugin-distro's
`resolveDistro` each dropped fields every gate accepted, leaving the btrfs-subvolume feature
inert across four green PRs.

Implementing a readiness knob nothing has ever needed would be speculation. If a slow mirror
ever proves otherwise, the field comes back **with** a consumer.

## `kernel_args` is deliberately NOT removed alongside it

It **is** consumed — by the bootc engine (`--karg`) and the bootstrap engine
(`renderBootloaderScript`). Only the `iso` arm lacks an implementation, and plugin-vm
rejects it there with a reason rather than ignoring it. That is the honest handling for a
field that is real elsewhere, and it is a different situation from a field that is real
nowhere.

## How tested

Removed from the schema, from the hand-written `VmSource` in `union_types.go`, and
regenerated with `task cue:gen` (exit 0, output committed).

The corpus case that authored `install_timeout` is updated, and a **teeth test** now asserts
authoring it is rejected, so it cannot quietly return without a consumer:

```
$ go test -count=1 ./schema/ ./spec/
ok  	github.com/opencharly/spec/schema	0.936s
ok  	github.com/opencharly/spec/spec	0.278s
```

The corpus test earned its keep immediately — it **failed** on the removal before I updated
it, with `#VmSource rejects a real, verified iso install source`, which is exactly the guard
working.

**Full suite, `-count=1`** — 18 packages with tests, all `ok`, no failures:

```
$ go test -count=1 ./... 2>&1 | grep -c '^ok'
18
$ go test -count=1 ./... 2>&1 | grep FAIL
(no output)
```

`gofmt -l .` clean.

## Rulebook compliance

- **R1 — RCA every anomaly.** The stall this field was meant to address was root-caused to
  the host-key pin before deciding what to do with the field. Removing it on the strength of
  a *correct* diagnosis, not a guess.
- **R2 — Finish the whole cutover.** Schema, hand-written union struct, generated types,
  corpus case and a new teeth test all move together. `distro-omarchy`'s `omarchy-vm` entity
  authors `install_timeout: 45m` and its PR (opencharly/distro-omarchy#5) is still open — it
  is updated there, in the same change that introduced it, rather than left to break.
- **R3 — No duplication.** N/A — a removal.
- **R4 — No workarounds.** The alternative was leaving a documented field that does nothing,
  which is the workaround this rule exists to forbid.
- **R5 — Delete legacy completely.** The point of the change. Schema, Go struct, generated
  output and corpus all cleared; the teeth test is what keeps it deleted.
- **R6 — Git safety.** `git status` inspected before the commit; no force-push, no direct
  push to `main`.
- **R7 — Prove behavior, not compilation.** The teeth test fails if the field returns, and
  the corpus test demonstrably failed on the removal before being updated.
- **R8 — Preserve emitted artifacts.** `task cue:gen` re-run and its output committed, so
  the generated types match the schema.
- **R9 — Binary equals source.** N/A — spec ships no binary and adds no runtime OS
  dependency.
- **R10 — Fresh disposable proof.** Schema-only change; no runtime path alters. The
  behaviour that motivated the removal was measured live on a `disposable: true` bed.
