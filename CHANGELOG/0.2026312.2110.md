# 0.2026312.2110 — feat(schema): the schema becomes a CUE package in a module

Head `1c63c453cfaff17c7d7b2bb87c6b909cfb22d06c` — 78 files, +538 −75.

## Summary

`schema/` is now a real CUE package in a real module: `cue.mod/module.cue` declares
`github.com/opencharly/spec`, and all 64 `schema/*.cue` files carry one `package schema` clause.
The package form evaluates to the same value the text concatenation compiles — so a consumer's own
CUE module can import the schema instead of holding a copy — and that equality is proved below. This is unit 1 of the concat → package cutover (TODO.md 2.5, 2.16, 3.1; DESIGN
D-SCH-2/D-SCH-3). It is deliberately not the cutover itself.

**The dual path is deliberate.** `spec/schemaconcat` and every consumer keep working unchanged:
`ConcatSchema`'s exported API is the same and it still returns the package-less body every
consumer compiles — it now strips each file's leading package clause (and the single blank line
that conventionally follows it), so the only difference from `origin/main` is the comment
corrections this PR makes.
charly core still compiles `baseBody + "\n" + servedCUE`, `internal/schemagen` still prepends
`package spec` + `@go(spec)`, and charly's pinned spec tag is untouched. Removing the dual path —
charly importing `github.com/opencharly/spec/schema` through a module, and the text splice going
away — is the next change.

### What the package form exposed

* **No duplicate definitions.** All 719 top-level definitions across the 64 files have unique
  names across files; the one repeated name (`#Distros`) is two statements of ONE definition
  inside `distro_vocab.cue` (an open map arm plus the closed struct), which the concatenation
  already unified. No definition was renamed to dodge a conflict. Evidence below.
* **`schema/_common.cue` was invisible to CUE.** CUE excludes a file whose name starts with `_`
  from a package load, so the shared defs (`#Context`, `#Step`, `#Op`, and the rest) would have
  been missing from the package. The file is now `schema/00_common.cue`; the `00_` keeps it FIRST
  in the concatenator's sort order, so the concatenated body order — and the generated Go — is
  unchanged.
* **The language version is a decision, not a bump.** Under CUE **v0.18.0** language semantics the
  schema's existing `close()` + embedded-definition idiom is rejected: `#Step`'s arms
  (`{#Op, run: ...}`) fail with `field not allowed`, and `#DescentDescriptor.transport` likewise.
  A minimal repro measured the boundary: v0.16.1 and v0.17.0 accept it, v0.18.0 does not.
  `cue.mod/module.cue` therefore pins `language: version: "v0.16.1"` — the version spec's own
  `cuetoolchain` pins — so the package's value is identical to the concatenation's. Raising it is
  the §10.1 pattern rewrite (TODO 2.16), not this change; the pinned v0.18.0-rc.1 binary reads the
  module and evaluates it with these semantics.
* **Cross-file references resolve through the package.** `schema/*.cue` carries no CUE `import`
  statements (sweep below), so no import can become file-local and unused, and the dual-path test
  compares every
  definition's rendered value, so a def that resolved differently through the package would fail it.
* **Two stale pipeline claims on this change's own surface, fixed here (R1):** `schema/README.md`
  and the `schemagen` doc header documented `-mode=concat`, but the command takes `-mode=params`;
  and `spec/version_gen.go` no longer exists (the version machinery was deleted), so its mention
  is gone.

### The package carries the whole schema

`cue eval ./schema` is compared against the PRE-change concatenation — the 64 `origin/main` file
bodies joined in the same sorted order — declaration by declaration, after whitespace
normalization (the printer aligns values across neighbouring fields, and the alignment groups
differ between one file and a package). Run from the worktree root:

```
$ python3 /tmp/prove_package_equals_concat.py
pre-change files: 64
declarations: concat 719 package 719
same names and values: True
```

The script reconstructs the pre-change body from `origin/main` with `git show`, compiles it in a
scratch module at the SAME language version, runs `cue eval` on both sides, and compares the
sorted, whitespace-normalized top-level blocks. The same equality is a committed test
(`TestPackageCarriesTheWholeSchema`), so it holds going forward rather than only in this run:

```
$ GOWORK=off go test ./schema/ -run TestPackageCarriesTheWholeSchema -count=1; echo "exit=$?"
```

## Change classification

**No `!`.** This PR adds the package form and keeps the text form; nothing a consumer uses changes.
The Go API of `spec` is untouched, `schemaconcat.ConcatSchema`'s signature and output are unchanged,
and charly keeps compiling the spec tag it already pins. The package form is additive.

**Dual path, deliberate.** Two forms of one schema coexist on purpose — the CUE package
(`cue eval ./schema`, what a module imports) and the package-less concatenation (the runtime and
the generator) — and a test gates them against each other. Removing the dual path is the next PR:
charly composes the schema through a module import, and `schemaconcat`'s normalization (and the
text splice) go away.

**Breaking change + rollback:** none for this repo's consumers — the package form is new, the
concatenated body still carries every definition (only comment lines differ), and no authored key
moved, so no `charly migrate` entry is owed.
Rollback is a revert of this commit: it restores the package-less files and the old `ConcatSchema`,
and no consumer ever observed the package form.
