# 0.2026270.938 — feat(schema)!: remove config/schema versioning entirely

## Summary

Delete the arbitrary config/schema version stamp and its equality gate from the `spec` contract module — the **producer leg** of the schema-versioning removal chain (`spec` → `sdk` → `plugin-migrate` → `plugin-box`/`plugin-fleet` → `charly`).

**Why.** Compatibility between charly core and a plugin is *already* enforced by unifying the authored document against the CLOSED CUE schema — an unknown or removed field is a hard `field not allowed` error — plus the plugin-provided CUE source (`PluginSchema{CueSource, InputDefs}`) spliced onto the host base. A denormalised CalVer copied into every authored file added a **second source of truth** that could only ever disagree with those two, and the equality gate (`GateSchemaVersion` demands the file stamp == the binary's embedded HEAD) produced a pure re-stamp wave on every schema change. Measured: 376 per-repo `candy` CI gates pinned to old charly tags are RED org-wide with `config schema … is newer than this charly supports`, for zero shape reason. Only the **CalVer git tags** (binary build identity, candy/ref pinning) remain real versioning.
