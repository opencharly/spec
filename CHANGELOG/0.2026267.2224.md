# 0.2026267.2224 — fix(loadmodel): fold every alias of a shared namespace template map

## Summary of changes

Fix a latent namespace-folding defect in `UnifiedFile.ProjectTemplates()` exposed by making bed validation namespace-aware (the check-bed roster cutover).

`fillNamespacedTemplates` carried a **global pointer-visited guard** (`visited map[*UnifiedFile]bool`, set once and never cleared). When the SAME namespace repo is mounted at MULTIPLE alias paths — distro-arch at `charly.arch`, `charly.cachyos.arch` (via cachyos's `arch` import), `charly.omarchy.arch` — only the FIRST alias reachable in map-iteration order got its templates qualified; every later alias was skipped. Map order is non-deterministic.

Consequence: a bed in a skipped alias (`charly.arch.check-arch-vm`, `from: arch`) resolved its `from:` against a scope missing its own template — the bed could not run / failed validation.

Fix: replace the global visited set with a **path-scoped ancestor stack** (`ancestors[uf]=true; defer delete(ancestors,uf)`). Every alias path now folds; a genuine self-referential cycle still terminates.

Also in this PR (validator findings):
- `sortedRawKeys` in the new test now actually sorts (its name promised determinism).
- The `ProjectTemplates` comment no longer claims to mirror `FillBoxPlans`'s guard — that guard had the SAME global-visited bug and is fixed in the sibling opencharly/sdk#283 (`FillBoxPlans` + `materialize_wire.go`).

Adds `spec/loadmodel_templates_multialias_test.go` (`_MultiAliasSharedNamespace` fails without the fix; `_SelfCycleTerminates` proves termination).

**Additive/fix only:** no `#SchemaVersion` bump, no migration.

**Closes / relates to:** supports the check-bed roster cutover (spec#154); sibling opencharly/sdk#283.
