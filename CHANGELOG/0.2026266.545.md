# 0.2026266.545 — feat(engine): add the NoRemoveWithDetach capability fact (live RDD)

## Summary

Add the **`NoRemoveWithDetach`** capability fact to the engine class' `#EngineCapability`.

**Live RDD found it:** `nerdctl` **rejects `-d` together with `--rm`** — `level=fatal msg="flags -d and --rm cannot be specified together"` (measured live on nerdctl 2.3.5) — while podman/docker accept both. A detached-argv builder must therefore drop `--rm` where it is illegal, and the engine must stay a **provider**, so this is a capability FACT in the table (not an engine-name switch).

- **`schema/engine.cue`** — `#EngineCapability` gains `no_remove_with_detach: bool` (documented with the measured nerdctl error).
- **`spec/cue_types_gen.go`** — regenerated (`task cue:gen` path; `TestGenReproducible` passes).
- **`container/engine.go`** — nerdctl's row sets `NoRemoveWithDetach: true`; podman/docker leave it false.
- **`container/engine_test.go`** — `TestEngineCapabilityFor` pins all three rows (nerdctl true; podman/docker false).

This is the `spec` producer leg; the `sdk` consumer (drop `--rm` from nerdctl's detached argv) and `charly` land as their own legs against the new tag.
