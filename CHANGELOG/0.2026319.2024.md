# 0.2026319.2024 — feat(ir)!: the candy model carries extract as opaque bytes

## Summary

The **second** of `#CandyModel`'s seven authored-shape fields to become opaque, on the pattern `opencharly/spec#331` established for `hook`:

```cue
	extract?: bytes @go(Extract,type=RawBody)
```

`#CandyExtract` **stays** in `spec` — it is `#Candy`'s own field, and the same reasoning as `hook` applies: what changes is that the IR (`#CandyModel`) stops **importing** it and carries bytes instead (`DESIGN.md` §3.1, I1 / D-SCH-7). The one consumer decodes.

**The reader set, swept against the consumer's `origin/main`:**

```console
$ git -C <sdk> grep -n 'm\.Extract\|\.Extract\b' origin/main -- '*.go' | grep -vE '_test|meta\.Extract'
origin/main:deploykit/spec_candy_adapter.go:63:func (a *specCandyAdapter) HasExtract() bool { return len(a.m.Extract) > 0 }
origin/main:deploykit/spec_candy_adapter.go:64:func (a *specCandyAdapter) Extract() []ExtractYAML { return a.m.Extract }
origin/main:loaderkit/scan_candy.go:238:	(len(m.Extract) > 0) ||
```

Three sites, two files: the adapter's accessor pair and the `HasContent` predicate. `HasExtract`/`HasContent` keep working unchanged — `len()` on a nil `RawBody` is 0, exactly as on a nil slice — so only `Extract()` needs to decode.

**Why `extract` second.** §7c's inventory ranks it simplest: the adapter is its *only* production struct-field reader, and the rendering paths (`candy_stage.go`, `install_build.go`) consume it through `layer.Extract()`, so they are unaffected by construction.
