# 0.2026321.854 — feat(schema): port the binding contract -- bind/unbind and the four shapes (P09)

## Summary

**`bind` was a contract nobody could call.** `DESIGN.cue:1255-1256` declares `bind`/`unbind` on the
`type` role, and `:1288-1291` declares all four shapes — but `schema/` (the SHIPPED contract) had none of
them. Measured before writing a line:

```console
$ grep -rn 'BindInput' spec/cue_types_gen.go | wc -l
0
$ grep -rln 'role: "type"' --include='*.go' --include='*.cue' . | grep -v DESIGN.cue
(nothing)
```

So this is a **port**, the same class as `spec#344`'s audit contract: DESIGN.cue is the single schema copy
and this file is its declaration moved into the module the code is generated from. **Nothing here is a
new shape.**

| DESIGN.cue | what it is |
|---|---|
| `#BindNeed {type!, name!, config!}` | what is wanted |
| `#BindInput {need!, provided_by!, deployment!}` | the `bind` method's input |
| `#BindOutput {binding!}` | the handle the type owner mints |
| `#UnbindInput {binding!}` | `unbind` takes the HANDLE, not the need |

**It is a METHOD, not an authored key.** `DESIGN.md:413` puts a binding in the core → plugin direction —
*"delivered by `bind` to the owner of the capability type"* — and D-CAP-4 agrees from the other side:
*"Bindings are state, delivered by the type's `bind`; they never appear in an authored file."* There is
therefore no `bind:` key on a candy, a box or a deploy; these four shapes are what crosses the wire.

**Deciding and delivering are two owners, and this PR is the second.** `spec/needsolver` (merged as
`v0.2026321.839`) answers *which* provide a need binds to, by §8.2's visibility. These shapes carry what
is then **handed** to the type owner. Neither package does the other's job.

`config` and `binding` are `#Opaque` because only the capability type knows its own configuration shape
(D-CAP-2: one owner per type). Core never inspects a handle — that is what makes the type an owner
rather than a lookup table core reads.


**And one of those tests earned its place this round.** `TestPackageCarriesTheWholeSchema` caught a real
defect in the first attempt:

```console
--- FAIL: TestPackageCarriesTheWholeSchema
    the concatenation has 676 definitions, the package 671 — a file the package loader excludes?
```

The 5 missing were exactly `#BindNeed`, `#BindInput`, `#BindOutput`, `#UnbindInput`, `#Opaque`. Cause:
**the new file had no `package schema` clause.** `schemaconcat` appends raw text after the first file's
clause, so generation still produced all four Go types — while the CUE *package* loader saw nothing. A
green `cue-gen` over a file the package could not see. Adding the clause made both counts agree.

That is why the concat and the package are compared at all: **one of them was right and the other was
silent.**

The generated types are the proof the port reached Go:

```go
type BindNeed struct {
	Type   Word   `json:"type"`
	Name   Text   `json:"name"`
	Config Opaque `json:"config"`
}
```
