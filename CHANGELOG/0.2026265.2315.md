# 0.2026265.2315 — feat(spec): engine provider class — single-homed resolution + a servable class (v3)

## Summary

Land the `engine` provider class in `spec` — the container-engine contract that makes the engine a **provider** (podman/docker compiled-in, nerdctl out-of-process) instead of ~170 literal engine-string sites and ~30 switches. Fresh PR: the prior thread (`#141`) was auto-closed by the gate policy; this branch carries every fix.

### Every changed file/behavior

**The engine class + vocabulary:** `schema/engine.cue` (new — `#EngineName` = podman|docker|nerdctl, `#EngineRunMode` = quadlet|systemd-unit|direct, `#EngineUnitRunModes` (the unit-supervised subset), `#EngineCapability`, **five** request/reply op-envelope pairs (`#EngineBinary…`/`#EngineGPURunArgs…`/`#EngineStartPlan…`/`#EngineUnit…`/`#EngineNetworkEnsure…`) plus the reply-only `#EngineDescribeReply`); `schema/candy.cue` (`"engine"` in `#ProviderClassNames`); `schema/deploy.cue` (`engine:` typed `#EngineName`); the generated `spec/cue_types_gen.go` / `spec/vocab_gen.go` (from `internal/schemagen`, which also gained the vocab-list emission); and the HAND-WRITTEN `spec/engine_consts.go` (the `DefaultContainerEngine` const + its doc).

**The behavior (single-homed):** `container/engine.go` — `EngineCapabilityFor` resolves ANY non-member word (empty OR unknown like `bogus`) to the ONE default engine, so `EngineBinary`/`EngineRunModeFor`/`GPURunArgs`/`imageExistsProbeArgv` all agree; `EngineBinary`/`GPURunArgs` are typed accessors of the class ops; `container/local_image_coneb.go` — read-side consumers behind the capability table; `container/engine_ops.go` (new) — `InvokeEngineOp`, the pure placement-agnostic servant; `ops/ops.go` — the `OpEngine*` selectors.

**`unit_emit` contract aligned to its servant:** the schema doc (`schema/engine.cue` + the generated copy) now states the op renders the **non-quadlet** systemd-unit form only; podman's `.container`/`.pod` quadlet is emitted by podman's OWN generator (a quadlet request returns no files).

**nerdctl reaches the runtime config:** `hostenv/runtime_config.go` — `DetectRunMode` returns the engine's CUE-owned mode (nerdctl → `systemd-unit`); `ValidateEngine`/`ValidateRunMode` accept `nerdctl`/`systemd-unit`; `runModeMismatchWarning` warns only on an explicit unit mode the engine cannot offer.

**engine-as-data in `exec` (removes the per-engine jump enum arms):** `exec/deploy_executor_nested.go` / `deploy_chain.go` / `deploy_executor_process.go` / `venue_descriptor.go` + `spec/deploy_executor.go` — `JumpPodmanExec`/`JumpDockerExec` replaced by `NestedJump.Kind = JumpContainerExec` + `NestedJump.Engine`; `exec/venue_wait.go` — `WaitForContainerReady` probes with the deploy's own engine from `CHARLY_RUN_ENGINE` (`readinessEngine`, fallback `defaultContainerEngine`), the producers named in the comment (`candy/plugin-settings`, the container-nesting layer); `exec/builder_run.go` — the shared `defaultContainerEngine` const.

### The two blocks closed this round

1. **Unknown non-empty word now single-homed too.** Previously `EngineBinary("bogus")` = podman (default) while `GPURunArgs("bogus")`/`imageExistsProbeArgv("bogus")` = docker/nerdctl's forms and `EngineRunModeFor("bogus")` = `direct` — the same split the `""` fix closed, surviving for unknown words. `EngineCapabilityFor` now resolves any non-member word to the default engine; **`TestUnknownEngineResolutionIsSingleHome`** pins `f(x) == f(EngineBinary(x))` for every consumer; the tests that codified the split are corrected (`TestEngineCapabilityFor` now asserts `bogus` resolves to the default; `TestImageExistsProbeArgv`/`TestEngineRunModeFor`/`TestRunModeMismatchWarning` agree).
2. **`unit_emit` doc and servant now agree on the decision input:** the servant reads the REQUEST's `run_mode` (defaulting to the engine's capability mode when empty), so a `run_mode=quadlet` request to ANY provider — even nerdctl — returns no files (podman's quadlet generator owns that form). `TestEngineUnitEmitHonorsRequestRunMode` pins it.
3. **The two surviving stale doc comments are swept** — `EngineRunModeFor`'s doc now states an unknown non-empty word resolves to the **default engine's** mode (not a `DirectRunMode()` fallback, which is reached only for `"auto"` with no engine), and `engineDescribe`'s doc states an unknown word resolves to the default engine's capability (the `Error` reply is only for `"auto"` with no engine). Both now agree with the code, the inline comments, and the tests.
