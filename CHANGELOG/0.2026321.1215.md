# 0.2026321.1215 — fix(schemagen): emit a map for a pattern-keyed collection

## Summary

**The generator asked the wrong question, and 94 fields paid for it.**

`#A: {[#Word]: {count: int}}` generated `type A struct {}` — the payload gone. So did every regex-keyed and every literal-disjunction-keyed collection in the schema, which is why `spec#271` exists. The branch is four lines in our own `schemaparams/gotypes.go`:

```go
if elem := val.LookupPath(cue.MakePath(cue.AnyString)); elem.Err() == nil {
	g.def.printf("map[string]")
	// ... the element emitted
}
// the fallthrough:
g.def.printf("struct {\n")   // <- line 372: everything else lands here
```

`cue.AnyString` is the **unconstrained** label `_`, so only `[string]: T` satisfies the lookup. A regex key and a literal-disjunction key both fail it, fall through to the struct branch, and close immediately — **because a pattern contributes no FIELD.**

```console
#A: AnyString lookup err = #A: field not found: [_]   →  struct {}          (#A: {[#Word]: {count: int}})
#D: AnyString lookup err = <nil>                     →  map[string]int64   (#D: {[string]: int})
#E: AnyString lookup err = #E: field not found: [_]  →  struct {}          (#E: {[("x" | "y")]: {}})
```

**The information is not lost at that point. It is simply not asked for.**

The pattern IS reachable — through the resolved syntax, where `[#Word]` arrives as `[WORD.#x]` inside a `let WORD = {#x: =~"^[a-z][a-z0-9_]*$"}` binding. So the fix is four pieces: a pattern detector over `val.Syntax()`, a key-type resolver, an emit path, and a policy for a disjunction key.

**The decision, and why `map[string]` for a disjunction key:** `struct{}` is strictly worse than either alternative because it loses the payload; Go has no sum type for a key, so a typed disjunction key would need a second authority enforcing the closed set at every call site; and the closure already lives in `#Word`'s `Valid()`, which every vocabulary consumer already calls. Typing it buys nothing a runtime `Valid()` does not, because a key read from config is never a constant. **One authority, per R2.** For a regex key the same reasoning applies for a different reason: `Selector.Pattern()` yields the constraint value, not the definition's name, so the name does not survive to be emitted — and the comment at the emit site says so.

**What it moves, measured from the final tree — three outcomes, not one:**

| outcome | count | what it means |
|---|---|---|
| `struct{}` → `map[string]struct{…}` | **93** | the fix working, the payload carried |
| `struct{}` → `map[string]string` | **1** | `DriverRow.Grant`, a string-word element: typed |
| `struct{}` → `map[string]any` | **0** | after the schema half below; **16** before it |
| unchanged | 166 fields + 9 empty types | no move |

```console
$ grep -c 'IncompleteKind' spec/cue_types_gen.go
0
$ awk '/^type CandyNeed struct/,/^}/' spec/cue_types_gen.go | grep -A3 'Cpu '
	Cpu map[string]struct {
		Count     Count `yaml:"count,omitempty" json:"count"`
		Exclusive bool  `yaml:"exclusive,omitempty" json:"exclusive"`
```

**The 16 that were `map[string]any` are why this PR has a schema half.** The first revision of the generator fix turned the four leasable entries — `cpu`, `memory`, `storage`, `mount` — into `map[string]any/* TODO: IncompleteKind: _|_ */`, which is **the same payload loss wearing a different spelling**, one level down. The measured cause is not the branch:

```console
$ # probe on the pre-fix schema
#CandyNeed.cpu?:  patternMapElem=true  elemKind=_|_  elemErr=exclusive: field not allowed

$ # isolated
#Closed: {count!: #Count}            & {exclusive: …}  ->  exclusive: field not allowed
#Open:   {count!: #Count, ...}       & {exclusive: …}  ->  count!: int&>0, exclusive: false
```

**A definition is CLOSED**, and `#Need`/`#Use` merge `#LeaseFields` into it. DESIGN makes that legal with the postfix `...` at the EMBEDDING site — the `@experiment(explicitopen)` form the pinned CUE v0.16.1 refuses. With a plain embedding the element is bottom.

So the three leasable shapes now declare the lease field themselves — `#CountNeed`/`#SizeNeed`/`#MountNeed` carry `exclusive: *false | bool`, which is the CUE-v0.16.1 spelling of DESIGN's net shape. The field is still added only for a `lease: true` row, and those four rows are exactly the leasable ones. **The alternative — opening the defs with `...` — is what `spec#362` records: an OPEN CUE struct is emitted as `map[string]any`, losing every field, because the `AnyString` lookup cannot tell an ellipsis-keyed map from an open struct. It is #271's sibling, not its remainder, and it is written down rather than worked around invisibly.**

**Large in line count, completely isolated in surface: six types, every one becomes a real map carrying its payload, and no site moves to `any`.**

And the payoff — the field that blocked a unit of work:

```go
	Secret map[string]struct {
		Src      AbsPath
		Dst      AbsPath
		Optional bool
	}
```

### No cycle, structurally rather than luckily

The key's Go type is `string` for every pattern shape, so the key side emits **no reference at all** and can never need `#Word`'s emission. The value side reuses `emitType`'s existing depth-first reference handling, which already turns a still-`inProgress` def into a nillable pointer — so `#Refd: {[#Word]: #Entry}` → `map[string]Entry` works through machinery that predates this change. **Four pieces, not five.**

## Change classification

Kind: a generator fix in `spec/schemaparams` plus the regenerated `spec/cue_types_gen.go`.

**Breaking change + rollback:** three CUE definitions gain a defaulted field (`exclusive: *false | bool`), which is additive — an authored `cpu:` need that says nothing about exclusivity still validates, defaulting to `false`. The Go API of six generated types changes — `Need`, `Use`, `Provide`, `CandyNeed`, `CandyUse` and `DriverRow` gain real maps where they carried `struct{}`, so any caller that read those fields as empty structs sees a different type. Nothing in the org reads them today (`git -C <repo> grep 'SecretUse' origin/main` finds three files in `spec` only, and `Need.Env`/`.Gpu`/`.Cpu` had no entry payload to read), which is why this is additive in practice. Rollback reverts the branch in `gotypes.go` and regenerates; the 94 fields return to `struct{}` and the payload is lost again.
