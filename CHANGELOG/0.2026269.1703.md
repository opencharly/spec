# 0.2026269.1703 — fix(exec): read cloud-init status unprivileged (never a password-prompting sudo)

## Summary of changes

Fixes a **30-minute hang** in charly's VM deploy readiness gate, exposed by the Cua
integration's `check-cua-container-disk-vm` bed, and adds the tests that prove both halves of
the fix.

`WaitForCloudInit` (`exec/ssh_wait.go`) polls the guest until cloud-init reaches a terminal
status. Its script hardcoded `sudo cloud-init status`. On a prebuilt containerDisk whose
**cloud-init is DISABLED** — the Cua Fleet image; measured `cloud-init status` → `status:
disabled` — no seed ever grants the passwordless sudo the code comment assumed. `sudo` (no
`-n`) cannot prompt over a stdin-piped ssh, so it failed (`sudo: a password is required`),
printed nothing, and the poll ran to its absolute cap:

```
charly: error: vm "check-cua-container-disk-vm" cloud-init did not settle …:
  cloud-init wait …: poll: absolute cap exceeded (cap 30m0s)
```

The unprivileged read is world-readable and returns `status: disabled` (rc=0) — and the
terminal classifier **already** treats that as terminal.

The concrete edits:
- **`exec/ssh_wait.go`** — the script now reads `cloud-init status` **unprivileged first** and
  classifies `done`/`error`/`disabled`/`running`; it falls back to **`sudo -n`** (never a
  prompt) only when that read is inconclusive. The script is the package const
  `cloudInitStatusScript`, and the **terminal classifier is extracted to the pure
  `pollCloudInitSettled(out string) bool`** so the "does the wait RETURN?" contract is
  testable — not just "does the script emit a token?".
- **`exec/deploy_executor_ssh.go`** — its `WaitForCloudInit` doc comment swept (it still
  described the old `sudo` behaviour).
- **`exec/ssh_wait_cloudinit_test.go`** (new) — `TestCloudInitStatusScript_ReadsUnprivileged`
  drives the script under `bash` with a stubbed `cloud-init` + a password-required `sudo`;
  `TestPollCloudInitSettled` drives the classifier over every terminal / non-terminal token.

### Review-round fixes (this head)

- **The terminal classifier is now tested** (round 1, block 2): `pollCloudInitSettled` was
  inline in the poll closure; it is now a pure function covered by `TestPollCloudInitSettled`,
  which asserts `status: disabled` **returns** (the exact token that hung) and `running` /
  blank / not-started do not.
- **The stale doc comments swept** (round 1, block 4): both comments that still described the
  old hardcoded `sudo` are corrected.
