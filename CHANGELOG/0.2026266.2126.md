# 0.2026266.2126 — feat(cache): StoreRoot/NamedStores/GCStats + the CAS retention wire fields

## Summary

Producer leg for the `cache` retention category — `charly clean --cache`, the last category of the plan that folds every cache onto the content-addressed `spec/cache` ArtifactStore. A replaced or deleted ArtifactStore entry leaves its superseded blobs behind (content addressing means a new key is a NEW manifest + blobs; the old ones stay unreferenced until reclaimed), and `Layout.GC()` already knows how to reclaim them — but there was no operator surface to invoke it, and no way to enumerate the named stores.

This PR adds the shared contract pieces (the mechanism stays in `spec/cache`; the capability stays in `plugin-clean`):

- **`cache/cache.go`**:
  - `StoreRoot()` — the cache root every named store lives under, honoring the `CHARLY_CACHE_DIR` override.
  - `NamedStores()` — every named ArtifactStore under the root: a directory carrying an `oci-layout` marker, sorted by name. A stray non-layout dir/file under the root is SKIPPED (never mistaken for a store to GC), and a missing root is an empty list, never an error.
  - `GCStats(dryRun)` — runs GC and reports the unreferenced blobs reclaimed + their summed bytes; a dry-run computes the **same** set without removing anything. The reported set INCLUDES cap eviction: the live-blob computation derives from the cap-pruned view a real run would keep, so a dry-run predicts exactly what a real run removes (incl. the blobs a cap-evicted entry alone referenced). `GC()` delegates to `GCStats(false)` (R3: one GC implementation).
  - `StoreDir` now composes through `StoreRoot` (R3: one root-resolution).
- **`schema/clean.cue`** (SDD single source): `#RetentionRequest.cache`, and `#RetentionReply.cache_stores` — a new `#CacheStoreInfo` `{name, entries, removed_blobs, removed_bytes}`. **Purely additive**: no key removed or renamed, so no `#SchemaVersion` bump and no migration-table entry is required. The entry cap stays the store's own (`DefaultMaxEntries` / `OpenLayoutLimited`) — not a project-resolved `defaults.` key, so no defaults-chain widening.
- **`spec/cue_types_gen.go`**: regenerated by `task cue:gen` (byte-idempotent).

**3. R1 — a load-sensitive failure in `spec/lock` surfaced during verification and was ROOT-FIXED in-tree.** A `-race` full-suite run failed `TestAcquireFileLock_BoundedOnContendedLock` (`took 5.457s (unbounded hang)`). RCA: the bounded wait's failure path resolved the holder via `flockHolderPIDs`, which walked `/proc/<pid>/fdinfo/*` for EVERY process — O(processes × open-fds), i.e. seconds of syscalls on a loaded host — so a wait "bounded at 200ms" overshot its own 5s assertion under concurrent load. `spec/lock` lives in THIS repo, so it is fixed here in the same cutover: `flockHolderPIDs` now reads `/proc/locks` ONCE (the kernel's own lock index; `N: FLOCK ADVISORY WRITE <pid> <maj>:<min>:<inode> START END`) — one read regardless of host load. `TestFlockHolderPIDs_NamesThisProcess` still passes (the positive control for the kernel-side lookup).
