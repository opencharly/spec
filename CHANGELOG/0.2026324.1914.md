# 0.2026324.1914 — feat(storeroot): honor the charly-only CHARLY_* overrides for every XDG input

## Summary

`DESIGN.md` D-STORE-1 (opencharly/opencharly#1212, merged) gives **every XDG input a charly-only
override** that takes precedence for charly alone, each naming a **complete, absolute charly
path**. `spec/storeroot` read none of them; this change makes the ONE resolver honor all seven.

- **`Dir`** returns a root's override verbatim when it is absolute:
  `CHARLY_CONFIG_HOME`, `CHARLY_DATA_HOME`, `CHARLY_STATE_HOME`, `CHARLY_CACHE_HOME`,
  `CHARLY_RUNTIME_DIR`. A relative or empty value is invalid and ignored, so the XDG input's
  default applies.
- **`CacheDir`** prefers `CHARLY_CACHE_HOME`, then the kept **`CHARLY_CACHE_DIR`** (still used
  verbatim, so a relative value stays relative), then `$XDG_CACHE_HOME/charly`. **No CHARLY_
  variable is dropped** (operator direction 2026-11-20, DESIGN #1211).
- **`Dirs`** takes `CHARLY_CONFIG_DIRS` / `CHARLY_DATA_DIRS` as a colon-separated list of
  complete charly directories, used verbatim after the home root. **`BaseDirs`** keeps returning
  the XDG input's own raw search path, because the override is not an XDG base list.
- **`Base`** keeps resolving the XDG base, so another application's path — a quadlet unit, a
  fish snippet, libvirt — does **not** move when a charly override is set. The cache root keeps
  its existing exception, where the overrides replace that one root wholesale.
- **Claim sweep (R5):** see the sweep below — every live "single/ONE override" claim is gone,
  and each remaining hit is dispositioned.

`CHARLY_REPO_CACHE` is untouched: it is a repos-directory path override, not a root override,
and `refs.RepoCacheDir` still reads it first.

The design decision behind the shape: an override names charly's own tree, never the XDG base
another application lives under, so `Base(RootConfig)` stays `$XDG_CONFIG_HOME` even with
`CHARLY_CONFIG_HOME` set. That is what keeps `systemd/user`, `containers/systemd` and the fish
snippet where the rest of the system expects them.
