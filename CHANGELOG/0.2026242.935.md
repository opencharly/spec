# 0.2026242.935 — feat(desktop): the theme, session, displaymanager and desktopentry kinds

## Summary

Four defs describing a graphical session the way `init:`/`service:` describes a supervised
process: the **kind is a renderer vocabulary**, the authored entity is **data**. One theme
entity renders into a Hyprland config, a sway config and a GTK settings file **without naming
any of them**.

| Def | What it is |
|---|---|
| `#Theme` | a closed colour-token palette plus the per-application files it renders into |
| `#Session` | a compositor's renderer vocabulary — per-construct templates, the config path, the wayland-sessions entry |
| `#DisplayManager` | the greeter: which one, which session it starts, autologin |
| `#DesktopEntry` | a freedesktop `.desktop` file, in both its command and web-app forms |

All four are **flat** (`Structural:false`): none deploys or nests a deploy member, so none
earns a `DeployTraits` row. Scalars, small records and inline templates — the
`plugin-harness-kind` shape, not the candy/substrate one.

### Why these are kinds and not `write:` steps

Every one of these could be hand-rolled as a `write:` with a heredoc. What a kind buys is a
**validator** and **cross-references** that a `write:` cannot express:

- **theme** — the token vocabulary is **closed**, so a template naming a token the theme does
  not define is rejected at load. An undefined token renders as an **empty string**: a
  terminal with no background colour, a bar with an invisible accent. No build step reports
  that; it is a subtly wrong desktop rather than a failure.
- **displaymanager** — `session` must match a session's `session_desktop.id`. An autologin
  naming a session file nothing installed is a **black screen at boot with an empty journal**,
  which is the worst failure this surface has.
- **desktopentry** — `categories` is closed to the freedesktop **registered main categories**,
  because a typo there errors nowhere: the entry silently vanishes from every menu. And
  `startup_wm_class` / `window` are read **by the session renderer**, so one entity feeds both
  the applications menu and the compositor's window rules. That last point is the **only**
  thing making `desktopentry` worth being a kind — without it a `.desktop` file is a trivial
  INI and this would be `write:` duplication, and should be dropped.

Nothing in `#Theme` or `#DesktopEntry` names a compositor, so the same entity serves
Hyprland, sway, labwc and KDE.

### Two shapes chosen against the obvious alternative

- **The 16 ANSI colours are named fields, not a list.** A template then says
  `{{.Token.color4}}` and a missing one is a **load error**, not an index panic at render
  time.
- **`#ThemeRender.distro` is `[...string]`, not `[...#DistroID]`.** These are the free-form
  **tags** a candy's `distro:` list carries (`box.cue` does the same), not the closed
  guest-distro id a VM source is validated against. `#DistroID` is also `@go(-)` and generates
  no Go type, so a list of it emits a reference to a type that does not exist — caught by the
  build rather than guessed.

### Why no `#SchemaVersion` bump

Purely additive optional defs with nothing to migrate — the same shape as the `iso` VmSource
arm (#71) and `#DiskLayout` (#72). Every bump recorded in `version.cue` is an authored
wire-key **change or removal**.

**The corpus cases are real.** The theme is a bundled Omarchy palette with the per-app files
the distribution actually renders; the session is Hyprland as Omarchy ships it (Lua syntax,
assembly model, `uwsm start hyprland.desktop`); the displaymanager is the sddm autologin an
Omarchy machine boots into; the desktop entries are both shapes — the shipped
`dua i /` command and the browser `--app=` web-app form.

**The teeth are the reason the defs are closed.** A sample:

| Rejected | Why it matters |
|---|---|
| `accent: "blue"` | a colour name is not a hex colour |
| `#fff` / `#ffffffff` | short form and alpha have no portable spelling across consuming formats |
| `accnt: "#123456"` | an unknown token is a typo — and the exact one the load-time check exists to catch |
| `categories: ["Utilities"]` | unregistered: the entry silently vanishes from every menu |
| `session: "Hyprland Session"` | not a slug, so the cross-check against `session_desktop.id` could never match |
| `window: {size: "large"}` | cannot become a window rule |
| a `#Session` with no `compositor` / no `config_path_template` | nothing to start, nowhere to render |

`TestDesktopKinds_AreDefinedAndClosed` asserts all six structs reject an unknown field —
without that, every "unknown field is a typo" case above would pass for the wrong reason.

**One correction worth recording.** The teeth initially used `unifyDef` (structural
validation) and four required-field cases passed when they should have failed: a structural
unify accepts a `#Theme` with no `token`, since the field is merely not yet concrete. They
now use `unifyDefFinal`, and the genuinely-required fields carry the `!` marker in the schema
— the test was not weakened to match the schema, the schema was corrected to match the
intent.

The helpers are **reused** from `box_init_test.go` rather than re-declared: one helper, one
concatenation contract.
