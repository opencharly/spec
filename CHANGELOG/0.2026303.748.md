## Summary

A withdrawn identifier that lives only INSIDE the assertion that guards it is a name no other control can read. The next re-add — the same name in another repo, or under another spelling — is then missed by the same mechanism, because the only copy of the name is inside the guard that already passed. The org already carries the shape of this defect on record: the retirement that introduced `stage_parallelism` swept its own module with a shell loop over six hand-written identifiers, recorded in that PR's changelog (`CHANGELOG/0.2026287.1848.md:139`). A sweep written into a PR body is not a control — nothing in the repository runs it, and the next withdrawal repeats the whole exercise.

This change gives the names a home of their own and puts the guard in the repository:

- `retired/identifiers.json` — the canonical inventory of withdrawn identifiers. Eleven entries, each naming the surface it was withdrawn from, the type it is scoped to where the withdrawal was local, what replaced it, and why it was withdrawn.
- `retired/` — a new leaf package that embeds the list, publishes it as `retired.Identifiers`, and asserts the contract's own surfaces against it.
- The two hand-rolled per-type negative loops are deleted: `hostenv/retired_build_selector_test.go` no longer reflects over `EngineConfig.Build` and `ResolvedRuntime.BuildEngine`, and `spec/stage_parallelism_rename_test.go` no longer reflects over `Box.PodmanJobs`. The list-driven guard asserts both, over EVERY type and EVERY literal in the module, and the hand-kept type table those loops carried goes with them. Their positive assertions stay: the renamed field must be present on the types that carry it, and `Box.Jobs` must still be there.

A scoped name is matched only inside its scope, and that scope is what keeps the rule honest: `build` is still a legal key on the box schema, so an unscoped rule for it would condemn a legal key, and a short name matched as a bare token would also match inside a longer one that starts with it.

The list is DATA and not a schema: it is a control's key set, so nothing loads it as a project, nothing carries it over the wire, and it stays readable by the org's non-Go controls with no projection and no regeneration step. It deliberately sits outside `schema/*.cue`, because `internal/schemagen` globs every CUE file into the contract's published generated types — a retired name placed there would be published as a wire shape.
