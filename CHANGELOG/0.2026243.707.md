# 0.2026243.707 — feat(scan): add an optional Warn seam so scan advisories can be data

## Summary

Adds ONE optional field to `spec.ScanSeams`:

```go
// Warn receives the scan's own advisories — candy-version skew and local-shadow notes —
// instead of them going straight to stderr.
Warn func(format string, args ...any)
```

That is the whole diff: **12 insertions in `spec/scan_seams.go`, nothing else.**

### Why it is needed

The candy scan emits two advisories — candy-version skew and the local-shadow note — and both
were bare `fmt.Fprintf(os.Stderr, ...)` calls in `sdk/loaderkit`. That made them unstructured
and therefore **uncountable**: `charly box validate` could not report how many warnings a run
produced, because they never reached its diagnostics.

That is not hypothetical. A draft of the new validate summary printed `0 warnings` on a run
that had **just emitted two** — worse than printing nothing, because it reads as a cleared
gate. This field is the channel that makes the number real.

This repo only declares the seam. The behaviour lands in the consumers, each in its own PR:

| Repo | Role |
|---|---|
| opencharly/sdk | the arbiter routes advisories through the sink |
| opencharly/plugin-loader | consumer cut over; stderr scraping deleted |
| opencharly/plugin-build | the validate path collects them as diagnostics |
| opencharly/plugin-box | `charly box validate` reports the count |

## How tested

```
$ go build ./... ; echo "exit=$?"
exit=0
```

A struct-field addition has no behaviour of its own to exercise here; it is proven by the
consumers that use it. End to end, with charly built against all four repos via `replace`:

```
$ charly box validate
charly box validate: OK — checked 489 candies, 38 boxes, 29 deploys, 7 distros, 7 builders; 3 warnings, 0 errors
```

Three warnings — two version-skew, one shadow note — counted from diagnostics rather than
lost to stderr. Before this chain the same command printed nothing at all on success.


## Tests

Two guards on the new field, with a negative control:

```
$ go test ./spec/ -run TestScanSeams
ok  	github.com/opencharly/spec/spec	0.003s
```

- the sink is part of `ScanSeams`, carries a printf-style signature, and a value set on the
  struct is the one invoked with formatted arguments
- **nil stays legal**, because that is how a caller selects stderr explicitly; a consumer
  assuming non-nil would panic on every existing build path

Negative control — deleting the field:

```
spec/scan_seams_test.go:20:3: unknown field Warn in struct literal of type ScanSeams
FAIL	github.com/opencharly/spec/spec [build failed]
```
