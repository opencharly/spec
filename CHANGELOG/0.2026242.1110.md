# 0.2026242.1110 — fix(schema): drop the dead #Pacstrap fields keyring_init_cmd and mirrorlist_url

## Summary

Second half of the opencharly/charly#477 cutover. The authored usages were removed in **opencharly/charly#484 (merged)**, so nothing declares these fields any more and the schema can drop them.

Both had **zero Go consumers**: the only occurrences of `KeyringInitCmd` and `MirrorlistURL` anywhere in the umbrella were this declaration and the types generated from it. They read as configuration and did nothing — charly's own omarchy pacstrap block carried comments explaining that it deliberately avoided both for exactly that reason, while `arch` and `cachyos` went on authoring them.

```
#Pacstrap: {
	base_package?: [...string] @go(BasePackages)
-	keyring_init_cmd?: string @go(KeyringInitCmd)
-	mirrorlist_url?:   string & =~"^https?://" @go(MirrorlistURL)
	extra_repo?: [...#PacstrapRepo] @go(ExtraRepos)
	runtime_pacman_conf?: string @go(RuntimePacmanConf)
}
```

`spec/cue_types_gen.go` is regenerated by `task cue:gen`, not hand-edited.

The diff is exactly the declaration and its generated projection — `vocab_gen.go` and `version_gen.go` are byte-identical after regeneration, so this removes a field without moving the schema version.

## Ordering

This is the second of two PRs, and the order was forced: removing the schema first would have rejected a `charly.yml` that still authored the fields. So the authored usage went first (charly#484, merged, full `go test ./charly/` green and `charly box validate` clean), and the declaration follows here. At no point was an authored field rejected by the schema, and at no point was a live consumer left without its field — there were none.

`opencharly/plugin-distro` carries its own copy of these two lines in `candy/plugin-distro/schema/distro.cue`; that is the remaining instance and goes next, on the same evidence.
