# 0.2026286.1942 — fix(exec): cloud-init settling in its error state is terminal but NOT ready (#209)

## Summary

**The root fix for a failure chain that reaches three repositories.** `WaitForCloudInit` treated every *settled* cloud-init status as success:

```go
// exec/ssh_wait.go — pollCloudInitSettled's contract, unchanged by this PR
// "`running` and a blank/transient read are NOT terminal; `done`/`error`/`disabled` are. PURE."
```

`error` **is** terminal — a guest that errored never becomes `done`, so polling on would reproduce the measured 30-minute hang this file's unprivileged-read design exists to avoid — **but terminal is not successful**, and the wait returned `nil` for both. So a guest whose provisioning FAILED was indistinguishable from a ready one, and `venue_wait.go` then discarded even that result:

```go
_ = gate.WaitForCloudInit(ctx)   // "Best-effort: silent on timeout (the downstream deploy-add surfaces the real error)."
```

**The first clause is fine and stays** — a timeout may be silent. **The second is the assumption this row falsifies:** a guest that looks ready gives downstream nothing to notice, which is why the breakage surfaced later as unrelated symptoms (`opencharly/vm-k3s-server#9`, and the `charly` rows), with `last_update: Thu, 01 Jan 1970 00:00:43 +0000` in the same report as corroboration.

Two commits, both small:

- **`558ef68`** — `ErrCloudInitFailed`, plus a **pure** `cloudInitSettledError(out)` extracted from the poll closure *for the same reason `pollCloudInitSettled` was* (so "terminal is not successful" is directly unit-testable), and the closure returns it carrying the guest's own words;
- **`f15ca16`** — the seam stops swallowing an *observed* failure: timeouts stay silent, `ErrCloudInitFailed` is warned about with the domain and the guest's output. **The function stays best-effort by design** — its callers live outside this repo (`candy/plugin-check`'s bed session among them), so a signature change is its own decision rather than a stowaway in this fix.

**The predicate is deliberately unchanged**, and stating that is part of the fix: a first reading of this row said *"the predicate must not accept `status: error` as settled"*, and the source says why that would be wrong.

## Round 1 — both findings, fixed

**R1/QUAL — a doc comment on the wrong function.** The new `cloudInitSettledError` doc block was inserted immediately after `pollCloudInitSettled`'s, with no blank line, so Go merged them into one comment group attached to the *new* func — **leaving `pollCloudInitSettled` undocumented and a comment contradicting the declaration it sat on.** Reordered so each doc is directly above its own `func`. **The validator's note is the missed control and I am keeping it verbatim: `gofmt -l` and `go vet ./...` do not check comment attachment, so the gates I pasted could not have caught it.** This is the *same* defect I fixed in `plugin-doctor#14`'s round 2 — same shape, same cause (an inserted block landing flush against the previous comment), three repos later.

**R10 — the headline behaviour shipped no coverage.** The seam's new branch could not be exercised without a guest, because `WaitForVmSshReady` constructs its own executor. ## Round 2 — my over-correction, and the control that stops it recurring

**R1/QUAL, and the validator's phrasing is the important part:** *"the underlying defect reproduces in a new form."* Round 1 merged the two doc blocks; my fix separated them but **left a blank line between `cloudInitSettledError`'s doc and its own `func`**, so the doc was *detached* rather than merged. **Same class, opposite direction** — and `gofmt`/`go vet` were silent again, exactly as the validator had already said they would be.

**So this round adds the missing control rather than another careful edit:**

```go
// exec/docattach_test.go — TestNoDetachedDocComments
// flags a // block separated from the func below it by a blank line (the class this review found twice),
// and deliberately does NOT require every func to carry a doc — unexported helpers and tests commonly
```

**And the new control immediately failed on SIX pre-existing instances in this package** — `deploy_executor_live.go` (×2), `deploy_executor_nested_test.go`, `executor_threading_test.go`, `venue_descriptor_test.go`. They are not introduced by this change, **but R1 is explicit that this change's gate being red makes a finding blocking, so they are fixed here:** six stray blank lines deleted, no prose changed.
