## Summary

Head `f6e3b94dd83fe80e86ec50d3943a4a23dbadf170` — the commit this PR pushes: **5 files changed, 1038 insertions(+), 4 deletions(-)**.

**opencharly/opencharly#799 named the gap: the contract knows what is retired, the repos know what they say, and nothing connects the two.** The contract's guard (`retired.ScanTree`) reads the contract's OWN surfaces — Go sources, CUE schemas, protobuf schemas — because that is where the contract's names live. The org's trees have more surfaces than that: an authored `charly.yml`, a skill's prose, a script, a check bed. A withdrawn name in one of those is just as live, and a scan that reads three extensions cannot see it. So the contract grows the ORG-WIDE reach, in this package, under the rules its own scan already applies.

**One implementation of the rules, and one token matcher.** The sweep shares the contract's token rule (`containsToken`/`tokenIndex`) and its text rule (`scanText`) with the schema scan, so the two cannot disagree about what a text surface is, or about which occurrence matched. Nothing here re-implements a rule that already exists in this module.

**A hit is not automatically a carrier.** The distinction is semantic — a sentence that DENIES a withdrawn name ("There is no `engine.build`") and a sentence that SETS its value carry the same name and mean opposite things — so no control can guess it. `retired.Record` makes it committed data: a hit a record covers is a RECORD, a hit no record covers is a CARRIER, and a record that covers no hit is ITSELF a finding, so the table cannot rot into a hole that hides a live use. A record covers only the identifier it names, so a record written about one name can never excuse another.

**The records TABLE lives with the org, not here.** A record names a file in a repository this module does not own, and this tree carries no records at all — its guard reads its own surfaces directly. Only the RULE for what makes a hit a carrier lives here, once.

**Where the executable lives, and why it is here and not in `.github`.** The shape chosen for this leg was "one sweep in `.github`, run over every repo". The ARM lives there; the RULE and the executable live in the contract, and `.github` invokes this module's command at a pinned tag. Two reasons, both measured rather than preferred: `.github` has no Go toolchain of its own, so a Go-structural scan — the only scan that can tell a Go comment from a Go literal — would have to be re-implemented there in another language, which is a second implementation of the same rules (R2); and the org's arm already runs in every TARGET repo's context, so a command that ships with the contract is reached by one line (`go run github.com/opencharly/spec/retired/cmd/retired-sweep@<tag>`) instead of a per-repo matrix. The three `main` packages the module already carried (`internal/wiregen`, `internal/schemagen`, `internal/cuesetup`) are developer tools under `internal/`; this one is deliberately PUBLIC — it is the module's SDK surface, and the org's arm must run it from another repo at a pinned tag.

**The discrimination cases execute the new code, and each of them can fail.** The suite builds a tree per rule so that one rule decides the verdict: a Go comment is not a surface while a Go literal is; a test file holds the assertions OF ABSENCE; a CHANGELOG is history; a nested repo is a repo of its own; a SYMLINK is another path's content, and a DANGLING one does not fail the run; a scoped name is swept only where its scope is declared; a record covers only the identifier it names, and only while its text is on the hit's line; a record that covers no hit is itself a finding. The case that keeps the suite from being vacuous is `TestTheSweepReadsEveryTextSurface`: it asserts that the contract's PRE-EXISTING scan finds NOTHING in its tree, so a control that used the old scan would read the tree as clean.

**The two findings this change introduced, fixed in it.** R1 is not a pass with warnings:

- `golangci-lint` (errcheck): `defer file.Close()` ignored the error → `defer func() { _ = file.Close() }()`.
- `golangci-lint` (prealloc): `namesOf` grew a slice without its capacity → `make([]string, 0, len(findings))`.

Both were introduced by this change, so both are fixed in it, and the lint re-run is `0 issues.`

**One anomaly found by the live run, RCA'd and fixed before this push.** The first org-wide run aborted: `retired-sweep: sweeping the tree: reading …/.dsh/skills/a11y-tools: open …: no such file or directory`. RCA — mechanism: `filepath.WalkDir` hands a symlink entry to the callback without following it, the callback opened the link, the unreadable path ended the whole run; blast radius: one dangling link in one repo would have failed the arm for EVERY repo, and the umbrella alone carries 361 such links; missed control: the sweep had no rule for what a SYMLINK is. The root fix is the umbrella's own rule, adopted here — a symlink is another path's content, so it is not read, it is counted in the coverage, and it never fails the run. The case that proves it (`TestTheSweepSkipsSymlinks`) has two halves: the link pointing inside the tree proves the content is not judged, and the dangling link proves the run survives it.
