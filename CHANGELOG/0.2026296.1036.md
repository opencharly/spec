# 0.2026296.1036 — feat(schema): W3.1 selection surfaces — deploy rootful, containerd namespace, VM-backend vocabulary

## Summary

The producer leg for W3.1's selection model. The plan's one precedence rule — **flag > deploy entity > env > settings file > built-in default** — had no schema-owned source at two of its levels, and the VM-backend vocabulary had no generated Go accessor, so a resolver would have had to carry word literals. This change supplies all three surfaces in the contract module, CUE first:

1. **`#RootfulMode` + `#Deploy.rootful`** (`schema/engine.cue`, `schema/deploy.cue`) — the CLOSED rootful-launch vocabulary `auto | machine | sudo | native`, already the set `plugin-settings` accepts for `engine.rootful`, now also the per-deploy selector. `#DeployTraits.selectors` gains `"rootful"`, so the loader can reject it on a substrate that does not declare it without switching on a substrate name.
2. **`#VmBackendName` + `#VmBackend`** (`schema/vm.cue`) — the provider words `libvirt | qemu | krun` are now their own def; `#VmBackend` keeps `auto` as the resolution default. `schemagen` emits `spec.VmBackends` and `spec.RootfulModes`, so `--backend` / `CHARLY_VM_BACKEND` / `vm.backend` and `--rootful` / `CHARLY_ENGINE_ROOTFUL` / `engine.rootful` are validated against the schema, never a literal.
3. **`containerd.namespace`** (`hostenv/runtime_config.go`) — `ContainerdConfig.Namespace`, `RuntimeConfig.Containerd`, and `ResolvedRuntime.Namespace`, resolved as **settings > the engine capability's `namespace` fact** (containerd: `"default"`). No env mirror, matching the plan's table (`containerd.namespace` | — | `namespace:` | `--namespace`).

Generated artifacts (`spec/cue_types_gen.go`, `spec/vocab_gen.go`) are the `charly task cue-gen` output, committed; a second run is byte-identical (hashes below).

**Scope boundary:** this is the producer. The `sdk` resolvers (`ResolvePodEngine`, `ResolveVmBackend`, `ResolveContainerdTarget`) are the next leg and will bump to this merge's tag; the `plugin-substrate` pod traits must declare `"rootful"` in a consumer leg before the loader admits a per-deploy `rootful:` on a pod; `plugin-settings` gains the `containerd.namespace` key as a consumer leg. No consumer repo is touched here.
