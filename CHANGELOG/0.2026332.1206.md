# 0.2026332.1206 — fix(container): a requested tag REPLACES the tag a full ref already carries

## Summary

`opencharly/spec#453`. `ResolveShellImageRef(registry, name, tag)` **appended** (`fmt.Sprintf("%s:%s", …)`)
without checking whether `name` already carried a tag or digest. A deploy entry records a full ref
(`image: ghcr.io/opencharly/whisper:2026.325.2318`), so `charly update <deploy> --tag <fresh>` composed

```
ghcr.io/opencharly/whisper:2026.325.2318:2026.332.0936
  → Error: parsing reference …: invalid reference format
```

and a fully-qualified deploy could never be moved to a newly built image. Five of this host's six CDI
deploys record that shape, so a rebuild left every deployment on its old artifact while the build
succeeded.

**The fix, in the ONE home every caller reaches** (this is why it lives here rather than at a call site —
the reviewer of the call-site attempt, `plugin-deploy-pod#110`, was right to refuse it): `refWithoutTag`
drops the digest and the tag, and the requested tag replaces it. The tag separator is the LAST `:` only
when it follows the last `/`, so a registry port (`localhost:5000/repo`) survives.

Head: `7e23ad65816408de795a846235e8ebe1a71cdcb4`
Diff: `container/local_image_coneb.go` (+ the helper), `container/resolve_shell_image_ref_test.go` (new)
