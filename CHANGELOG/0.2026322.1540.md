# 0.2026322.1540 — feat(schema): mirror the two drifted VM state fields and gate the hand mirror

## Summary

`spec/hand_state_types.go` opens by stating its own contract: the three types in it cannot be
generated faithfully, so they are hand-mirrored, and *"every field here has a matching CUE field"*.
Nothing enforced that sentence, and it was already false: the Go struct carried
`key_injection_resolved` and `snapshot`, and `schema/deploy.cue` carried neither.

This change makes the mirror true and then makes it stay true.

- The inline `ephemeral?: { … }` block becomes a named `@go(-)` def, and the two missing records
  join it as `#VmKeyInjectionResolved` and `#VmSnapshotState`. Each of the three is `@go(-)`
  because its Go type is hand-written: the annotation **suppresses generation** for that record,
  and it is load-bearing — measured, not inferred: with the annotation absent, `cue-gen` emitted
  the three types and the build failed on `VmKeyInjectionResolved redeclared`. `#VmDeployState`'s
  own `@go(-)` is a *different* sentence: its open `...` tail additionally degrades `gengotypes`'
  output to `map[string]any`, so generating it would be lossy as well as duplicative.
- `#VmDeployState` gains `key_injection_resolved?: #VmKeyInjectionResolved` and
  `snapshot?: [...#VmSnapshotState]`, and points `ephemeral?` at the new def.
- `schema/hand_state_lockstep_test.go` compares each def's field names against its Go struct's
  yaml tags **in both directions**, so a field added on either side alone fails the suite.

**Row 2.3 closes here as correctly hand-written.** The `@go(-)` exceptions are not debt to be
generated away — `PortSpec` has no CUE def by design (its own schema comment says so) and the
state records need generator support for open records that does not exist — so the row's honest
disposition is that these three stay hand-written, with a control that proves the mirror rather
than a comment that asserts it.
