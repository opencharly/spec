## Summary

Two coordinated `#Plugin` changes in `schema/candy.cue`, the wire contract in
`protocol/schema/plugin.cue`, a new schema test, two comment-only cleanups, and the

1. **`schema/candy.cue`** — add `plugin.requires` + `#PluginRequirement`; make

   `*"builtin"` default.
2. **`protocol/schema/plugin.cue`** — the wire twin: `Capabilities.requires` (field 5)

3. **`schema/plugin_test.go`** (new) — schema tests that FAIL without the change.

   the retired `source: builtin` wording (no value change).
5. **`proto/plugin.proto`, `proto/plugin.pb.go`, `spec/cue_types_gen.go`** — regenerated.

`requires:` names a peer `capability` (`"<class>:<word>"`), an optional `source` candy
ref (a peer outside the project closure), and `optional`. Today a plugin's internal
peer need is met only if the peer happens to be referenced by the project's own plans
(or a call-time `ExtraRef`); this makes the dependency **declarative**, so the host can
connect/order it identically in every placement.

`plugin.source:` is now REQUIRED and github-only (the shared `#GithubRef` shape).
Whether a plugin runs compiled-in or out-of-process is the separate `charly.yml`
`compiled_plugins:` selection, never a manifest form.

### The blast radius of making `source` required is proven to be exactly two candies

Making `source` required breaks a plugin candy only if it has no `source` at all (it
previously fell back to the dropped `*"builtin"` default) OR spells the sentinel
explicitly. Both cases are searched below, across EVERY candy manifest in the org
working copy (the ~400-repo umbrella checkout), so "only two" is fully established:

```
$ find . -path ./.git -prune -o -name charly.yml -print | grep -v '/CHANGELOG/' | while read f; do
    grep -qE '^[[:space:]]+plugin:' "$f" || continue
    grep -qE '^[[:space:]]+source:' "$f" || echo "NO SOURCE: $f"
    grep -qE '^[[:space:]]+source:[[:space:]]*builtin' "$f" && echo "BUILTIN: $f"
  done
BUILTIN: ./plugin-agentteams/candy/plugin-agentteams/charly.yml
BUILTIN: ./plugin-dsh/candy/plugin-dsh/charly.yml
```

(No `NO SOURCE:` line: every plugin candy already carries a `source:`. Only the two
`BUILTIN:` lines.) Each is corrected to its real module ref in its OWN repo, in a PR
whose base is that repo's `origin/main`:

- **opencharly/plugin-dsh#6** (`feat/plugin-source-ref` ← `main`) → `github.com/opencharly/plugin-dsh/candy/plugin-dsh`
- **opencharly/plugin-agentteams#4** (`feat/plugin-source-ref` ← `main`) → `github.com/opencharly/plugin-agentteams/candy/plugin-agentteams`

Both values already validate under the CURRENT pinned schema, so those PRs can land in
any order with this one — the fix batch is exactly those two named PRs.
