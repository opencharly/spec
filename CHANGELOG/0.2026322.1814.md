# 0.2026322.1814 — feat(clean): declare the per-host `clean:` section and its store budget

## Summary

`D-STORE-7` bounds a named store *"within a size budget"*, and today that ceiling is a plugin
constant nobody can tune. It is a property of the **machine that holds the store**, so it belongs
in the per-host configuration (`~/.config/charly/charly.yml`) — `DESIGN.md:2483` **D-STORE-2**: the
user configuration holds *"each plugin's own section — under its own schema"* — and not in a
project's `defaults:` block, which is shared while a host's disk is not.

This change declares that section in the contract, which is what makes it authorable at all: the
per-host document is a CLOSED schema, so an undeclared top-level key is a load error and an
undeclared key *inside* a declared section would be accepted and silently ignored. Both halves are
now typed.

- **`schema/clean.cue`** gains `#CleanSection` (carrying `store_budget?: #StoreBudget`) and
  `#StoreBudget` (carrying `bytes: int & >0 @go(Bytes, type=int64)`). The file already owns the
  word `clean` — the retention verb's wire types — and now owns the per-host section of the same
  surface too, which its header states.
- **`int64`, deliberately.** A budget is a byte count and the value this exists for — 256 GiB =
  `274877906944` — does not fit a 32-bit `int`, so a bare `int` would wrap silently on the `386`
  and `arm` cross-compile targets. The schema's own precedent is `distro.cue`'s
  `disk_size_bytes: int @go(DiskSizeBytes,type=int64)`.
- **`#NodeDoc` recognizes the section as a document directive**, so an authored `clean:` block is
  never mis-read as a node named `clean`; the generated `DocDirectives` list gains the word as a
  consequence. It is **TYPED** there where its older siblings are `_`: the requirement is that an
  undeclared key inside the section is a load error, and `_` would accept a typo and let the
  retention plugin fall back to its default in silence. The siblings are untouched.
- **`spec.DeployConfig` and `spec.UnifiedFile` carry `Clean *CleanSection`** — the two hand-created
  per-host structs that already carry `cache:`, `ledger:` and `system:`. `DeployConfig` is not
  CUE-generated (it is `spec/spec/deploy_config.go`), so the field is declared there; `deploykit`'s
  `DeployConfig` is an alias of it, which is why the sdk needs only a pin bump later.
- **NO default anywhere.** An absent section stays absent (`nil`), so the 32 GiB fallback lives
  once, in the plugin that enforces it. A CUE default would put the number in two places.

No wire field: `#RetentionRequest` is unchanged — no peer runs the store category — so the budget
is resolved where the config is read, which is what `schema/clean.cue`'s own header already says
about the retention engine.

Related, not filed here: opencharly/plugin-clean#28 carries the requirement (whose mechanism this
corrects from a project `defaults:` field to the per-host section), and opencharly/spec#383 tracks
delivering a plugin its own section through the host service — this change declares the section
that reader will read.
