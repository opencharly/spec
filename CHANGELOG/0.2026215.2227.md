# 0.2026215.2227 — docs(schema): drop the deleted validateInitDependencies from the CandyView comment

## What & why

The `#CandyView.capabilities` doc comment named `validateInitDependencies` — a `candy/plugin-box` validator that the superproject leg of this cutover DELETES. The missing-init case is now impossible: the active init system's `depends_candy` is injected into a box's composition at every box-resolution chokepoint (opencharly/sdk#119). The comment now names only the surviving reader, the `validatePackagedServices` box-arm.

Schema-wise this is documentation-only: **no field is added, removed, or reshaped.**

## Why the referenced validator is safe to delete

Stated here because this comment is the only thing in this repo that pointed at it. `buildkit.ResolveBox` is the ONLY place a box's `Candy` list is set, so every composition path funnels through one of three seams, all of which now inject: `ResolveAllBox`'s returned map (build path), `loaderkit.ProjectResolvedProject`'s fresh-box loop (validate / inspect / bundle-deploy), and `deploykit.FillNamespaceBoxViews` (import-namespace boxes). Bundle-deploy needs no separate call — it reads `rp.Boxes` from the envelope the second seam produces — and a `local:`/VM deploy compiles candies rather than boxes, so it composes no box at all. The deleted code had **zero test coverage**. Full argument in opencharly/sdk#119.

## How it was found

The R5 grep self-test, run PER SUBMODULE. `git grep` does not cross submodule boundaries, so a super-root sweep for the deleted identifier reported clean while this file still named it.
