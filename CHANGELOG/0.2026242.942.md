# 0.2026242.942 — fix(desktop): idiomatic Go names for the desktop-kind fields

## Summary

The four desktop kinds landed in [#74](https://github.com/opencharly/spec/pull/74) **without
`@go()` annotations**, so `cue:gen` produced snake-cased identifiers with a leading capital:

```go
Entry_name       string
Browser_arg      []string
Mime_type        []string
Startup_wm_class string
Config_path_template string
Url              string
```

Every other def in this schema annotates, and these are types a plugin consumer writes
against **directly** — the `plugin-desktop-kind` provider decodes into them field by field —
so leaving them non-idiomatic makes every consumer read wrong.

### No shape change, so nothing migrates

`@go()` renames only the **Go identifier**. The `yaml:` and `json:` tags — and therefore the
authored wire surface — are byte-identical, so no manifest changes, nothing needs a migration
op, and `#SchemaVersion` does not move.

### How it was found

Writing the `plugin-desktop-kind` provider against these types. The compiler said
`e.URL undefined (type *spec.DesktopEntry has no field or method URL, but does have field
Url)` — which is the schema telling a consumer it was authored carelessly.
