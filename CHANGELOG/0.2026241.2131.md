# 0.2026241.2131 — feat(distro_vocab): add the omarchy distro id

## Summary

Adds `omarchy` to the `#Distros` vocabulary — the first step of bringing
[Omarchy](https://github.com/omacom/omarchy) (DHH's vanilla Arch + Hyprland
distribution) to the same footing as Arch and CachyOS: pod images, VMs, and a full
GUI deployment.

```cue
omarchy: {format: "pac", ssh_unit: "sshd", init: "systemd", ovmf_family: "arch"}
```

`task cue:gen` propagates it into all five generated tables in `spec/vocab_gen.go`
(`DistroIDs`, `DistroFormats`, `DistroSSHUnits`, `DistroInits`, `DistroOvmfFamilies`)
and widens the derived closed `#DistroID` union.

**Why a distinct id rather than an alias of `arch`.** The traits are identical to
Arch's, but `#DistroID` keys three things Arch does not share, each of which would
otherwise become a branch on a string:

1. the unattended-install answer format — archinstall JSON, which Arch's own ISO does
   not ship pre-seeded;
2. the `[omarchy]` pacman repo **and** Omarchy's pinned Arch mirror snapshot
   (`stable-mirror.omarchy.org`), which is materially behind upstream Arch — measured
   `linux 7.1.9.arch1-2` there vs `7.1.11.arch1-1` on `geo.mirror.pkgbuild.com`;
3. the bootloader — limine plus a Unified Kernel Image, not grub.

This is additive: a new key in a closed disjunction invalidates no existing config, so
it needs no migration entry and no `#SchemaVersion` bump.

Based on `main` after #68, which cleared the pre-existing lint failures that were
blocking every commit in this repo. This branch is a single commit containing only the
change described above.

## How tested

All four traits were verified against a **real installed Omarchy 4.0.1 guest**, not
inferred — the ISO was installed unattended under QEMU/OVMF from a `cidata` seed and
then inspected over SSH:

```
$ ssh user@omarchy-guest 'grep ^NAME= /etc/os-release; uname -r'
NAME="Omarchy"
7.1.9-arch1-2

$ pacman -Q omarchy                       # format: "pac"
omarchy 4.0.1-1

$ systemctl is-enabled sshd               # ssh_unit: "sshd"
enabled

$ systemctl is-system-running              # init: "systemd"
running

$ pacman-conf --repo core Server           # the pinned Omarchy mirror snapshot
https://stable-mirror.omarchy.org/core/os/x86_64
```

`ovmf_family: "arch"` follows from the guest being Arch-based; it booted under the
`edk2/x64` OVMF images this host ships, which is the `arch` family layout.

## Rulebook compliance

- **R3 — no duplication.** The traits live only in `#Distros`; nothing infers a distro
  trait from an account name, an image URL, or a source kind. `#DistroID` stays derived
  from the map's own keys, so the id space and the trait table cannot disagree.
- **R4 — no workarounds.** `spec/vocab_gen.go` is regenerated by `task cue:gen`, never
  hand-edited.
- **R5 — no legacy left behind.** Nothing is deprecated by this change; it is purely
  additive.
- **R6 — git safety.** Feature branch, PR-only, no force-push, no direct push to `main`,
  no hook bypass.
