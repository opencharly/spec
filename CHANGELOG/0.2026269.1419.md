# 0.2026269.1419 — feat(spec)!: a deploy identity may contain '.', the path join separator

## Summary of changes

Make the **deploy identity** dot-legal: a deploy key is now a dot-joined path of
dot-free **segments**, optionally suffixed with `/<instance>`. This is the
contract-root leg of the **unified-deploy-identity cutover**.

### Scope — what this PR does and does NOT do

**Does:** relaxes `ValidateDeploymentName` so `.` is the path join operator of an
identity (not a defect). This alone fixes the reported overlay-poisoning failure
(see R10 below).

**Does NOT:** retire the `vm:`-prefixed stored key. That is the **SDK leg** of the
same cutover — **opencharly/sdk#301** (`feat(deploykit)!: key a VM's per-host
state by its deploy IDENTITY`, in flight) — followed by the charly/plugin legs
and a `charly migrate` entry that re-keys existing `vm:<dashed>` overlay entries.
This PR makes **no** claim that the second identity is already gone; it removes
the grammar rule that made a dot a defect.

### RCA (8-step, measured live)

**Unexpected.** `charly deploy export` / `deploy show` hard-failed on a
namespaced deploy's per-host overlay, and a non-allowlisted warning rode every
namespaced bed's `cleanup` step:

```
load deploy config via executor: ~/.config/charly/charly.yml: deployment key
"charly.check-docs" contains '.' — the character is reserved for dotted-path
addressing (charly deploy add a.b.c), never a literal deploy-tree key
```

**Mechanism.** A namespaced deploy writes its **dotted identity** as the overlay
key (`charly.check-docs:`). The overlay is read back through the full project
loader, where `ValidateDeploymentName` rejected any `.` in a key — so the ENTIRE
overlay failed to load, not just that entry.

**Root cause.** The dot-ban encoded "dots are reserved for dotted-path
*addressing*" as "dots are illegal in a *key*" — conflating the address with the
key, which the unified identity makes the same string.

### Fix

`ValidateDeploymentName` accepts a well-formed identity and rejects only a
MALFORMED one — an empty segment (leading/trailing/doubled `.`) or an empty
instance (trailing `/`). `ValidateDeploymentMembers` applies the dot-free-segment
rule (a member name is a single segment; the dot belongs between segments).
