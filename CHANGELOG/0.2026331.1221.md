# 0.2026331.1221 — feat(schema): add defaults.buildkit, the buildkitd daemon settings

## Summary

Adds the project-level buildkit daemon surface to the contract: `#Buildkit` (the `[worker.oci]` settings charly manages), referenced by `#Box` (so a box entity's `buildkit:` is validated), by `#NodeDoc` (so the authored `defaults.buildkit` is validated by the **load-time document gate**, not silently decoded), and by `#BuildResolveReply` (so the build drive receives the authored settings and renders them into `buildkitd.toml`).

Fields: `process_mode`, `max_parallelism`, `snapshotter`, `no_process_sandbox`, the GC budget (`reserved_space` / `max_used_space` / `min_free_space`), per-record `gcpolicy` entries, `registry_mirror`, and a raw `extra` TOML escape hatch for any daemon setting charly does not model. Every field is optional; an empty value selects the daemon's own default — except the GC budget, which the drive always writes (100 GB), because buildkitd's compiled free-space target (373 GB) prunes the cache to its ~10 GB floor on a host with less free space. That is the measured cache-invalidation driver in opencharly/charly#1292: the small arch RUN stays CACHED while the builder's large `pacman -Syu` layers re-execute and change the artifact.

Producer/consumer order: this schema lands first; `opencharly/sdk` (the renderer + 100 GB default, PR #650) is independent of it; `opencharly/plugin-build` reads the shape and passes it to the daemon; `opencharly/charly` bumps the pins and runs the bed.

### Spike

**RCA claim (from charly#1292):** the repeated-build cost is the daemon's default GC pruning the cache, not the per-build tag; the project needs an explicit, authorable GC budget.

**Instrument:** a throwaway probe compiled against the shipped schema (`schemaconcat` + `#NodeDoc`, the load-time gate) that unifies one candidate document per arm and prints ACCEPTED/REJECTED with the CUE error. Run twice — `SP-1` on this head, `SP-2` with `schema/node.cue`'s `defaults?: _` restored (the pre-change tree) — so each candidate is measured, not argued.

```
=== SP-1  this head (defaults.buildkit typed)
A scalar defaults.buildkit_max_parallelism = -1      ACCEPTED
A scalar defaults.buildkit_max_parallelism = 4       ACCEPTED
C opaque defaults.buildkit = "[worker.oci]..."       REJECTED  #NodeDoc.defaults.buildkit: conflicting values "[worker.oci]\n  max-parallelism = 4\n" and {process_mode?:string,max_parallelism?:(int & >=0),...} (mismatched types string and struct)
B struct defaults.buildkit {max_parallelism: 4}      ACCEPTED
B struct defaults.buildkit {max_parallelism: -1}     REJECTED  #NodeDoc.defaults.buildkit.max_parallelism: invalid value -1 (out of bound >=0)
B struct defaults.buildkit {max_paralellism: 4}      REJECTED  #NodeDoc.defaults.buildkit.max_paralellism: field not allowed
B struct defaults.buildkit {} (empty block)          ACCEPTED
exit=0

=== SP-2  pre-change tree (defaults?: _)
A scalar defaults.buildkit_max_parallelism = -1      ACCEPTED
A scalar defaults.buildkit_max_parallelism = 4       ACCEPTED
C opaque defaults.buildkit = "[worker.oci]..."       ACCEPTED
B struct defaults.buildkit {max_parallelism: 4}      ACCEPTED
B struct defaults.buildkit {max_parallelism: -1}     ACCEPTED
B struct defaults.buildkit {max_paralellism: 4}      ACCEPTED
B struct defaults.buildkit {} (empty block)          ACCEPTED
exit=0
```

Reading the round:

- **A — scalar fields on `defaults` (`defaults.buildkit_max_parallelism`, …).** `ACCEPTED` in BOTH trees, including the out-of-range `-1`: a scalar scatter leaves the value unvalidated and cannot express a `[[worker.oci.gcpolicy]]` list. **Eliminated.**
- **C — one opaque `defaults.buildkit` TOML string.** `ACCEPTED` on the pre-change tree and `REJECTED` on this head: once the field is typed it is not a string, and if it stays untyped nothing is checked. It cannot be the primary surface; it survives only as `extra`. **Eliminated as the surface, kept as `extra`.**
- **B — a nested `#Buildkit` def referenced by `#Box`, `#NodeDoc` and `#BuildResolveReply`.** The only arm that is `ACCEPTED` for a valid document and `REJECTED` for `-1` and for a mistyped knob, while the empty block stays legal. **Winner.**

**Winner:** B. **RCA verdict:** confirmed — the def compiles, regenerates reproducibly, the generated types round-trip the shape into the resolve wire, and only B enforces the range/closedness that the authored surface needs.
