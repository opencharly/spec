# 0.2026321.1340 — feat(proto): carry Bind and Unbind on the plugin service — the contract row becomes callable

## Summary

**A contract row becomes callable — and until now it was not even reachable.**

`DESIGN.md:413` says a **binding** is *"a need or use paired with its provide, **delivered by `bind` to the owner of the capability type** (§8)"*, and `DESIGN.md:693` (D-CAP-4) says *"Bindings are state, delivered by the type's `bind`; they never appear in an authored file."* The shapes those sentences imply are already merged (`spec#352`: `#BindInput{need!, provided_by!, deployment!}`, `#BindOutput{binding!}`, `#UnbindInput{binding!}`).

**But nothing could call `bind`.** Measured before this change:

```console
$ git -C spec grep -n 'BindInput\|BindOutput\|UnbindInput' origin/main -- '*.go' '*.cue'
schema/bind.cue (the definitions) + spec/cue_types_gen.go (generated)   ← 6 hits, ALL the definition pair
$ # consumers: sdk 0, charly 0
$ git -C spec grep -c 'Bind' origin/main -- proto/plugin.proto → 0
```

**Zero `Bind` in the protocol.** So no out-of-process plugin could ever be handed a `#BindInput` however its manifest read. The shapes were a contract no transport carried.

### Why the zero was DELEGATION, not a missing shape

A grep returning zero can mean "the contract delegates this" — and here it does: `DESIGN.md:413` states the delivery, so the wire method is *implied*. **`Bind` was zero because nobody had wired it, not because DESIGN decided against it.** That is the difference between "we added a method" and "we made a contract row callable", and it is why this is the producer-first leg of a six-unit chain rather than an invention.

So the change is `protocol/schema/plugin.cue`, rendered by `internal/wiregen` through `charly task wire-gen`; `TestProtoMatchesSchema` fails on drift. **A hand edit of the proto would have been reverted by the next regeneration.**

### What was added

Two methods on the `Provider` service, three messages, **`bytes` + JSON throughout** — the `InvokeRequest.params_json` / `InvokeReply.result_json` pattern, with no typed mirrors:

```proto
message BindRequest   { bytes input_json  = 1; }   // the marshalled #BindInput
message BindReply     { bytes output_json = 1; }   // the marshalled #BindOutput
message UnbindRequest { bytes input_json  = 1; }   // the marshalled #UnbindInput
```

`Unbind` returns `Empty`.

**`BindReply` is ONE field, and the mirror is quoted in full so it can be checked:**

```cue
{
	"name": "InvokeReply"
	"doc":  "CheckResult / InstallPlan / Diagnostics, JSON"
	"fields": [
		{
			"name":   "result_json"
			"type":   "bytes"
			"number": 1
		},
	],
},
```

**One field, no error channel** — and `ProviderServer.Invoke(ctx, *InvokeRequest) (*InvokeReply, error)` shows why: **a failure crosses as the gRPC status.** An earlier draft of this message carried an `error` field; it was removed because it would have invented a shape *beside* the pattern it claimed to mirror. (`HostBuildReply`'s `error = 2` is the executor reverse-channel service, where a build failure is data; `Frame.error = 14` is the streaming leg. Neither is this mirror.)

**No destination field.** The reply IS the binding, the binding is state (D-CAP-4), and **a destination reachable only through the plan is a destination that requires the value in the IR** — so how the type owner effectuates delivery is the owner's business, not this message's payload.

### R7 — the round trip, and the ABSENCE half

**Two layers, because a payload that survives the wire says nothing about whether a method carries it.**

`proto/bind_wire_test.go` carries each payload `#BindInput` → JSON → `input_json` → `proto.Marshal` → `Unmarshal` → decode, asserts `need`/`provided_by`/`deployment` field-for-field, **then validates the decoded payload against the shipped CUE**.

`proto/bind_grpc_test.go` exercises **the METHOD**, over a real connection: an in-process gRPC server on **`bufconn`** — no port, no external service, **nothing to skip, because the service under test is one the test starts** — registers a stub type owner whose `Bind` decodes `input_json` into `#BindInput` and echoes `provided_by` into the returned binding, and a real `ProviderClient` then calls it. `client.Bind(...)`'s reply is **decoded and asserted** (`podman`, `bed`), `client.Unbind(...)` returns a non-nil `Empty`, and a stub returning `status.Error(codes.FailedPrecondition, …)` **surfaces with that code to the client** — the channel the one-field `BindReply` design depends on. If that ever stops being true, `BindReply` needs the field and this test is where it is decided.

(This module pins `grpc v1.61`, which predates `grpc.NewClient`; the dial is `DialContext` + `WithBlock` over the same bufconn listener — same connection, older spelling, and the code says why.)

```console
PLANT A — the decoder looks for the wrong key (`provided` instead of `provided_by`):
  --- FAIL: BindInput: need, provided_by, deployment
      provided_by did not survive: "", want "podman"

PLANT B — the schema stops closing need.type (`#Word` → `string`, then cue-gen):
  --- FAIL: a need type outside #Word
      the boundary accepted a #BindInput the schema refuses — the payload is transported, not validated

PLANT C — the CUE drops the `Bind` method row, then wire-gen:
  vet: proto/bind_grpc_test.go:96:23: client.Bind undefined
      (type ".../proto".ProviderClient has no field or method Bind)
  -- a COMPILE failure, which is the proof that deleting the method breaks a real caller.

PLANT D — the stub's Bind returns an empty #BindOutput:
  --- FAIL: Bind over gRPC
      the reply's binding = map[], want the provide the request carried (podman)
      -- the test must read the REPLY, not merely complete the call

RESTORED:  --- PASS  (three round trips + three absence cases + two method calls
                      + the status channel + the positive control)
```

**A and B prove the payload; C and D prove the method.** Plant C is a *compile* failure, and that is the strongest form of "a test that fails without the change": with the CUE row gone, `client.Bind` does not exist, so the caller the test is cannot be written. Plant D proves the test reads the reply rather than merely completing the call.

**Plant B is the assertion that earns the sentence.** A round trip proves bytes move; it does not prove the payload is *validated*. The absence half refuses three shapes that transport perfectly — a `need.type` outside `#Word`, a `provided_by` that is not a `#Ref`, and a payload missing a required field — **and a positive control so a validate-always-fails helper cannot pass it.**
