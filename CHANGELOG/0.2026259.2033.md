feat(schema): the shared OpenAI-compatible LLM vocabulary (#LLMSpec/#LLMParams)

Adds schema/llm.cue — the SHARED LLM contract with TWO consumers: the generic
pipeline engine's agent stages (candy/plugin-pipeline) and the `vision:` check
verb (candy/plugin-vision), which validates a screenshot by sending it to the
same endpoint. R3 puts the vocabulary in ONE place; the boundary law puts
authored CUE in this contract module. Same shape as schema/desktop.cue
(plugin-facing vocabulary in spec, generating the Go types a plugin imports).

- #LLMSpec: endpoint + connection config (base_url, model, api_key,
  organization, project, timeout, idle_timeout, max_retries, headers, params).
- #LLMParams: the general chat-completions request block (temperature, top_p,
  max_tokens, max_completion_tokens, frequency/presence_penalty, seed, stop,
  response_format, reasoning_effort, reasoning, stream_options,
  parallel_tool_calls, tool_choice, logprobs, top_logprobs, user, metadata,
  logit_bias, extra). Both CLOSED; `extra` is the one legal unknown-key path.
- #LLMResponseFormat / #LLMReasoning / #LLMStreamOptions / #LLMNamedToolChoice.

NO #SchemaVersion bump: purely additive optional defs with nothing to migrate —
the same shape as the iso VmSource arm, #DiskLayout, and the desktop kinds
(spec PR #74, which likewise added plugin-facing vocabulary without a bump).

Why the LLM defs are named #LLM* and not #ResponseFormat etc.: spec and the
plugin-pipeline mirror both compile in ONE CUE instance; a bare #ResponseFormat
would be a name that could collide with any future base def. The #LLM prefix
namespaces the shared vocabulary.

Tests (schema/llm_test.go, the desktop_test.go shape — CORPUS via unifyDef,
TEETH via unifyDefFinal): an ollama corpus block (env-referenced key, sampling +
structured output + reasoning + extra), a vision corpus block, an int literal
for a `number` param, closedness on both defs (each rejection NAMES the field),
the numeric ranges, the reasoning_effort enum (exactly ollama's accepted
high|medium|low|none), and the response_format type enum.
