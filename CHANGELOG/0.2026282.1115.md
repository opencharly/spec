# 0.2026282.1115 — fix(repo_identity): bound the local ref path by the project's repository (charly#848)

## Summary

`RepoIdentity`'s **LOCAL ref path** derived a directory from `ref` and handed it to
`ProjectRepoIdentity`, which reads THAT directory's `charly.yml`. Nothing bounded it to the importing
project, so a ref resolving outside the project's repository read **another checkout's manifest** and
returned its identity — a `repo:` declared by a neighbouring checkout came back verbatim. The
qualification path in the same file (`gitTopLevelRel`) was already bounded.

Closes **opencharly/charly#848** (split from `#847`; that one's `json:"-"` fix is complete on its own
terms and stays independent).

**The bound mirrored — quoted from the tree, not invented.** `gitTopLevelRel` already asks the
containment question:

```
topReal, _ := filepath.EvalSymlinks(top)      // both sides symlink-resolved
dirReal, _ := filepath.EvalSymlinks(dir)
filepath.Rel(topReal, dirReal)                // accepted only when
r != "." && r != "" && !strings.HasPrefix(r, "..")
```

Same predicate, same **boundary notion**: the git **working-tree toplevel**. That choice is what keeps
a sibling project *inside* one repository a definition mount (still resolved — a namespaced import of a
subdirectory project is exactly the case `#847`'s sibling test pins) while a ref that **leaves the
repository** names no project in it. `baseDir` is `filepath.Dir(abs)` at the call site
(`sdk/loaderkit/walk.go:190`), i.e. the importing project's own directory, so its repository is the
right boundary — not `baseDir` itself, which would have refused legitimate same-repo sibling mounts.

**R2 — the predicate is EXTRACTED, not copied.** It was about to exist twice, so `pathWithin` is now
the ONE implementation, called by `gitTopLevelRel` (to qualify a sub-path) and by `RepoIdentity` (to
refuse an escape), with `gitTopLevel` the one cached boundary lookup they share:

```
$ grep -n 'pathWithin(' spec/repo_identity.go
109:		if _, ok := pathWithin(top, dir); !ok {      # RepoIdentity — the containment gate
186:func pathWithin(top, dir string) (string, bool) {   # the ONE implementation
212:		if r, ok := pathWithin(top, dir); ok {        # gitTopLevelRel — the qualification
```

**An escaping ref is NOT an error.** `""` is this function's documented *"cannot be determined"*
answer — the same one it returns for a non-git directory — so the loader degrades to version/path-keyed
identity exactly as before. No new policy, and no new failure mode.
