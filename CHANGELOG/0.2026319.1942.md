# 0.2026319.1942 — feat(ir)!: the candy model carries the hook as opaque bytes

## Summary

The **first** of `#CandyModel`'s seven authored-shape fields to become opaque. `hook` was `#CandyHook`; it is now `bytes`:

```cue
	hook?: bytes @go(Hook,type=RawBody)
```

**And its surviving references**, so the "not removed" is evidence rather than assertion:

```console
$ grep -rn '#CandyHook' schema/*.cue | grep -v '^\S*:\s*//'
schema/boxmetadata.cue:176:	hook?: #CandyHook @go(Hook,optional=nillable)      # #BoxMetadata
schema/boxmetadata.cue:252:	hook?:        #CandyHook           @go(Hook,optional=nillable)  # #BakedLabelSet
schema/candy.cue:128:	hook?: #CandyHook @go(Hook,optional=nillable)      # #Candy (the authored body)
schema/candy.cue:456:#CandyHook: {                                     # the def itself
```

That is `DESIGN.md` §3.1 implemented rather than argued: the authored `#CandyHook` belongs to the plugin that owns the candy body, so the IR stops importing it and carries bytes instead (I1 / D-SCH-7). `deploykit`'s `specCandyAdapter` decodes what the build engine needs.

**Why this one first.** It is *shape-compatible with the wire that already exists*: the OCI label `ai.opencharly.hook` is already JSON — authored YAML → struct (`loaderkit/scan_candy.go`), struct → `json.Marshal` into the label (`deploykit/write_labels.go:110`), label → struct (`spec/container/box_metadata_coneb.go:151-156`). A `bytes` field therefore embeds exactly what the label already carries, and the producer/consumer pair becomes explicit instead of implicit.

**The reader set, swept against the CONSUMER's `origin/main`** — not against this branch and not against the paired SDK PR, which is unmerged:

```console
$ git -C <sdk> grep -n 'm\.Hook\|\.Hook\b' origin/main -- '*.go' | grep -vE '_test|BoxMetadata|meta\.Hook'
origin/main:deploykit/spec_candy_adapter.go:171:func (a *specCandyAdapter) Hooks() *HooksConfig { return a.m.Hook }
origin/main:loaderkit/scan_candy.go:327:	m.Hook = ly.Hook
```

Exactly two sites: the producer (`scan_candy`) and the one consumer (`specCandyAdapter`). The wider inventory that ordered this work is `PROGRAM/schema-ownership-rca-rdd.md` §7c — no field is free to opaque, but six of seven have exactly ONE production struct-field reader; `hook` is the one spread widest (4 repos), which makes it the best teacher and the worst to leave last.

**Landing order** (producer-first): this PR → `tag-on-merge` writes the CalVer tag → the SDK PR pins it and lands the marshal/decode pair. The coordination comment on this thread states the same on both sides.

It fails in three ways: if `Hook` reverts to `*CandyHook`; if the field stops serialising as `RawBody`; and if the bytes on the wire stop being the AUTHORED JSON verbatim (a quoted string is what plain `[]byte` produces, and base64 is what `encoding/json` does with it — either would silently change the `ai.opencharly.hook` label every existing reader decodes). The generator's no-op half is `TestGenReproducible`, already in this repo's gate.

**The consumer side is proven in the paired SDK change** (`opencharly/sdk`), where `scan_candy` marshals and `specCandyAdapter.Hooks()` decodes: `ok github.com/opencharly/sdk/deploykit 12.271s`.

## Change classification

Kind: a schema (IR) change in `spec`. **It breaks every consumer that reads `CandyModel.Hook` as `*CandyHook`** — which, per §7c, is exactly one production site (`sdk/deploykit/spec_candy_adapter.go:171`) plus `sdk/loaderkit`'s producer line. Both are handled in the paired SDK PR, which pins this tag.

**Breaking change + rollback:** consumers must decode the bytes (the SDK pair does). Rolling back restores `hook?: #CandyHook` and regenerates — the wire is unchanged either way, because the label was already JSON.
