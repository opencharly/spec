# 0.2026326.323 — feat(schema)!: a build-time manager is a builder — never a box format or a distro format

## Summary

The schema half of **one builder mechanism for every build-time manager** (aur, npm, pixi, cargo, mise). It's Unit 1 of opencharly/sdk#608. aur took a different road from npm on every surface, and each road had a silent skip: an `aur:` package declared in `layer-kde-shell` reached no image while the build stayed green (opencharly/layer-kde-shell#7). This PR removes the shapes those roads stood on and adds the ones the single road needs.

Removed (each one was a second road or a field nothing applied):
- `aur` from `_buildFormat` (`schema/box.cue`). A box's `build:` lists OS package formats only. `build: [pac, aur]` was an opt-in that dropped every declared aur package when it was absent.
- `secondary` from the distro `#Format` (`schema/distro.cue`). Its only user was arch's `format.aur` install template. `primaryFormat` loses its `secondary` arm (`spec/distro_methods.go`).
- `format_sections` from `#CandyModel` (`schema/candymodel.cue`), and `FormatSection` from `CandyReader` (`spec/candy_reader.go`). Only aur used them, merging every `distro.<x>.aur` into one image-independent section.
- `detect_config` from `#Builder` (`schema/builder.cue`).
- `#BuilderCollectInput.replaces` and the generated `Replaces` field (`schema/buildwire.cue`, `spec/cue_types_gen.go`) carried that same dead `replace:` to the aur collect leg; no install ever applied it.
- `#AUR.replace` (`schema/00_common.cue`). The loader read it, but neither mode applied it, and no repo in the org authors it (org code search: zero authored hits).

Added:
- `#TagPkgConfig.managers`, keyed by `#BuildType` (`schema/candymodel.cue`). A manager declaration lives on the distro tag it was authored under, like that tag's OS packages, so an image honours it only when its tag chain selects the tag. `mise` joins `#BuildType` (`schema/box.cue`).
- `#BuilderPackage {format, dir, glob}` (`schema/builder.cue`) is a builder's **declared** package output (aur's per-candy pac packages). It's the builder plugin's own knowledge, returned in `#BuilderResolveReply.package` and `#BuilderCollectReply.package` (`schema/buildwire.cue`). The IR carries it as `BuilderStep.Package` (`spec/install_step_vocab.go`), the step view as `builder_package` (`schema/deploy.cue`, `spec/install_step_view.go`), and the pre-pass as `BuilderPreresolved.Package` (`spec/builder_preresolved.go`). It's **never authored on the builder node**: DESIGN's builder node is a manager map (DESIGN.cue `#BuilderAlt`, D-IR-7). An earlier draft put payload and package fields into the authored vocabulary; that widened the gap from DESIGN, and the operator chose this plugin-owned shape (R11).
- `BuilderStep.Scope()` reads the step's declared `Package` instead of `s.Builder == "aur"` (`spec/install_step_vocab.go`).
- `#BuilderCollectInput.manifest` / `manifest_content` (`schema/buildwire.cue`). Each builder derives its teardown set from the candy's manifest (D-IR-2). Before, nothing filled npm's or cargo's teardown set, so their reverse was always empty. `#BuildStageContext` comments are reworded (`schema/buildctx.cue`).
- `#LoadedProject.embedded_defaults_digest` (`schema/loadedproject.cue`). This fixes a cache defect this cutover's own gate found. The materialized-tree cache keys on the walk envelope plus the spec/sdk versions, but the binary's embedded default vocabulary is also a materialize input. So a changed embedded `charly.yml` was served the previous vocabulary's cached tree. Measured: charly's `TestDeployCompileParity_PluginRoundTrip` failed on a warm cache and passed against an empty `CHARLY_CACHE_DIR`. The host walk stamps the digest (opencharly/charly, same cutover), so the envelope, and therefore the key, covers it.

Docs (round 3), this module's own skills, moving with the schema:
- `.agents/skills/layer/SKILL.md`: the AUR section now states the new rule. It is tag-scoped, the image routes the builder, an unrunnable builder fails loudly, and the install is the builder's declared package output. The `replace:` example is removed; it documented a `pacman -Rs` no install ran.
- `.agents/skills/image/SKILL.md`: `build:` lists OS package formats only, and the arch-test example drops `build: [pac, aur]`.
- `.agents/skills/install-plan/references/step-kinds.md`: BuilderStep scope comes from the declared package output, and an uninstallable output on a host venue is an error, not a skip.

Docs (round 4): every builder list names `mise`, which this PR adds to `#BuildType` (the image skill's `builder:` keys and `produce:` example, the layer skill's `build: all` row, step-kinds' BuilderStep row). install-plan `emit-opts-and-testing.md` now says "the vocabulary builders" instead of "the four DETECTION-builders", and gives the `BuilderResolveReply` shape with this PR's `Package` field.

`spec/cue_types_gen.go` is regenerated (`charly task cue-gen`; a clean regen is a no-op).

**The chain (producer-first, each PR its own gate):** spec (this PR) → sdk → plugin-builder, plugin-fleet, plugin-box, plugin-installstep, plugin-loader, plugin-deploy-pod and the builder plugins (aur, npm, pixi, cargo, mise) → charly → distro-arch → layer-kde-shell (reverts its workaround to `distro.arch.aur: [kdotool]`). Every downstream branch is committed and gated against this one through a Go workspace.
