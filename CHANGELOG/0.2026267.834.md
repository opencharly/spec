# 0.2026267.834 — feat(schema): add the generic task kind (#Task/#TaskValue)

## Summary

Add the generic `task` kind to the spec schema: `schema/task.cue` defines
`#Task`/`#TaskValue`, and `task cue:gen` regenerates the derived Go
(`spec.Task`, `spec.TaskParamSpec`) and the vocab (`KindValueDefs["task"]`).

A task is a named, host-native, reusable **plan** — the same `#Step`/`#Op`
grammar a candy's `plan:` uses — plus task-level execution config
(`dir`/`env`/`vars`/`depends_on`/`sources`/`generates`/`status`/
`preconditions`/`silent`/`interactive`/`platforms`/`timeout`/
`continue_on_error`/`params`). It is the declarative replacement for a
Taskfile entry, to be served by the new `opencharly/plugin-task`.

`#Task` references the base `#Step` grammar, so it is validated HOST-SIDE
against `#TaskValue` — the same pattern `#Candy`/`#Local`/`#Vm` already use
(a self-contained plugin schema cannot carry `plan: [...#Step]`). `schemagen`
auto-derives `KindValueDefs["task"] = "#TaskValue"` — no hand-maintained map.

**Purely additive:** a new kind removes nothing from any existing config, so
there is **no `#SchemaVersion` bump and no migration-table entry** (per
`/charly-build:migrate` "Purely additive changes").
