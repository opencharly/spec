# 0.2026324.636 — feat(schema): implement the declared os: and source: KINDS

## Summary

**`os:` and `source:` have been DECLARED kinds in the contract since DESIGN.cue:283-284, with their shapes written at :811 and :799-809 — and `schema/` implemented neither.** This adds both, mirrored verbatim.

**Why it matters:** `#SourceFields` requires `os!: #Ref @ref(os)`. A reference into a kind no schema admits is a dangling reference, so **a `#Source` node was unauthorable** — which is why a box starting point still arrives in five ad-hoc spellings (`base:`, `from: builder:<word>` + `bootstrap_builder_image`, a VM template `source:` block, `distro:`, and the still-declared `clone`/`imported` arms). This is the node those become.

**`#ImageRef` is deliberately NOT `#OciRef`.** This module already has `#OciRef` (`candy.cue:611`), which requires an explicit `oci://` scheme. The contract's `#ImageRef` carries no scheme — a source's `oci:` origin names an image the way `podman pull` does. Two spellings of two different things, so both stay.

**A `kind` with no behaviour is schema-only, and this module already has the pattern.** `schema/init.cue` is the same shape: a CUE def plus generated types, no provider. `#Init` validates one value of the `init:` map; `#Os` validates one value of the `os:` map.

### What the sixteen cases prove, and why they go through `cue.Concrete(true)`

| def | accepts | refuses |
|---|---|---|
| `#Os` | fedora+dnf, alpine+apk on openrc, arch with a bootstrapper and disk layout | no `package_manager`, no `init`, `emerge` outside `_packageManager`, an `init` role outside `_initRole`, an unknown key |
| `#Source` | `oci`, sha256-pinned `disk`, `bootstrap`, `iso` | **two origins**, **zero origins**, **no `os`**, an unpinned remote `disk` |

**The concreteness rule is why these are real.** `unifiesWith` uses `cue.Concrete(true)` because — as that helper's own comment records — a missing REQUIRED field leaves a value INCOMPLETE rather than bottom, so **a plain `Validate()` accepts an `os` with no `package_manager`.** A test built on `Validate()` would pass with the requirements deleted.

**D-SRC-1 is proven structurally rather than asserted:** two origins and zero origins are both refused, and an unpinned remote disk is unrepresentable because `#Download`'s `sha256` is required. **D-SRC-2** by the `no os` reject. **D-CANDY-3** by `no init` and `no package_manager`.

## Four module rules caught four real mistakes, each fixed

**This draft was wrong three times before it was right, and each time the module's own gate said so:**

1. `#SourceFields...` — **definition spread requires `@experiment(explicitopen)`, and this module carries no experiment flags.** The four origins now list their fields explicitly, which also makes "exactly one origin" readable where it is enforced.
2. `_initRole` with no `_initRoleWord` — **`TestEveryTableDerivesItsWordList` requires every S3 table to derive its word list.** Added.
3. `@vocab(registry)` / `@vocab(build)` / `@vocab(machine)` — **a table's vocab owner is `spec` in this module, because every set here compiles into the `spec` contract module.** Corrected on all three.

**I am recording these because they are the reason the first `go test` was red and the last is green** — not a claim that the shape is right because it compiles, but a record that the schema layer rejected three wrong versions of it.
