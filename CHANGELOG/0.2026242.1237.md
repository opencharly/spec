# 0.2026242.1237 — fix(container): confirm an image-resolution miss against a fresh list

## Summary

**A group bed with two image-backed members cannot check its second member.** That is why no such bed exists yet — the existing multi-member beds (`check-group`, `check-builder-vm`) use `local:` members with no image, so nothing had ever exercised this path.

`ListLocalImages` serves a 5-minute persistent cache, and `ResolveLocalImage` resolves a short name from it. The bed phase order is **build A → check A → build B → check B**. Checking A repopulates the cache from a snapshot taken *before* B was tagged, so checking B — a separate process, and now a cache **hit** — cannot see its own freshly built image:

```
charly: error: image "punktfunk-host:check-punktfunk-fleet-2026.242.1217" is not available locally.
               Run 'charly box pull punktfunk-host:check-punktfunk-fleet-2026.242.1217' to fetch it first
```

A stale **hit** is harmless — it names an image that exists. A stale **miss** is not. So a miss is now confirmed against reality before it is believed: drop the cache, gather once more.

## How the cause was established

The failure is deterministic — two consecutive runs of `check-punktfunk-fleet`, same failure at the same step, `FAIL after 113ms` (far too fast to be a real check).

The image was demonstrably present. From the host member's own build log, 113ms before the failure:

```
579:[7/7] COMMIT ghcr.io/opencharly/punktfunk-host:check-punktfunk-fleet-2026.242.1217
581:Successfully tagged ghcr.io/opencharly/punktfunk-host:check-punktfunk-fleet-2026.242.1217
```

and afterwards, from the store:

```
$ podman image exists punktfunk-host:check-punktfunk-fleet-2026.242.1217  ->  exists
```

So neither the build nor the tag nor podman's short-name resolution was at fault. The discriminator is in the two members' check-image logs:

```
client check-image: 1 "listing local images (first run — may take a moment)" line   -> cache MISS -> fresh list -> PASS
host   check-image: 0 such lines                                                    -> cache HIT  -> stale list -> FAIL
```

The passing member fetched a fresh list; the failing one was served the snapshot the passing member had just written. Confirmed by inspecting the cache at `~/.config/charly/cache/images.json`, which holds no `punktfunk-host:check-punktfunk-fleet-*` entry.

**Negative control** — retry removed:

```
--- FAIL: TestResolveLocalImage_RetriesOnStaleCacheMiss (0.00s)
    a stale-cache miss must be re-checked against a fresh list, got:
    image not found in local storage: punktfunk-host:check-punktfunk-fleet-2026.242.1217
```

That is the same error, on the same ref, that killed the bed.

The other two guards exist so the fix cannot drift into something worse. `GenuineAbsenceStillFails` keeps "confirm the miss" from becoming "retry until something turns up" — a real absence still reports `ErrImageNotLocal`, after exactly one confirmation. `CacheHitDoesNotRefetch` keeps the fast path fast: a hit never triggers a second enumeration, which matters because that enumeration is ~9s on a large store.
