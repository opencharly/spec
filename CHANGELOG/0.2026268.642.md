# 0.2026268.642 — fix(loadmodel): cycle-guard Beds() against mutual imports

## Summary of changes

Fix a **hang regression** in `UnifiedFile.Beds()` introduced by spec#154 (the namespace-aware bed resolver, MERGED).

`Beds()` calls `collectBeds`, which recurses `uf.Namespaces`. The merged version had **no cycle guard**. A mutual import — `main` imports `sub`, `sub` imports `main` — is the documented, intentionally-supported aliasing contract (the loader's pointer-identity cycle-break), and it makes the `Namespaces` graph cyclic. So `Beds()` recursed forever, hanging:
- `go test ./...` in `charly` (the suite deadlocked in `TestImportNamespace_MutualCycle`, then the runner killed it at its cap — the CI `go` check timed out at exit 143), and
- any real project load of such a config.

Sibling defect: the SAME missing-guard class in `fillNamespacedTemplates` was fixed in spec#155 for the TEMPLATE fold (`ancestors` stack); `collectBeds` (the BED fold) added by #154 was missed.

Fix: thread a **path-scoped ancestor stack** through `collectBeds` (`ancestors[uf]=true; defer delete(ancestors,uf)`): a genuine back-edge is skipped, while a shared namespace legitimately mounted at MULTIPLE alias paths (a diamond/multi-alias mount) still folds at every path — the reason a global visited set is wrong.

Adds `TestBeds_MutualCycleTerminates`.

**Closes / relates to:** fixes a regression from spec#154; sibling of spec#155. Unblocks charly#656.

**Breaking change + rollback:** none (pure fix). Rollback is a revert.
