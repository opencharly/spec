# 2026.227.1950 — correct the $TMPDIR test mechanism: GOTMPDIR, not statement order

`CHANGELOG/2026.227.1934.md` shipped the right fix on a partly wrong explanation,
and it is merged, so it cannot be edited. This entry corrects the record and fixes
the same claim where it is still live — the `altTempRoot()` doc comment in
`proc/temphold_test.go`. Comment and prose only; no behaviour changes, and the
`altTempRoot()` code itself is untouched and still correct.

## What the previous entry got wrong

It said `t.TempDir()` "consults `GOTMPDIR`, never the `TMPDIR` these tests are about,
**and it resolves BEFORE the `t.Setenv("TMPDIR", …)` that follows it**". The first
half is right. The second half credits statement order, which is not what does the
work: `t.TempDir()` never reads `TMPDIR` at all, so no reordering could have saved
the test. Naming order as the cause invites the wrong fix.

**The mechanism is that the two functions read different variables.**
`os.TempDir()` roots at `$TMPDIR`, else `/tmp`. `t.TempDir()` roots at `$GOTMPDIR`
— Go 1.26's `testing.makeTempDir` is `os.MkdirTemp(os.Getenv("GOTMPDIR"), pattern)`
(`$GOROOT/src/testing/testing.go:1460`) — falling back to `os.TempDir()` only when
`GOTMPDIR` is empty. The governing condition was never "is `TMPDIR` set" but
**"does `t.TempDir()` land outside `/tmp`"**.

Two other explanations circulated during review and are recorded here so neither is
re-derived: `go test` does **not** re-export `GOTMPDIR` as the test binary's
`TMPDIR` (measured — `TMPDIR` absent, `os.TempDir()` = `/tmp`), and `go test -c` is
not needed to reproduce. Plain `go test` with both variables cleared does it.

## One test was defective, not two

Measured on the pre-fix body (`bbb3c6a2`), plain `go test`, all four combinations:

| `TMPDIR` | `GOTMPDIR` | `SweepStaleTemps_HonoursTMPDIR` | `OpenedFilesByAnyProcess_HonoursTMPDIR` |
|---|---|---|---|
| set | set | FAIL | FAIL |
| unset | set | FAIL | FAIL |
| unset | unset | FAIL | **PASS — vacuous on a stock runner** |
| set | unset | FAIL | FAIL |

The previous entry's "its sibling escaped by accident … One shared root removes both
accidents" reads as though both tests were broken. Only
`TestOpenedFilesByAnyProcess_HonoursTMPDIR` was, and only in row three — the stock
CI default, no `TMPDIR` and no `GOTMPDIR`, which is precisely where it mattered.
`TestSweepStaleTemps_HonoursTMPDIR` discriminates in all four and was never
defective.

It shares `altTempRoot()` anyway, and that is a judgement call rather than a
correction: it discriminates via the pre-fix glob being non-recursive, a property
unrelated to what it asserts, which would go vacuous the day the sweep learned to
recurse. With the helper in place the same 2×2 is FAIL in all eight cells on the
merge-base body and PASS in all eight at the merged head — strengthened, not
weakened.

## The author's pasted evidence was true

The original PR's `--- WITHOUT TMPDIR ---` FAIL was a real run that reproduces
exactly. This host exports `GOTMPDIR=/home/atrawog/.cache/go-tmp` globally, which is
outside `/tmp`, so row two of the table above is red — the environment masked the
gap rather than anyone pasting something unrun. The single false claim was the word
*wherever* in the generalisation drawn from that run, and the review round that
introduced the "false evidence" framing withdrew it. Recorded here because the
merged entry does not say so.
