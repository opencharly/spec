# 0.2026250.903 — feat(cutover-c3): stage:/parallel: schema — the shared stage step modifier + the member-concurrency substrate scalar

## Summary

Cutover C task 3 (CC-3) — the `stage:`/`parallel:` schema. This is the FIRST PR of the CC-3 wave (spec → sdk → charly → umbrella).

**`stage:` — the shared STAGE-GROUPING step modifier** (`schema/_common.cue`):
- `#Op` gains a shared modifier `stage?: string & =~"^[^.]+$"` (singular, dot-free — dots are reserved for dotted-path addressing, like deployment keys).
- When a bed carries stages, the check walk groups steps by stage and executes the stage groups in first-seen order; within a stage, steps on DIFFERENT members run as INDEPENDENT Runner instances CONCURRENTLY (A4 — never share one Runner); same-member steps keep authored order.
- All-or-nothing per bed: if any step of a bed carries `stage:`, every step of that bed must (validated at load — the SDK PR).

**`parallel:` — the substrate scalar covering the deploy's members** (`schema/deploy.cue`):
- `#Deploy` gains `parallel?: bool` beside `disposable:`.
- When true: whole-member-plan concurrency (each member's plan on an INDEPENDENT Runner). Does NOT interact with `stage:` — stages dominate.

**Generated + tests:**
- `task cue:gen` regenerated: `Op.Stage`, `Deploy.Parallel`, vocab `AuthoringVerbs`/`OpFields` gain `stage`.
- New `spec/stage_parallel_cue_test.go`: CUE-level typing gates (dotted stage rejected, empty stage rejected, non-bool parallel rejected; valid values accepted) + yaml round-trips for both new generated fields.
