# 0.2026288.1152 — docs(exitcode): state both routes to exit 3 — an absent host prerequisite, and an empty plan resolution

## Summary

The module's exit-code contract states, once, the check-command convention — and its line for **3** named a single route: *"the bed was SKIPPED (a required host prerequisite — e.g. a GPU — is absent)"*. `opencharly/plugin-check` now reaches 3 by a **second** route, because an empty plan resolution is a SKIP rather than a pass: an image that baked no `plan:`, a deployment whose source declares none, or a bed child whose own plan and `add_candies` contribute no steps used to print their no-plan sentence and **exit 0**, i.e. a phase that asserted NOTHING was indistinguishable from one that asserted everything and passed (`opencharly/plugin-check#110`, fixed in `opencharly/plugin-check#114`).

This is a **comment-only** change to the canonical table, and it does two things: it names both routes to 3, and it states the reading rule that follows from them — *nothing ran is neither a pass nor a failure, so a caller that reads only 0/non-0 must read 3 as "ask why", not as "green"*. That sentence is the part a caller can act on; the rest is the instance list.

**Why here, and why also in `sdk`.** This file is the single statement of the contract — the `sdk` copy says so itself (*"single-sourced here so both the HOST … and candy/plugin-check reference ONE contract"*) — while it had grown a second copy of the table. Those two copies had already **diverged**: the sdk one still asserted the narrower meaning after this code began reporting 3 for an empty resolution. So the pair of PRs is: this one fixes the canonical statement, and `opencharly/sdk`'s replaces its duplicate with a pointer to it. A second statement of a contract is a second contract (R2), and the divergence is the evidence rather than the argument.
