# 0.2026240.1812 — feat(distro): ovmf_family becomes a distro trait

## Summary

The second item of batch **B4**, and its producer leg.

The OVMF firmware family was a hand-maintained `ovmf_distro_aliases:` map kept in **two
byte-identical copies** — `charly/charly.yml` and `plugin-vm/candy/plugin-vm/build_defaults.yml`:

```
$ diff <(sed -n '144,153p' charly/charly/charly.yml) \
       <(sed -n '42,51p' plugin-vm/candy/plugin-vm/build_defaults.yml)
BYTE-IDENTICAL
```

Every new distro had to be added to both, and adding it to only one was silent.

It is a property of the distro exactly like `format`, `ssh_unit` and `init`, so it becomes the fourth
`#DistroTrait` field and generates into `spec.DistroOvmfFamilies` beside `DistroFormats` /
`DistroSSHUnits` / `DistroInits`.

## Optional, because the absence is meaningful

An id with **no** family keeps today's behaviour: `ovmfCandidatesForDistro` tries the union of all
families and the not-found error emits the generic install hint. `archarm` (aarch64 firmware paths
differ) and `alpine` stay unset, as they were — an unproven family is worse than the fallback.

Generating an optional trait needed `distroTrait` to take a `required bool`. The first version of
this PR added a **separate** `distroTraitOptional` — a near-verbatim copy differing only in the
missing-field branch. The validator blocked it as R3 duplication, correctly, and the two are now one
function.

The parameter carries a real distinction rather than being a flag for its own sake: `format`,
`ssh_unit` and `init` are declared by every id, so a missing one is a vocabulary bug and must fail
generation. The non-empty guard moves under `required` for the same reason — only a required trait
proves `#Distros` was populated at all.

## Two corrections that fall out of keying by real distro ids

- **`cachyos` gains a family it never had.** The alias table predated the distro, so a CachyOS host
  fell through to the union — and that is exactly the host the cstream VM beds run on.
- **`alma` is gone.** It was never a `#DistroID` (the id is `almalinux`), so that row could not match
  a validated distro: a dead entry that read like coverage.

```go
var DistroOvmfFamilies = map[string]string{
	"almalinux": "fedora", "arch": "arch", "cachyos": "arch", "centos": "fedora",
	"debian": "debian", "endeavouros": "arch", "fedora": "fedora", "manjaro": "arch",
	"rhel": "fedora", "rocky": "fedora", "ubuntu": "debian",
}
```

## How tested

```
$ task cue:gen      # SDD; reproducible, second run is a no-op
$ go test ./...     18 packages ok, 0 failures
$ golangci-lint run 0 issues.
```

`TestDistroOvmfFamilies` asserts more than the mapping:

- every family carried over from the old table is unchanged;
- `archarm` and `alpine` are **absent**, so the fallback is preserved rather than accidentally
  narrowed;
- every value is a family the OVMF path table knows;
- **every key is a real `#DistroID`** — the assertion that makes a second dead `alma`-style row
  impossible, rather than just removing this one.
