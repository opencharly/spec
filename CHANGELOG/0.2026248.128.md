# 0.2026248.128 — fix(refs): bound every network git op with a deadline + bounded retry

## Summary

Every network git subprocess in the @github ref resolution (`spec/refs`) executed through a bare ``exec.Command`` — no context deadline, no retry — so a `git ls-remote`/`git fetch` whose connection died in a GitHub HTTP/2 reset window (curl error 92 CANCEL / "RPC failed; HTTP/2 stream 5 reset") blocked its caller FOREVER (git's libcurl starts with no timeout). The r9 wave forensics: three 16-lane eval check runs froze permanently before deploy-add — 21 threads, 20x futex_wait + 1x do_epoll_wait on a dead socket.

The fix routes every network git op through a new `runGitOp` runner:
- **Bounded context deadline** — 30s for ref metadata (`ls-remote`: resolve / latest-tag / default-branch), 60s for transfer (clone / fetch / submodule update).
- **Bounded retry** — 2 retries with a short backoff (500ms, then 1s) that re-issues the op when the deadline killed it or git's stderr carries a transient-network signature ("RPC failed / HTTP/2 stream reset", connection reset, "Empty reply from server", early EOF, 5xx).
- **Permanent failures fail fast** — repo-not-found / 404 / 403 carry no transient signature and are never retried (retrying would mask the real error and triple its latency).

`GitResolveRef`, `GitLatestTag`, `GitDefaultBranch`, `GitClone` (both the commit-fetch and branch-clone paths) and `populateSubmodules` all go through the runner; local-only git calls (`git config -f`, provenance) are untouched.

New tests (refs/git_op_timeout_test.go) drive REAL git against a REAL git http-backend smart-HTTP server with per-request fault injection:

```
=== RUN   TestGitOpRetriesAfterHang
--- PASS: TestGitOpRetriesAfterHang (0.75s)              # first connection HANGS → deadline kills → retry succeeds, 2 requests
=== RUN   TestGitOpRetriesAfterKilledConnection
--- PASS: TestGitOpRetriesAfterKilledConnection (0.05s)  # first connection dropped ("Empty reply from server") → retried → succeeds
=== RUN   TestGitOpBoundsPermanentHang
--- PASS: TestGitOpBoundsPermanentHang (1.45s)           # permanently-hanging server → error "timed out after", bounded wall time
=== RUN   TestGitOpDoesNotRetryPermanentFailure
--- PASS: TestGitOpDoesNotRetryPermanentFailure (0.01s)  # 404 repo → exactly 1 request, no retry
PASS
ok  github.com/opencharly/spec/refs  2.256s
```

Without the deadline, the permanent-hang test would block forever; without the retry, the hang/kill tests would error instead of succeeding.
