# 0.2026331.148 — docs(xdg): a candy volume path takes `~`, not the braced `${HOME}`

## Summary

Corrects a measured false claim in the `xdg` skill — the one a session loads immediately before
authoring a cache volume, so a wrong spelling there costs a failed bed run.

The skill said a candy volume path accepts `path: "${HOME}/.cache"` and cited `kit.ExpandPath`
(`spec/spec/env_path.go`). That helper DOES expand `${HOME}`, but a candy `volume.path` never goes
through it: it is expanded by `sdk/deploykit.expandVolumeHome`
(`deploykit/volume_collect.go:51`), which resolves `~/`, `~` and `$HOME` and leaves the braced
`${HOME}` untouched. A `${HOME}` path therefore reaches podman literally and is rejected as
non-absolute — measured by the `pod-openwebui` witness bed, whose `hf-cache-on-the-volume` step FAILED
on that spelling and passed once it was written `~/.cache` (opencharly/sdk#647).

Two changes, both in `.agents/skills/xdg/SKILL.md`:

1. The worked example is `~/.cache`, with the trap named in the comment and a sentence saying
   plainly that the braced form is not expanded.
2. The paragraph that cited the wrong helper now names the helper a volume path actually uses, and
   says why the other one is a trap rather than an authority.
