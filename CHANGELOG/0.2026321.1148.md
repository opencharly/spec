# 0.2026321.1148 — fix(cue): mark the three #Opaque uses in bind.cue with their S10 reason

## Summary

D-PAT-1 requires that every **use** of `#Opaque` mark itself `// S10` on the line that uses it, because
an open struct is otherwise indistinguishable from a typo-tolerant shape. The three uses in
`schema/bind.cue` carried their reason only in the definition's doc comment — which the census does
not read — so `design-dpat` counted them as findings:

```
FAIL spec/schema/bind.cue:32: opaque: a #Opaque use with no // S10 marker — mark the line, or type
     the field (D-KIND-5)
FAIL spec/schema/bind.cue:51: opaque: ...
FAIL spec/schema/bind.cue:57: opaque: ...
```

That is why opencharly/opencharly could not pin past `af9c505429fe`: its pre-push gate compares the
schema census against `design/dpat-baseline.tsv` and fails on ANY new violation. So a spec commit
carrying three findings blocked every consumer, and the umbrella's `spec` pin sat `behind` through two
waves (filed as opencharly/spec#357).

Each site now names what makes it foreign-owned, on the use line:

```cue
#BindNeed: {
	type!:   #Word
	name!:   #Text
	config!: #Opaque // S10 — foreign-owned: only its type knows the shape (D-CAP-2)
}

#BindOutput: {
	binding!: #Opaque // S10 — foreign-owned: core never inspects the owner's handle (D-CAP-2)
}

#UnbindInput: {
	binding!: #Opaque // S10 — foreign-owned: only the type owner can map it back (D-CAP-2)
}
```

Nothing else changes. The shapes are the same; `#Opaque` remains the one open struct (§4, S10:
*foreign-owned payload*); and the long explanations stay where they were, in the definitions' doc
comments.

**Markers are single-line on purpose.** My first attempt put the reason on a continuation line; the
schema generator carries continuation lines into the generated Go as doc comments, which produced
truncated fragments like `// configuration shape (D-CAP-2), and a solver that inspected it would be a
second authority`. A one-line marker keeps `spec/cue_types_gen.go` byte-identical.
