# 0.2026322.1143 — fix(container): carry the engine stderr in the image-list error

## Summary

**A failed image enumeration said `exit status 1` while the engine's explanation sat unused in
memory.** `defaultListLocalImages` ran the engine through `cmd.Output()` and wrapped the result with
`%w` alone. `exec.Cmd.Output()` populates `*exec.ExitError.Stderr` **whenever `cmd.Stderr` is nil** —
exactly this call — so the engine's diagnostic was already in hand and then discarded. `%w` preserves
only the status, and an `ExitError`'s `Error()` is literally `exit status 1`.

The neighbouring timeout branch is careful and diagnostic ("the local image store is large or
contended; prune it (charly clean) or retry when builds are idle"). The exit-status branch was not, so
the failure a caller most often hits was the one that said the least.

### Measured — 2026-11-18, this host

With a build holding the engine's storage lock:

```console
$ charly clean --images --keep 3 --dry-run
charly: error: command "clean": pruning images: listing local images via podman: exit status 1
```

podman had the cause on stderr; it was thrown away. The only way to learn it was to run the engine by
hand — an R3 workaround created by a missing diagnostic.

## The fix

`engineFailureDetail(err)` extracts `ExitError.Stderr`, collapses it to one line (`strings.Fields` +
join, so a multi-line engine diagnostic stays readable in an error), and bounds it at 400 runes with a
**visible** ellipsis. The wrap carries it only when there is text to carry, so a failure with no
stderr (a signal, a start failure) keeps the plain message instead of gaining a dangling `": "`.

### The changed branch ran live, against a REAL engine — with the cache bypassed

A bogus `CONTAINERS_STORAGE_CONF` makes the real `podman` fail for real; nothing on the host is
created, mutated or deleted, because podman cannot read its own config:

```console
$ CONTAINERS_STORAGE_CONF=/nonexistent/storage.conf podman images --format json
rc=1

$ CONTAINERS_STORAGE_CONF=/nonexistent/storage.conf CHARLY_CACHE_DIR=/tmp/cs/emptycache go run .
  # calls container.ListLocalImages("podman") from this head
charly: listing local images (first run — may take a moment)...
error: listing local images via podman: exit status 1: Failed to obtain podman configuration: open /nonexistent/storage.conf: no such file or directory
```

`CHARLY_CACHE_DIR` points at an empty directory **deliberately**: `ListLocalImages` serves a TTL'd
cache entry keyed by engine, so without the bypass a warm cache would answer and the arm would prove
nothing about the error path. The first attempt at this arm did exactly that and printed
`unexpected success`; the bypass is what makes the measurement real.

Before this change the same path printed `listing local images via podman: exit status 1`, full stop.
