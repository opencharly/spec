# 0.2026328.2055 — docs(xdg): how the roots resolve inside a pod

## Summary

`.agents/skills/xdg/SKILL.md` gains one section, **Inside a pod**, stating how the roots resolve in a container and the two things never to do about it.

A charly pod runs as its image user — under `--userns=keep-id` when it has a bind mount — and no charly pod runs as container root (D-HW-10). `HOME` is therefore the image user's own home, and `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME` and `XDG_STATE_HOME` — HOME-derived by specification, and the inputs `storeroot` derives from — resolve exactly as they do on the host. `storeroot` consequently sees the same `~/.config/charly`, `~/.local/share/charly`, `~/.local/state/charly` and `~/.cache/charly` the image user owns, and a volume mounted under that home is the same tree. Nothing has to be set in the deploy.

The two prohibitions, both derived from the same fact:

- **Do not set `XDG_*` in a deploy.** They are derived from `HOME`; an explicit value overrides an operator's choice and any image that sets its own.
- **Do not set `HOME` to compensate for a user that resolves the wrong one.** A workload whose home is not the image home is running as the wrong user — the defect to fix is the user (D-HW-10), not a variable.

## How tested

The section's measurement ran inside the image at keep-id as the image user (podman 6.2.0, crun 1.31, rootless):

```
$ podman run --rm --userns=keep-id:uid=1000,gid=1000 --user 1000 --entrypoint /bin/sh <image> \
    -c 'echo HOME=$HOME; id -un; id -u; echo XDG=[$XDG_CONFIG_HOME][$XDG_DATA_HOME][$XDG_CACHE_HOME][$XDG_STATE_HOME]; python3 -c "import os;print(os.path.expanduser(chr(126)))"; node -p "require(chr(111)+chr(115)).homedir()"'
HOME=/home/user
user
1000
XDG=[][][][]
/home/user
/home/user
```

Every claim in the section is either that output or a direct consequence of the HOME derivation the file already documents above it. The claim is discriminating: with `HOME` at `/root` (the container-root shape this rule removes), the same programs report `/root` — the reason `HOME` must not be left wrong, and the reason it must not be pinned either.
