# 0.2026321.1009 — fix(schema)!: name the volume access mode vocabulary _volumeAccessMode

## Summary

**A vocabulary name was spent twice, and CUE merged the two meanings without a word.**

`schema/deploy.cue` declared `_access` for a deployment volume's **access mode** (three modes). `DESIGN.cue:489` uses `_access` for something else entirely — the **venue access** words (`exec`, `copy`, `log`, `console`, `display`, `forward`, `power`). CUE unifies same-name definitions silently, so the two vocabularies became one of ten words:

```
_accessWord → ["exec", "copy", "log", "console", "display", "forward", "power"] + 3 volume modes
cue eval    → exit 0
go build    → rc=0
```

Nothing refused it. **The collision was invisible to every gate the module runs**, and it would have surfaced only when the capability surface tried to cite `_access` for venue access and silently accepted a volume mode.

Found while porting the capability-ask surface from `DESIGN.cue`. `DESIGN.cue` is the single schema copy, so the name belongs to DESIGN; the volume concept gets its own.

| before | after |
|---|---|
| `_access` (volume modes) | `_volumeAccessMode` |
| `_accessWord` | `_volumeAccessModeWord` |
| `#DeployStorage.access` (the one citation) | follows the rename |
| the authored field `access:` | **unchanged** — the wire is untouched |
