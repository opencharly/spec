# 0.2026242.1105 — fix(lock): bound the blocking acquire — fail fast on a contended flock

## Summary
The recurring fleet-del stall (VM beds' cleanup hanging in futex_wait) has a THIRD unbounded wait, distinct from the two already fixed in sdk#191 (engine command + agentkit store lock): `lock.AcquireFileLock` (spec/lock/filelock.go) ran `syscall.Flock(LOCK_EX)` with NO timeout when `blocking=true`. A goroutine dump from the stuck `charly fleet del` shows it parked in `spec/lock.AcquireFileLock` for 14 minutes.

Fix: the blocking acquire now polls `LOCK_NB` with a 50ms interval, failing fast after `lockTimeout` (2 min, a package var for testability) instead of blocking forever on a contended lock. The non-blocking path is unchanged.
