# 0.2026320.2116 — fix(vm)!: make #ResolvedVm.backend and .autostart optional, unbreaking every vm create

## Summary

Makes `#ResolvedVm.backend` and `#ResolvedVm.autostart` **optional** instead of `!`-required, which
unbreaks `charly vm create` for every VM in the org (opencharly/spec#341).

```
charly: error: command "vm": applying vm defaults for "<entity>":
  applyCueDefaults vm: decode: autostart: cannot convert non-concrete value bool
```

Head `6d0b176`, **3 files, 122 insertions(+), 4 deletions(−)**.

### Mechanism — traced, not inferred

The SDK's kind table maps the vm kind to **this** def (`sdk/loaderkit/cue_schema.go`:
`cueKindDefs["vm"] = "#ResolvedVm"`) and `candy/plugin-vm/vm_host_seams.go` routes every VM
operation through `loaderkit.ApplyCueDefaults("vm", vm)`, which:

1. marshals the **resolved** struct — `Backend string` and `Autostart bool`, both with `omitempty`, so an
   unset value is **omitted** from the marshaled YAML;
2. unifies that YAML with `#ResolvedVm`;
3. **decodes back, with no `.Default()` call anywhere** in the function.

With `autostart!: bool` / `backend!: string`, step 2 leaves those fields non-concrete whenever the struct
omitted their zero values, and step 3 fails. `false` *is* a zero value, so **an entity that does not
autostart could never be encoded at all**.

### Why not a default — measured, and it corrects my own earlier report

The obvious fix, `autostart!: *false | true`, does not work:

```
#ResolvedVm.autostart: cannot convert non-concrete value *false | true
```

**`Decode` never resolves a default disjunction**, so a required-with-default spelling fails identically.
I asserted the opposite on opencharly/spec#341 earlier in this campaign; this PR and a comment on that
issue correct it.

Optional is both the fix and the shape this envelope **already documents for itself** — its own comment
says the resolved envelope carries "PLAIN post-default scalars", set by the producer when they are set:

> ResolvedVm mirrors #Vm's fields — written out explicitly rather than embedding #Vm, since the resolved
> envelope carries PLAIN post-default scalars, not #Vm's own enum/default machinery (firmware/backend/autostart
> are plain string/bool here, never the `*"bios"|...` disjunction).

What this does **not** change: an authored `backend:`/`autostart:` still validates against the same closed
vocabulary, and the second test pins that every provider word is still accepted — no validation is traded
for the fix.

**The generated diff is NOT comment-only, and my first revision of this body wrongly said it was.** The
retag transform follows the constraint, so the JSON tags change too:

```
- Backend   string `yaml:"backend,omitempty"   json:"backend"`
+ Backend   string `yaml:"backend,omitempty"   json:"backend,omitempty"`
- Autostart bool   `yaml:"autostart,omitempty" json:"autostart"`
+ Autostart bool   `yaml:"autostart,omitempty" json:"autostart,omitempty"`
```

The Go **types** are unchanged (`string`, `bool`), so nothing recompiles differently — but the JSON wire
shape does: a consumer decoding JSON now sees the key ABSENT where it previously saw `""` / `false`. That
is the correct counterpart to the optionality (YAML already carried `omitempty`) and it is called out in
the breaking-change answer below rather than left for a consumer to discover.

**Coverage limit, stated rather than glossed:** this lands the CONTRACT fix. The end-to-end proof — a real
`charly vm create` succeeding — needs this tag, then the `sdk`/`charly` require bump, then a rebuilt binary.
That is the producer-first sequence and it is **not claimed here**.

## Change classification

Schema (CUE) change plus one generated-file refresh and one new test.

**Breaking change + rollback:** it is `!`-marked because it relaxes a required field, and the effect reaches
the wire in two directions. In CUE, an envelope whose producer omitted the values now DECODES instead of
failing — that is the fix. In JSON, those keys are now omitted instead of emitted as `""`/`false`, because
the retag transform put `omitempty` on the JSON tags to match; a JSON consumer that assumed the keys are
always present must treat absence as the zero value. Nothing else moves: both fields keep their names,
their types, their validation (the provider-word test above pins it), and their YAML spelling, so no Go
consumer recompiles differently. Rollback is a revert of this commit; the
two fields return to required and every `charly vm create` breaks again, which is the state this PR exists
to leave.
