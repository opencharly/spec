# 0.2026287.638 — feat(schema): external-cluster inputs — kubeconfig on kubernetes:, guest identity on kubevirt:

## Summary

Two authored inputs an **externally-managed** Kubernetes cluster needs, neither of which
`charly.yml` could express. The gap is exercised, not theoretical: on a live OVH-managed
cluster (`quant-dev`, 3 nodes, k8s `v1.35.2`) KubeVirt `v1.9.0` + CDI `v1.66.1` were installed
and a `VirtualMachineInstance` reached `Running` (`virt-launcher 2/2`) — and the two missing
inputs are exactly what stood in the way of doing it from config.

**1. `#Kubernetes.kubeconfig` (+ the same key on `#ResolvedKubernetes`).** Today `#Kubernetes`
carries a context name only (`schema/kubernetes.cue:18`), `#KubernetesDeployVenue` carries
`kube_context` only (`schema/deploy.cue:805-810`), and the deploy path shells `kubectl
--context` with no `--kubeconfig` (`plugin-kube/candy/plugin-kube/deploy.go:169-174`). An
externally-managed cluster is normally addressed by a **per-cluster file**, not by the ambient
`$KUBECONFIG` / `~/.kube/config`, and a context name cannot be resolved against a file charly
was never told about. The `kube:` and `kubevirt:` **verbs** already accept `kubeconfig:`
(`plugin-kube/.../schema/kube.cue:60`, `plugin-kubevirt/.../schema/kubevirt.cue:47`) — that
asymmetry is the gap. Empty keeps today's behaviour (the ambient file a charly-created
k3s/kind cluster relies on).

**2. `#KubeVirt.distro` / `.ssh_user`.** `resolveGuestIdentity` hard-errors for every
non-containerDisk source **even when `cloud_init:` is supplied**
(`plugin-kubevirt/candy/plugin-kubevirt/lifecycle.go:383-386`; its own message says the pair is
"not yet carried by #KubeVirt"). That makes the CDI `data_volume` arm — the one external-cluster
boot path that needs **no image registry and no node SSH** — undeployable. The pair mirrors
`#VmBoxMetadata`'s existing `distro`/`ssh_user` (same Go field names, one vocabulary); an
explicit value always wins over box metadata.

**Both fields are plain `string`, and the id/presence rules live in the kind provider's
`OpValidate`** — the home this file's header documents for cross-arm rules. Two anomalies were
run through RCA while authoring and fixed in this same change:

* a CUE `if` keyed on the `@go(-)` union discriminator `source.kind` collapsed the whole
  `#KubeVirt` type to `any /* IncompleteKind: _|_ */` (gengotypes cannot complete a definition
  whose conditional depends on a `@go(-)` union) — the presence rule moved to `OpValidate`;
* `distro?: #DistroID` emitted `undefined: DistroID` in the generated Go — `#DistroID` is
  `@go(-)` and generates no Go type — so the field is a `string` validated against the
  vocabulary in `OpValidate`, exactly as `#VmBoxMetadata.distro` already is.

Migration: additive only (two optional keys). The one tightening — the pair being required for
non-containerDisk arms — breaks nothing in the org; executed check below.

Closes #220
