# 0.2026241.931 — feat(refs): the git cache lives in the per-host charly.yml `cache:` section

## Summary

The per-host charly.yml (`~/.config/charly/charly.yml`) is the SINGLE home for local system state — deployments (`deploy:`), install records (`ledger:`), local system info (`system:`), and cache status (`cache:`). The git metadata cache the loader resolves @github refs with moves HERE, out of the ad-hoc JSON files under `~/.cache/charly/repos` (`git-cache.json` / `latest-tags.json` — both deleted).

**New kinds (CUE-sourced, SDD):**
- `schema/cache.cue` — `#CacheConfig`/`#GitCache`/`#GitCacheEntry`: the `cache:` kind (latest tags, default branches, resolved refs, downloads)
- `schema/ledger.cue` — `#LedgerConfig`: the `ledger:` kind (deploy/candy records — the install ledger's new home)
- `schema/system.cue` — `#SystemInfo`: the `system:` kind (host identity: hostname, distro, kernel, arch, GPU, …)
- `schema/node.cue` — `cache`/`ledger`/`system` are reserved `#NodeDoc` directives (not mis-read as nodes)
- `spec/loadmodel.go` + `spec/fleet_config.go` — `Cache`/`Ledger`/`System` fields on `UnifiedFile` + `FleetConfig`

**GitClient cache relocation (R3/R5):**
- `refs/git_client.go` — the cache is now a lightweight YAML read-modify-write of the `cache:` key in the per-host charly.yml (preserving every other key — `deploy:`, `provides:`, …), under the advisory file lock, with the HEAD schema version stamped on a fresh file. No more `git-cache.json`.
- `refs/git.go` — `GitLatestTag`/`GitDefaultBranch` are now pure network primitives; the per-primitive `latest-tags.json` cache is DELETED (R5). One cache, one layer — the GitClient owns caching.
- `refs/git_client.go` — the warm-up is parallelized (10-worker pool): 200 repos × ~1.5s sequential ≈ 5 min collapses to ~30s.
- `cue:gen` regenerated `spec/cue_types_gen.go` + `spec/vocab_gen.go` (reproducibility test passes).
