# 0.2026269.759 — fix(container): parse docker's NDJSON images --format json output

## Summary

`ParseLocalImagesJSON` assumed podman's single JSON-ARRAY shape and did one
`json.Unmarshal` into a slice. Docker's `images --format json` differs in **two** ways, both of
which broke `charly clean` on docker-backed hosts:

1. **NDJSON, not an array.** Docker emits JSON LINES (one object per line), so the
   whole-buffer unmarshal failed with `invalid character '{' after top-level value` on the
   labeled listing.
2. **Empty output on a no-match filter.** `docker images --filter dangling=true --format
   json` emits nothing when the store has no dangling images, so the unmarshal failed with
   `unexpected end of JSON input`.

Both are fixed: empty (or whitespace-only) output is a valid EMPTY result; a non-empty buffer
is tried as an array (podman) then decoded per line (docker). A line that is not valid JSON is
an error, never silently skipped.

Docker's rows also carry separate `Repository` + `Tag` scalars (`<none>` when absent) rather
than podman's `Names` array or docker-inspect's `RepoTags`, so a third ref-extraction fallback
builds the ref: `Repository@Digest` for a digest-pinned row (Tag `<none>`, Digest
`sha256:…` — the pull-by-digest shape, which must not degrade to a bare `repo` that matches a
DIFFERENT image), else `Repository:Tag`, else the bare `Repository` when the tag is `<none>`.

### Why it lands here (producer)

Found live via the command-parent R10 bed `check-commands-local` on a docker-backed host (its
`clean --dry-run` step). The failure is present on `main` and independent of that cutover, so
it lands as its own fix; the charly leg consumes the merged tag.
