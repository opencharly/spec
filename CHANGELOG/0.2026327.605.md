# 0.2026327.605 — feat(seam): a check run can execute a bed's own run: steps

## Summary

opencharly/plugin-check#153 — the kde-cstream plan's **G5**. In `charly check run`, the live stage is verify-only, so **every bed `run:` step is skipped** and a bed's actions (resize the stream, launch a terminal, send input) never happen; every dependent `check:` step then asserts against an action that did not run. Measured on `check-kde-cstream-pod`: `121 steps: 71 passed, 22 failed, 28 skipped`, with each failure traceable to a `skipped — verify-only mode (mutating step)` step. Authoring those actions as `check:` steps is what D-VERB-1 forbids ("the one step that changes state is a `run:` step").

`#CheckRunRequest` gains one field:

```cue
bed_actions?: bool @go(BedActions)
```

- **Set only by `charly check run`'s live stage** on a `disposable: true` bed — D-DEP-3 authorizes apply-and-reverse there. A plain `charly check live` stays verify-only, and the plugin refuses a non-disposable deployment loudly rather than skipping.
- **The sdk rule that consumes it executes only the plan's DEPLOY section** — the candy and box install timeline (which ran at build) stays skipped.
- This PR is the SCHEMA half; the sdk rule and the plugin's argv/guard follow producer-first, each with its own mutation-proven test.
