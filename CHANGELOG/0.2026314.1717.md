# 0.2026314.1717 — refactor(schema): derive every word-list enum from a vocabulary table (S3)

## Summary

`spec` is the producer: the schema every entity in the org is judged against. It carried
**187 `union` census rows** — disjunctions written out alternative by alternative. This PR
converts every pure **word list** among them into the §10.1 S3 vocabulary table:

```cue
_context: {build: {}, deploy: {}, runtime: {}} @vocab(spec)
_contextWord: [for w, _ in _context {w}]

#Context: or(_contextWord) @go(-)
```

**137 rows are swept, 50 are left, and 0 are added** (census emitted on a scratch umbrella
worktree whose `spec` gitlink is this head — below). 135 tables stand behind 136 sites. The
generated Go is **byte-identical**: `spec/cue_types_gen.go` and `spec/vocab_gen.go` both
regenerate with no diff, so the module's API — and therefore the sdk contract and every
plugin that imports `github.com/opencharly/spec/schema` — does not move at all.

Refs opencharly/opencharly#945 (the census), #950 (the sequence), and the fourteen proven
legs: plugin-spice#15 and plugin-cdp#8 (the two read for this PR), plus plugin-jetkvm#15,
plugin-cua#10, plugin-punktfunk#20, plugin-agent-pi#11, plugin-gh#13, plugin-omarchy#11,
plugin-agent#15, plugin-task#65, plugin-desktop-kind#4, plugin-herdr#15, plugin-appium#12,
plugin-vm#94.

**The one judgement this repo needs, and it is a measured correction of the brief.** The
brief's working number was "98 of 187 are pure word lists". Measured at this pin with two
independent instruments (the calibrated line scanner and the CUE AST), the split is:

| class | rows | what it is |
|---|---|---|
| pure word lists | **116** | every alternative a quoted string |
| literal-default word lists | **26** | a word list carrying a `*"word"` default (`*"locked" \| "shared" \| "private"`) |
| definition / shape / list-or-string / matcher unions | 45 | not word lists at all |

137 of the 142 word-list rows are swept; the other 5 are left with reasons (below). So the
headline is **137 of 187**, not 98 — and the four rows the brief's own recipe would have
swept blind are exactly the ones that needed a decision.

Three shapes needed care, and each is now stated once in `schema/README.md`
("Vocabulary tables (S3)"):

- **A literal default stays inline** and is also a table row:
  `sharing?: *"locked" | or(_sharingWord)` with `_sharing: {locked, shared, private}`. The
  default is part of the surface (omitting the key materializes it), and the accepted set is
  unchanged. 26 rows are this shape.
- **A list element**: `interaction_modes?: [...or(_interactionModesWord)]` — five rows.
- **A two-value literal default stays as written** (`mode?: *"internal" | "external"`,
  `autostart: *false | true`): S3's one permitted inline enum. 34 such unions carry no
  census row and are untouched.

### Left — 50 rows, and why each stays

| rows | why |
|---|---|
| 45 | **Not word lists.** A definition union (`#VmValue: (#Vm \| #DeployValue)`), a key-tagged struct union (`#MatchOpMap: {equals: _} \| …`, `#Step`'s five arms), a list-or-scalar (`#PortScope`, `#MatcherList`, `llm.stop?: string \| [...string]`), a word-or-def (`tool_choice?: "none" \| "auto" \| "required" \| #LLMNamedToolChoice`), or a `string & !="" \| int` pair. These are S4 tag-table work (or genuinely not unions of words) and are the experimental-language-flag half the brief keeps out of scope; they stay censused. |
| 4 | **A word list whose last alternative is `""`**: `#Op.extract`, `#Security.cgroupns`, `#Security.ipc_mode`, `#KubeVirtDomain.machine`. An empty string is not a word, so it is not a vocabulary-table row — putting `"": {}` in a table would make the table's key set stop being a set of words, which is S3's definition. Sweeping them would need a second spelling (`or(_xWord) \| ""`), which is the "invent a second convention" the brief forbids; and they cannot simply drop the alternative without moving the surface. Left, reported, not forced. |
| 1 | **`#Tunnel: (("tailscale" \| "cloudflare") \| {…})`** — the word set is a sub-expression of a larger word-or-struct union, so converting the inner union leaves the line's own disjunction in place (the census row would survive with a new symbol). The `provider:` field inside the struct arm **is** swept. |

### 5. Text-parsed disjunctions — the pre-sweep check — step 5

A derived enum has no text body, so anything that reads an enum's SOURCE or its compiled
alternatives by TEXT would see an empty set. Checked before the sweep, in this repo and in

## Change classification

Schema-internal refactor of the contract module's CUE FORM. Nothing a consumer reads moves:
the generated Go params and the generated vocabulary lists are byte-identical, so every
plugin, the sdk contract and charly core see exactly the same types and the same word lists;
no definition, field, tag or authored word is added, renamed or removed; the accepted
authored surface is unchanged over 135 swept sites (3476 checks) and 2192 real documents
(3619 judgements). What DOES change is the CUE text itself — the derived form replaces the
written-out union — so anything that renders that text verbatim (a generated reference page)
will show the new form after its own regeneration, and a plugin whose served schema imports
`github.com/opencharly/spec/schema` will compose 135 more hidden labels, which are
package-scoped and provably inert (the compose probe above).

**Breaking change + rollback:** no consumer breaks and **no `sdk` bump is owed** — the
lockstep question the brief raises is answered by measurement, not by caution: `sdk`'s
`vmshared/spec_aliases.go` re-exports spec types and `sdk/kit` imports it, so a spec bump
would need an sdk bump only if a type or word it re-exports disappeared — and
`spec/cue_types_gen.go` and `spec/vocab_gen.go` regenerate byte-identical, so not one
exported identifier or vocabulary slice changed. Consumers (`plugin-tunnel`, `plugin-vision`
and every other importer of `github.com/opencharly/spec/schema`) therefore compile and behave
