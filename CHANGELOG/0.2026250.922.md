# 0.2026250.922 — feat: add the config: plan-step verb (CUE schema contract)

## Summary

Add the **`config:` plan-step verb** — a CUE-schema-driven config-file generator for the run step catalog (SDD: `schema/_common.cue` is the single source; Go types regenerated by `task cue:gen`).

- `#OpVerb` gains `"config"`; the CLOSED `#Op` gains `config?: string` (scalar destination path, exactly like `write:`) and the shared `validate?: string` modifier (non-empty when set) naming a vendored CUE format schema (the egress-schema set) that the rendered file must satisfy.
- `spec.OpVerbs` / `spec.Op` regenerate via `task cue:gen` (no hand-edited generated files).
- `Op.VerbsSet()` / `Op.Kind()` classify `config` like any install verb.
- `Op.StringFields()` (the in-place variable-expansion surface) now includes the config destination AND — only for `config` ops — the `content` body. `write:` bodies stay verbatim bytes (the documented write contract is untouched); `config:` exists precisely for generate-time substitution.

The verb substitution/validation behavior lands in the sdk deploykit emitter (next PR in the wave) and the `charly box validate` per-verb rules + `VerbCatalog` binding (charly PR). This PR is the schema contract they implement against.
