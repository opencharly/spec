# 0.2026288.1242 — feat(schema): an optional skill body, and a candy's .agents/skills trees

## Summary

Leg **L1** of the `.agents/skills` relocation (`opencharly/opencharly#496`, the `agents-skills-relocation` ledger): the **schema surface** that lets a skill's body move out of `charly.yml` into a file, while its node keeps the routing metadata the corpus, the docs link gate and the OCI label need.

**What the contract now says.** A skill is authored at `<tree>/<name>/SKILL.md` (plus `references/<stem>.md`; an `agent`-type node at `<tree>/<name>.md`), where `<tree>` is the owning candy's new `skills:` list — default `.agents/skills`, the Agent-Skills standard location — and `<name>` is the node's `name:`, defaulting to the **node name**.

- `#Candy` gains the optional `skills: [...string]` with non-empty elements: the ONE place the marketplace generator and the docs projection will look for a skill's body.
- `#Skill`'s `name`, `description` and `content` become **optional** — the body and its frontmatter description live in the file. Of the routing metadata, **`family` and `owner` stay required** (which corpus family the skill lands in; the `ai.opencharly.skills` OCI-label association), while **`triggers` and `category` remain optional exactly as they were before this change** (`category` carrying its `development` default) — a trigger contributes an R0 dispatcher row only where an author writes one.
- The version of record is **not** in the file: it is the github ref that fetched the repo (the marketplace refs list's pin, or a consumer's `candy:` list). So the settled Option A needs no new ref grammar and no self-pin.

Every requiredness claim above is read off the **committed** definition, not asserted from intent:

```
$ git show HEAD:schema/skill.cue | sed -n '/^#Skill: close({/,/^})/p' | grep -oE '^\s+[a-z_]+\??:' | tr -d ' \t'
name?: family: owner: description?: content?: type?: model?: tools?: references?: triggers?: category?:
# required = the two entries with no `?`: family, owner
```

**Strictly permissive, so every live entity keeps validating.** The in-line form is untouched: all 355 `skill:` entities in the org still load and the corpus generator still produces today's bytes. The in-line form's removal is the relocation's own final leg (L14) — this leg is the schema half of a producer-first chain whose next steps are the shared reader (`sdk`), the generator (`plugin-marketplace`) and the docs complement.
