# 0.2026269.1640 — feat(resolvedproject): project candy plugin.requires into CandyView

## Summary

Add the **resolved-view receiver** for a candy's authored `plugin.requires:` list — the
`#CandyView.plugin_requires` field, the `spec.CandyReader.GetPluginRequires()` accessor, and a
schema test that fails without the field. This is the **producer leg** of a cross-repo chain
(spec → sdk → charly); it ships the contract, and the two consumer legs named below consume its
tag.

**Why the field is needed (the gap):** `plugin.requires:` was added to `candy.cue` (spec#163) as
the authored declaration of a plugin's inter-plugin dependencies, carried on the wire as
`Capabilities.requires` and consumed by the host's gate. But the resolved-project **view** —
the `CandyView` envelope every consumer reads a candy through (the SAME view `plugin_source` /
`plugin_providers` live in) — had no receiver for it: `#CandyView` is a CLOSED struct with
`plugin_source` + `plugin_providers` and no `plugin_requires`. So a consumer reading a candy's
plugin block off the resolved view could see its providers but **not** its declared dependencies.

This change closes that asymmetry: `#CandyView.plugin_requires?: [...#PluginRequirement]` (the
same `#PluginRequirement` def spec#163 introduced — one shape, no mirror), the matching
`CandyReader.GetPluginRequires()` accessor beside `GetPluginProviders()`, and
`schema/plugin_requires_test.go`.

### Scope, with the exact consumer legs named (producer-first, B6)

This PR is the **spec contract only**. `#CandyView` is CLOSED, so a consumer cannot even compile
against `plugin_requires`/`GetPluginRequires()` until this tag exists — spec must land first. The
two consumers land as their own branches that bump their `spec` pin to this change:

- **sdk** — `opencharly/sdk` branch **`feat/candyview-plugin-requires`**: the projector
  (`loaderkit/scan_candy.go`'s `populateFromYAML` copies `ly.Plugin.Requires` into
  `v.PluginRequires` exactly as it already copies `Source` + `Providers`) plus the adapter
  accessor (`deploykit/spec_candy_adapter.go`'s `GetPluginRequires()`, beside its existing
  `GetPluginProviders()`).
- **charly** — `opencharly/charly` branch **`feat/requires-manifest-consume`**: the host's
  requires gate reads the declared dependencies through the resolved view
  (`candy.GetPluginRequires()`), the reference plugin declares `requires:` in its manifest + Go
  meta, and the disposable R10 bed exercises resolve/connect/cycle/missing-peer live.

Both consume this PR's `spec` tag. This PR does NOT claim to test runtime resolution — its own
gate is the schema + interface contract (below).
