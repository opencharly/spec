# 0.2026242.1115 — ci: add a go job with build, test, gofmt and golangci-lint

## Summary

Second instance of the `go-ci-lint-parity` batch (opencharly/charly#464), after opencharly/charly#486.

This repo had **no Go CI at all** — only `pr-validator.yml` and `tag-on-merge.yml`, neither of which builds, tests or lints the module. The only enforcement was the local `.claude/hooks/pre-commit-gate.sh`, so nothing kept `main` green between commits.

Adds a `go` job: build, test, gofmt, golangci-lint.

## The drift is real, and it recurs

charly#464 measured **11 findings** on this repo's `main` on 2026-08-29. opencharly/spec#68 cleared them. `main` has **2 again today**, introduced by #73:

```
lock/filelock_timeout_test.go:25:15: Error return value of `f.Close` is not checked (errcheck)
lock/filelock_timeout_test.go:30:15: Error return value is not checked (errcheck)
```

That is the whole argument for the gate, observed twice in two days on one repo. And the cost does not land on whoever caused it: because the hook lints the **whole repo** rather than the diff, these two findings would have blocked the next contributor to touch this repo — someone with no connection to #73.

Both are deferred calls in a test whose errors were never meant to be consumed. They are made explicit (`defer func() { _ = f.Close() }()`) rather than silenced with a nolint, so the gate lands green on a tree that is genuinely clean.

## Two deliberate choices

**Pinned by module version, not a third-party action.** `go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.13.2` makes the CI binary the same build the pre-commit hook uses locally. A gate that disagrees with the hook is worse than no gate: it fails people who did everything right. It also means a new upstream release cannot turn `main` red on its own schedule.

**build + test + gofmt alongside the lint**, because this repo had none of them in CI — adding only the lint step would leave a module whose tests nothing runs.

## Rulebook compliance

- **R1 (RCA)** — the gap and its consequence are measured (no Go CI here; 11 findings then, 2 now, both times on a pristine `main`), not asserted.
- **R2 (no deferral)** — the 2 findings the gate exposed are fixed in this PR, not filed for someone else; landing a gate that turns `main` red would be exactly the split R2 forbids.
- **R3 (no duplication)** — uses the repo's existing `.golangci.yml`; no parallel lint configuration.
- **R4 (no workarounds)** — the deferred errors are explicitly discarded at the call, not suppressed with a nolint directive or an exclusion rule.
- **R6 (git safety)** — feature branch, no force-push, no hook bypass.
- **R7 (prove the gate)** — every command the job runs is pasted above with its output, before and after the fix.
