# 0.2026250.709 — feat: add mcp_provide to #Vm and #CheckEnv (P4 substrate-neutral surface)

## Summary

P4 (substrate neutrality) — the schema half of the plan at `plan/charly-mcp-systemd-config.md` §3.10: a `charly` capability works on every substrate; a `vm` entity must be able to declare `mcp_provide` like a box does, and the check env must carry it to the `mcp:` verb for VM/host venues.

Two additive CUE fields + regeneration + tests:

1. **`schema/vm.cue` — `#Vm` gains `mcp_provide`** (after `cloud_init`): a `kind:vm` entity declares its MCP servers (e.g. the systemd-started `charly mcp serve`) exactly like a box does — the P4 substrate-neutral surface. Shape is the existing `#CandyMCPProvide` (name/url/transport) — R3, one canonical def, no duplicated shape.
2. **`schema/checkresult.cue` — `#CheckEnv` gains `mcp_provide`** (after `venue_kind`): the host threads the deployment's `mcp_provide` declarations into the check env so the out-of-process `mcp:` check verb can resolve the endpoint for VM/host venues (no OCI label — the box path reads the baked label; VMs/hosts have none).
3. **`task cue:gen` regenerated `spec/cue_types_gen.go`**: `Vm.MCPProvide []CandyMCPProvide` and `CheckEnv.MCPProvide []CandyMCPProvide` (with the CUE comments carried through). `VmSpec` is an alias of `Vm` (`spec/charly_names.go:26`), so the authored-vm surface gains the field.
4. **`spec/vm_mcp_provide_test.go`** — three gates: (a) schema-level parse — a kind:vm body with `mcp_provide` validates against the compiled `#Vm` (CLOSED, so the accept case fails if the field is reverted) and a missing-`url` entry is rejected (proves the field binds `#CandyMCPProvide`, not a loose passthrough); (b) yaml round trip of a kind:vm body; (c) `CheckEnv` JSON round trip of `mcp_provide`.

No breakage: both fields are optional (`?`), old files parse unchanged; the wire shapes gain an optional key only.
