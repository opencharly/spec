## Change classification

**Non-runtime: schema + library behaviour, no consumer-visible surface for a host
document.** Three facts place the break, and each was read from the artefact rather than
assumed:

1. The host `charly.yml`'s `cache:` section is declared **open** at the document root —
   `schema/node.cue:167` is `cache?: _`, recognized there only so a document carrying it is
   not mis-read as a node named `cache`. So a host document that still carries
   `cache: git: resolved_refs:` / `downloads:` loads exactly as before; the closed def
   `#GitCache` is not what judges it.
2. The client's own load path is tolerant: `refs.load()` unmarshals only
   `bypass`/`latest_tags`/`default_branches` into an anonymous struct, and `refs.save()`
   rebuilds the whole `cache:` node from those three, so the dead keys are dropped on the
   next save with no migration step.
3. The removal is reachable only through the generated Go type
   (`spec.CacheConfig` / `spec.GitCache` lose `ResolvedRefs`/`Downloads`), and a JSON payload
   decoded against that definition would now be rejected by `DecodeGeneratedJSON`'s
   `DisallowUnknownFields`. Measured: no file in `charly` or `sdk` references `CacheConfig`,
   and `refs` uses its own YAML structs — so there is no in-tree consumer to update.

The remaining behavioural change is the one the change is FOR: a warm-up that previously
resolved every ref now stops at its total ceiling and writes the cache once.

**Breaking change + rollback:** there are TWO breaks, and both are named here.
(1) **The generated `spec` type** — the `ResolvedRefs`/`Downloads` fields no longer exist, so a
plugin that decoded `#GitCache` from JSON would now reject those keys.
(2) **A removed exported method** — `func (g *GitClient) ResolveRef(repoURL, ref string)
(string, error)` is deleted from `refs/git_client.go`. Any external caller of that exported API
stops compiling; the sweep below shows no production call site inside this org, and the
primitive `GitResolveRef` — the function that does the work — is NOT removed.
Plus the bounded prefetch, which stops a warm-up at its ceiling instead of resolving every ref. Nothing breaks for a host `charly.yml` (open at the
root) and nothing was migrated or deleted on disk. The rollback is a plain revert of this PR:
the two defs are additive to the schema, a cache file written without them still loads, and
re-adding them restores the previously accepted generated type.
