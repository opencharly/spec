# 0.2026276.1337 — feat(spec): the system-package teardown delta — #Format.present_template + SystemPackagesStep.Installed

## Summary

`charly deploy del` removes the packages a deploy **declared**, not the ones it **installed**, so a teardown asks the package manager to remove packages the venue's base image already provides. This is the contract half of the fix; the tracked issue is **opencharly/charly#771**, and this is part 1 of 3 (part 2 is the `plugin-installstep` delta that computes it at execution time; part 3 is the `charly` leg that supplies the per-format query and runs the bed).

**Root cause, measured** (full RCA table with file:line on the issue): `(*SystemPackagesStep).Reverse()` recorded `Targets: s.Packages` — the DECLARED list — while the install runs with `--needed`, so a base-provided package is SKIPPED at install and still named at teardown. pac then refuses the whole transaction, and `kit.RunReverseOps` logs and continues, so the packages charly *did* install are left behind:

```
:: removing curl breaks dependency 'curl' required by pacman / gettext / libelf / tpm2-tss
:: removing iptables breaks dependency 'libxtables.so=12-64' required by iproute2
error: failed to prepare transaction (could not satisfy dependencies)
reverse: package-remove failed: exit status 1
```

apt/dnf are worse than pac here — `apt-get purge` / `dnf remove` of a base package *succeeds* and cascade-removes its dependents.

**What lands**

- `schema/distro.cue` — `#Format.present_template?: string` (plus the regenerated Go): a command rendered for the format whose stdout lists, one per line, the packages from the rendered set that the venue ALREADY has (already installed or already satisfied). The per-format query belongs in config, not Go: `deploykit.RenderHostPackageCommand`'s documented contract forbids hardcoded dnf/apt/pacman dispatch.
- `spec/install_step_vocab.go` — `SystemPackagesStep.Installed []string`, execution-time state set by the step executor, and `Reverse()` prefers it:
  - `nil` = not determined → fall back to `Packages` (prior behaviour, unchanged for every existing consumer);
  - non-nil and EMPTY = authoritative → **no package-remove op at all** (every declared package was already present);
  - non-empty → exactly that delta is recorded.
- `spec/install_step_vocab_test.go` — `TestSystemPackagesStepReverseInstalledDelta`, covering all four cases (nil / non-empty / empty-non-nil / non-install phase).

**Deliberately NOT on the wire:** `Installed` is not added to `InstallStepView`/`StepFromView` or any other serialized shape. It is execution-time state the executor sets on the step immediately before calling `Reverse()`, not plan data, so it must not travel on the wire.

**No `#SchemaVersion` bump**, deliberately: this is a purely additive optional def, the shape `schema/llm.cue:17` documents as needing no bump ("the same shape as the iso VmSource arm, #DiskLayout, and the desktop kinds (spec PR #74)").
