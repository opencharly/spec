# 0.2026320.840 — feat(schema)!: the resolved twins for candy aliases and volumes

## Summary

**The first step of the split that frees the candy sub-shapes** — and it invents nothing: it applies the precedent that landed the `vm` unit.

```go
// spec/charly_names.go:26-28 — the unit that already did this
// VmSpec is the charly name for the vm entity: the authored #Vm moved into plugin-substrate
VmSpec = ResolvedVm
```

When `vm` moved its authored body into the plugin, `spec` did not lose a decode target. It kept the **resolved** form — `#ResolvedVm`, a `spec`-owned CUE def (`schema/vm.cue:955`) that generates to Go like every other spec shape and that consumers name. So the split is **three-way**, not two:

| shape | what it is | owner |
|---|---|---|
| `#CandyAlias` / `#CandyVolume` | the AUTHORED shapes a user writes | the plugin that owns the body (§3.1) |
| `#CandyAliasValue` / `#CandyVolumeValue` | the wire value the gate validates | the same plugin |
| **`#ResolvedCandyAlias` / `#ResolvedCandyVolume`** | what a consumer DECODES an opaque body into | **`spec`** (§10.2) |

This PR adds the third row for the two shapes the views need first.

**They are written out explicitly, not embedding the authored def** — the reason `#ResolvedVm` gives in its own comment: *"the resolved envelope carries PLAIN post-default scalars, not `#Vm`'s own enum/default machinery."* A volume name's regex and an alias command's non-emptiness are authored-input validation; a decoded body has already passed it. That is also why the twins **cannot drift** from the authored defs: they answer different questions, which is what makes §3.1 and §10.2 satisfiable at once without copying any authored shape.

`TestResolvedCandyTwinsAreTheDecodableWireShapes` pins the property the split depends on, and it is the one no hand-built fixture would catch:

- a value of the **authored** type, marshalled through `json.Marshal`, **decodes into its twin** with the authored values intact — which is exactly what happens at runtime (the plugin validates the authored shape, the host encodes it, a consumer decodes the twin). If the field names ever stopped agreeing, every body would decode to zero values and a fixture-driven suite would still be green;
- and the twins are **distinct types** from the authored defs (`reflect.TypeOf` comparison), because an alias would make the twin the authored def again — and moving the authored def would take the decode target with it, which is the whole barrier this works around.

The generator's no-op half is `TestGenReproducible`.
