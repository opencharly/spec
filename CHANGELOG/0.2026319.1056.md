# 0.2026319.1056 — feat(loader): a kind gate carries its authored and wire shapes apart

## Summary

A kind has **two** shapes, and the gate now carries both:

- the **authored body** the host validates and fills defaults through — `#Vm`, where `autostart: *false | true`;
- the **wire value** a plugin's `InputDef` names — `#VmValue: (#Vm | schema.#DeployValue)`, a union that also admits the substrate arm, where `autostart!` is required.

`KindGate` carried one name for both. The fill therefore resolved the **union** for an authored body, and a perfectly valid authored vm was refused for a field the *other* arm requires:

```
expected CUE to ACCEPT "vm libvirt modeled field accepted", but it failed:
  t.yml:vm: autostart: field is required but not present
```

`KindGate` now carries `WireDef` beside `Def`; an empty `WireDef` means the two shapes are the same def, so every existing gate is unchanged.

This is `opencharly/opencharly#1048`'s root fix, landed producer-first: the contract declares the split, the SDK resolves `Def` (it already does), and the host fills `Def` with the authored body and `WireDef` with the plugin's declared input.

## Change classification

Kind: `spec.KindGate` gains `WireDef`. Additive and back-compatible: an empty `WireDef` means the authored and wire shape are the same def, which is what every existing gate already assumed.

**Breaking change + rollback:** none — the field is optional and omitted from the wire when empty (`omitempty`), so a host and a plugin that never set it behave exactly as before. Rolling back deletes the field and the test that pins it.
