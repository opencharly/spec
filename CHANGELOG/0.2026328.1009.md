# 0.2026328.1009 — refactor(refs)!: route the per-host config through ONE reader/writer (spec/perhost)

## Summary

The per-host config (`~/.config/charly/charly.yml`) is a SHARED document — deploys, the git-ref
cache, the ledger and the system info are written into it by different charly commands that can run
concurrently. Four independent copies of "lock, read the yaml.Node, set my key, marshal,
tempfile+rename" had grown, and the copies have already destroyed real data on a host
(2026-11-24): one cleared a section by DELETING the whole file, and one wrote a stale in-memory
value over a value another process had just changed.

**`spec/perhost` is that contract stated once — the cache writer's own approach, extracted:**

- ONE advisory lock, `<file>.lock`, bounded at 10 s (a stuck holder fails fast and is named);
- the read happens **inside** the lock — never a caller's snapshot;
- the mutation touches **only the keys it owns**, so every other section survives;
- the write is a tempfile in the same directory + `rename`, mode 0600 (no torn reads);
- a corrupt file is an **error** and the mutation never runs — the bytes stay for recovery.

`refs` (load, save, ClearCache) now runs through it; the two data-loss fixes already on main become
consequences of the shared writer rather than special cases.

**This PR re-lands a commit the previous merge missed.** opencharly/spec#434 squashed only the
first commit of its branch — `git ls-tree -r v0.2026328.920 | grep perhost` → 0. The auto-merge
fired on the earlier head before the second push was validated, and a `MERGED` signal says a PR
landed, not what it carried. This branch is that commit cherry-picked onto current `main`.

A defect the migration introduced and the suite caught: the helpers `save()` called took `g.mu`,
but `save()` must stay LOCK-FREE — `LatestTag`/`DefaultBranch` and the cache tests call it while
holding `g.mu`, and `sync.Mutex` is not reentrant, so `TestGitClientCacheAndPersist` hung for the
full 600 s package timeout. The helpers are lock-free; a content-only test could never have seen it.

Test accounting, stated exactly:

- **NEW in this PR** — `perhost`: every other section preserved; a corrupt file refused with its
  bytes untouched; **24 concurrent `Update` callers each keeping their own key**; and
  `Set` replacing a non-mapping intermediate instead of emitting a duplicate key. `refs`:
  `TestSaveIsCallableWhileHoldingMu` (asserts `save()` RETURNS) and
  `TestConcurrentSaveDoesNotResurrectAClearedBypass` (the bypass lost-update guard).
- **PRE-EXISTING on main** (landed in #434, kept and re-run here) — the `ClearCache` preservation
  guard, `TestClearCachePreservesTheDeployConfig`, and the corrected `TestGitClientCacheSurface`.

Review-round fixes carried by this branch: `cacheLockPath()` — dead once `save()` moved onto
`perhost.Update` — is deleted (`grep -rn cacheLockPath` → no output), so the shared writer's
`<path>.lock` is the ONE lock path for this file; `perhost.Set` replaces a non-mapping intermediate
rather than appending a duplicate key, and zeroes `Style`/`Anchor` on a node it replaces; `save()`
and `ClearCache()` now share ONE `persistCache()` write (the round-2 R2 finding), with
`warmUpSaveFn()` inside it so every write — ClearCache's included — is counted; and `SetBypass`
releases `bypassOwned` after the persisting write, so a long-lived client cannot re-assert a stale
flag over a later operator clear. The round's missed-control RCA is posted as a PR comment.
