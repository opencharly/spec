### The candy, and what it is not

`spec-skill-shelf` is a **CONCEPT candy**: `plan:` is a `true` no-op plus a `true` check, it ships
no install content, and it composes no box. Its only job is to own routing metadata:

```yaml
spec-skill-shelf:
  candy: { … }
disposable-skill:
  skill:
    name: disposable
    family: internals
    owner: spec-skill-shelf
    triggers: [ "Disposable-flag semantics / `disposable: true` authorization / …" ]
```

Routing-only: `name`/`family`/`owner` plus the `triggers:` that generate the `DISPATCHER.md` row.
**No inline `description:`/`content:`** — the shape `pod-ollama#7` and `#612` both used. The prose is
the file, and an inline body that disagrees with its file is a hard error in the marketplace
generator, so nothing is copied back over a node. `family` stays `internals`, so every
`/charly-internals:<skill>` address and the corpus path `<family>/skills/<name>/SKILL.md` are
unchanged.

The manifest header line that read `spec owns NO candies/boxes, so there is no discover:` was true
before this change and false after it. It is corrected in the same commit to `spec ships NO image
and composes NO box … plus ONE CONCEPT candy` — left to rot it would be exactly the falsified-header
defect #612 had to repair. The `discover:` claim is still true and still absent, because this PR
does not give `spec` an image.

**How the name respects the class rule.** "Repo classes and naming" says bare names are for
core/contract repos — `spec` **is** one, and this PR does not touch its name. What it adds is a
*carrier candy inside a repo that already holds code*, which that same section explicitly
sanctions. The name is chosen so it cannot be read as a product family: a family is a
`layer-<family>` repo, never a bare name, and product candies are bare nouns or
`<noun>-layer/-full/-base` — whereas `spec-skill-shelf` states what it *holds* (this repo's skill
shelf) and carries the repo's own class in its prefix. It is deliberately **not** the retired
`*-skills` carrier-**repo** shape either: that class is a repo whose only content is prose, and this
is one node in a repo of CUE schema, generated Go and a proto wire contract.

**No OCI label entry.** The candy composes nothing, so there is no image for `CollectSkills` to
project onto — measured, not asserted (`[cwd = this session's spec worktree]`):

