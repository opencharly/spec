# 0.2026241.2320 — feat(vm): add the iso VmSource arm for unattended installs

## Summary

Adds a sixth `#VmSource` arm, `iso`, so charly can install a distro that ships **only an
installer medium** — no cloud image, no bootstrap tarball. Omarchy is the first such
target: it publishes `omarchy-<ver>.iso` and nothing else, so today it has no VM path at
all.

The arm boots the installer against an initially blank disk and lets the installer
partition and install. The split of responsibility is the one `init:`/`service:` already
established:

- **the vm entity owns the DATA** — `#VmInstaller`: `username`, `password` ⊻
  `password_hash`, `disk`, `hostname`, `timezone`, `locale`, `keyboard`, `encrypt`,
  `ssh_authorized_key[]`, `defer_provisioning`, plus a typed-open `answer:` map for
  per-distro extras;
- **the distro owns the FORMAT** — `#DistroInstaller`: the answers volume's `volume_id`
  and `fs`, the `file[]` list of Go templates with a `when:` guard, an optional
  `boot_arg`, and `done: poweroff | marker`.

That split is deliberate. archinstall JSON, kickstart, preseed, Subiquity autoinstall and
AutoYaST are five real formats, each keyed by distro and by nothing else — so nothing
infers a format from a URL, an ISO name or a `base_user`. `#InstallerSeedContext` is what
those templates render against; the plaintext password never reaches it (the caller
crypt()s first), so no plaintext lands on the answers volume, in a log, or in a temp file.

`distro` is CUE-required on this arm, following `bootstrap` rather than `cloud_image`:
the answer-file format lives on the distro, so an absent value is a hard nil at render
time with no plausible default to trade against.

Purely additive — a new arm in a closed disjunction and new optional defs invalidate no
existing config, so **no migration entry and no `#SchemaVersion` bump**. Nothing consumes
the arm yet; `plugin-substrate`'s `validateSourceDistro` and `plugin-vm`'s build path
follow in their own repos, which is the contract-first landing order this repo already
uses.

## How tested

**The arm was verified working before the schema was written.** The real
`omarchy-4.0.1.iso` (sha256 verified) was booted under QEMU/OVMF with a `cidata` answers
volume built exactly as `#DistroInstaller` describes. It installed **fully unattended**,
rebooted itself, and came up as `Omarchy 7.1.9-arch1-2`:

```
$ genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
$ qemu-system-x86_64 -enable-kvm -m 8192 -smp 4 -machine q35 \
    -drive if=pflash,...OVMF_CODE.4m.fd -drive if=pflash,file=OVMF_VARS.fd \
    -drive file=disk.qcow2,if=virtio -drive file=omarchy-4.0.1.iso,media=cdrom \
    -drive file=cidata.iso,media=cdrom -boot order=cd ...

$ ssh -i spike_key user@127.0.0.1 -p 2299 'id; uname -r'
uid=1000(user) gid=1000(user) groups=1000(user),992(input),998(wheel)
7.1.9-arch1-2
```

Every field the schema models was consumed by the real installer: SSH worked from
`ssh_authorized_key` alone (proving the seeded `authorized_keys` enabled sshd and opened
the firewall), `git config user.name/user.email` returned the values from
`full_name`/`email`, `hostname` and `sudo` came from the answers, and the resulting
layout was `/dev/vda2[/@] btrfs subvol=/@` with the ESP at `/boot` — matching
`#DistroInstaller`'s `done: poweroff` flow.

**Schema tests** — `schema/vm_iso_source_test.go`, corpus **and** teeth:

```
$ go test -count=1 ./schema/ -run 'Iso|Installer|VmSource' -v
--- PASS: TestVmSourceAcceptsTheIsoArm
--- PASS: TestVmSourceAcceptsDeferredProvisioning
--- PASS: TestVmSourceIsoRejectsCrossBranchFields

```

The corpus case is the exact source literal of the VM installed above, not a
hypothetical. The teeth reject `rootfs`, `root_size`, `base_user`, `builder`,
`builder_image` and `box` on this arm (each belongs to another source kind and would be
silently ignored by the iso build path), an unknown `distro`, and a malformed
`volume_id`.

`TestVmSourceIsoRequiresDistroLikeBootstrap` is written as **parity with the bootstrap
arm** rather than against a bare validation mode: a required-but-absent field is
*incomplete*, not conflicting, so it surfaces only under a concreteness check. The test
asserts bootstrap rejects it too, and fails loudly if that premise ever goes stale.

## Rulebook compliance

- **R3 — no duplication.** The answer-file format is declared once, on the distro. No
  second copy in Go, and nothing infers it from a URL or an ISO name — the same rule
  `distro_vocab.cue`'s header states for every distro trait.
- **R4 — no workarounds.** `done: poweroff | marker` is a process-exit or guest-agent
  **poll**, never a sleep. Generated Go comes from `task cue:gen`, never hand-edited;
  the one hand-written file (`spec/union_types.go`) is the documented exception for the
  flat discriminated struct, and it is updated in the same commit as the CUE.
- **R5 — no legacy left behind.** Purely additive; nothing is deprecated.
- **R6 — git safety.** Feature branch, PR-only, no force-push, no direct push to `main`,
  no hook bypass.
- **R10 — proof from the final tree.** The gate above ran on the committed tree, and the
  behaviour it encodes was proven on a real unattended install before the schema existed.
