# 0.2026241.2128 — fix(lint): clear the 11 golangci-lint failures blocking every commit

## Summary

`main` is red against this repo's own pre-commit gate, so **no commit can land in
`spec` at all** — the failures are unrelated to any one change. This clears them.

**Root cause (R1).** `spec` has no CI lint workflow — `.github/workflows/` holds only
`pr-validator.yml` and `tag-on-merge.yml`. The local pre-commit gate
(`.claude/hooks/pre-commit-gate.sh`) runs `golangci-lint` repo-wide and is therefore the
*sole* enforcement, with nothing keeping `main` green between commits. Verified
pre-existing: `gofmt -l exec/deploy_executor_nested.go refs/git.go` lists both files on a
pristine `origin/main` checkout.

The root cause is **org-wide, not repo-local** — no opencharly repo runs `golangci-lint`
in CI (`grep -rl golangci --include='*.yml' */.github/workflows/` matches nothing across
the umbrella). It is routed to the named thematic batch **`go-ci-lint-parity`**,
opencharly/charly#464, which covers the shared reusable workflow, the per-repo dispatcher,
and the drift sweep. It is deliberately not done here: adding the org's first CI lint
workflow to a single repo would fork harness config, which
`scripts/check-harness-parity.sh` exists to prevent.

All 11 fixes are mechanical, with **no behaviour change**:

- **gofmt (2)** — a missing blank line before a trailing comment in
  `exec/deploy_executor_nested.go` and `refs/git.go`.
- **errcheck (7)** — best-effort cleanup calls now discard explicitly: `json.Unmarshal`
  in two cache tests, `defer unlock()`, and the `tmp.Close` / `os.Remove` rollback path
  in `refs/git_client.go`.
- **unparam (2)** — `writeImageCache` and `writeImageLabelsCache` returned an `error`
  that was **always nil**. Each has exactly one non-test caller, and both already
  discarded it with `_ =`. Dropped the return and updated the four test call sites that
  asserted on it.
