# 0.2026295.1243 — feat(schema)!: engine word containerd + krun VM backend

## Summary

The spec-repo producer leg of the containerd engine / krun VM-backend cutover. This PR changes only `opencharly/spec`, but it includes that repo's in-repo Go consumers of the schema (the capability table, the `start_plan` op, the exec jump/readiness/builder paths, and the generation pipeline). The plugin rename, deploy/engine code, `charly migrate` rewrite, namespace resolver, candies and beds are the expected consumer legs after this merge and tag.

- **`#EngineName` is now `"podman" | "docker" | "containerd"`.** The engine word `nerdctl` is deleted (R5, no alias, no dual path). `containerd` means "containerd driven through the nerdctl CLI", rootful **or** rootless; `nerdctl` survives only as the binary.
- **The `containerd` capability row is data-complete:** `binary: nerdctl`, run mode `systemd-unit`, `supports_rootless` **and** `supports_rootful`, `address`, `namespace`, `privilege_prefix`, `substrates: ["pod"]`, and `runtime_handlers: ["crun","krun","runc","nvidia"]`. The workload user is split into `workload_user_rootless` / `workload_user_rootful`, so the capability no longer assumes rootless; `start_plan` selects by `rootful`, emits `--runtime` from the request, and refuses a handler the engine does not declare.
- **`#Vm.backend` and `#VmDeployState.backend`** gain `krun` through one `#VmBackend` def (`auto | libvirt | qemu | krun`).
- **`#Vm.krun`** carries `network`, `kernel`, `nested_virt`, `gpu`, `gpu_flags`, `ram_headroom_mib`. The block is optional; its fields are **required-with-default**, so `krun: {}` materializes the measured `962/256/tsi/stock/off/false` in CUE itself. With `backend: krun`, `source` must be an OCI-image arm (`container_disk` / `bootc`) and the libvirt-only fields (`libvirt:`, `autostart`, `firmware`, `machine`, `cloud_init`) are rejected with **field-named** CUE errors.
- **The deploy entity** gains `backend?` and `namespace?` (default resolution stays in code: deploy > config > `default`); `engine?` is extended through `#EngineName`.
- **The hosting rule is data:** `#EngineCapability.substrates` says which kinds an engine may host; the new `#DeployTraits.selectors` says which deploy selectors a substrate accepts (`pod` → `engine`, `vm` → `backend`). A loader can reject `engine:` on a vm and `backend:` on a pod without a substrate-word literal.
- **`#EngineBinaries`** is the CUE-owned word→binary mapping (`containerd` → `nerdctl`), read by the capability table, the exec jump, the readiness probe, `checkhost`, `container.IsHostNetworked`, and `BuilderRun`. It lives in the contract module because `spec/container` imports `spec/exec`, so `exec` cannot import `container` without a cycle.
- **Regenerated** `spec/cue_types_gen.go` and `spec/vocab_gen.go`; a second `charly task cue-gen` is a **no-op**.
