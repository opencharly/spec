# 0.2026276.1636 — feat(schema): carry the engine's approval/input envelope on the workflow IR

## Summary

`#WorkflowApproval` is the IR's *normalized* form of an approval gate, but an **engine computes strictly more than the authored def could carry**. plugin-lobster's `approvalRequest` resolves the SHORT approval id, the items/preview a human is shown, and the approver-identity policy the gate enforces. Without that id in the reply, `#WorkflowResumeRequest.id` has nothing to be resolved against — **the resume face was undiscoverable**. `#WorkflowInputRequest` had the same gap on the *subject* the gate is about: the engine's own resolved stdin/previous-output value.

This adds **only optional, IR-only** fields, so it is **not** an authored wire-key change:

| file | |
|---|---|
| `schema/workflow.cue` | `#WorkflowApproval` gains `approval_id` / `items` / `preview` / `initiated_by` / `required_approver` / `require_different_approver`; `#WorkflowInputRequest` gains `subject` — all optional |
| `spec/cue_types_gen.go` | regenerated (never hand-edited) |
| `spec/workflow_envelope_test.go` | NEW — the closedness corpus + the "authored def did not grow the engine fields" pin |

**The authored `#PipelineApproval` keeps its terse surface, and that is pinned structurally, not by a comment.** Without a test, a later "convenience" mirror of these engine fields onto the authored def would silently become a format change. The corpus's last case holds the authored def to its terse shape, so such a mirror **fails the test** instead of shipping.

**No `#SchemaVersion` bump and no plugin-migrate entry**, deliberately: nothing an author writes changes meaning and no existing wire byte moves — the `schema-change-recipe` case.
