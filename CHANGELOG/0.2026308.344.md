# 0.2026308.344 — fix(spec): keep a folded deploy-level member's bare address in the projection

## Summary

`UnifiedFile.Deploys` prefixed **every** namespace-scoped key. A deploy-level member is a top-level addressable entry addressed by its **bare** name — the Cutover C law `sdk/loaderkit.FoldMembers` implements — and that bare address is global by construction, so the namespace prefix must not apply to a folded member (`MemberOf != ""`). Its `from:` cross-ref *is* namespace-local and stays root-qualified.

This is the **contract half** of the producer-first pair for opencharly/charly#1083; the SDK half (the namespace-recursing fold) is opencharly/sdk#483 and lands after this contract change.

Without it, a namespace-imported bed's member projects only as `charly.check-sidecar-pod-ephvm`, while `sdk/deploykit/deploy_members.go:98` dispatches the bare `check-sidecar-pod-ephvm`. `spec/deploy.ResolveNodePath` finds no node, `ClassifyNodeTarget` (`spec/deploy/deploy_ops.go:98`) defaults the substrate to `pod`, and the dispatch refuses a substrate the project composes — after the member's VM has already been created.
