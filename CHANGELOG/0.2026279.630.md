# 0.2026279.630 — fix(schema): the marketplace version stamp is optional, not required

## Summary of changes

The org-wide cutover (*"chore(schema): drop the retired config version: stamp"*) removed the
`version:` stamp from every `marketplace:` entity, because the marketplace versions by commit SHA
— `marketplace/README.md` states it plainly:

> *"No `version` fields anywhere: plugins version by the marketplace commit SHA, so every corpus
> update is picked up on `/plugin marketplace update`."*

**That cutover never updated the schema.** `#Marketplace.version` stayed **required**, so the one
repo carrying a `marketplace:` entity fails its own gate:

```
node "marketplace": plugin kind:marketplace: plugin_input fails
#MarketplaceInput: #MarketplaceInput.version: incomplete value =~"^[0-9]+[.][0-9]+[.][0-9]+$"
```

This makes it optional — matching `#MarketplaceFamily.version?`, which this same file **already**
treats as optional. A legacy config that still carries a stamp keeps loading; the emitted
manifests already omit it via `omitempty`, so commit-SHA versioning is restored end to end.

**Three files (two commits), schema-owned (SDD):**

- `schema/marketplace.cue` — `version` → `version?` on `#Marketplace`, with the reason recorded
  in-place so it is not re-required by a future reader.
- `spec/cue_types_gen.go` — **regenerated** by `charly task cue-gen`, never hand-edited. The
  `Marketplace.Version` tag goes `json:"version"` → `json:"version,omitempty"`, now identical to
  `MarketplaceFamily.Version`.

- `spec/marketplace_config_test.go` — **new coverage** that FAILS on the pre-change schema:
  a version-less body must validate (the new behaviour), a legacy body carrying a CalVer must
  still validate (back-compat), and a malformed version must still be rejected (the CalVer
  pattern survives). `cue.Concrete(true)` is load-bearing: `Concrete(false)` PERMITS incomplete
  values, so a missing required field would pass and the test would be a mere compile check.

**Closes / relates to:** unblocks opencharly/marketplace#422 and opencharly/pod-charly-hooks#12.
Sibling leg: opencharly/plugin-harness-kind (the loader's self-contained `#MarketplaceInput`).

**Breaking change + rollback:** none — a required field becomes optional, so every config that
validated before still validates. Rollback is a revert.
