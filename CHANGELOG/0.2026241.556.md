# 0.2026241.556 — fix(exec): pass the container's OCI-spec user/HOME explicitly to podman/docker exec (#149)

## Summary

Fixes opencharly/charly#149 (F-EXEC-HOME): a container created during a concurrent bed window can resolve a broken exec session env — `uid=1000(user) gid=0(root)` with `HOME` empty — even though its OCI spec carries `uid/gid 1000/1000` + `HOME=/home/user`. The exec chain now reads the running container's `.Config.User` + `.Config.Env` (HOME) once at chain construction and passes them as explicit `--user` / `--env HOME=` on every podman/docker exec hop, making the session env deterministic and immune to the engine's exec user/HOME resolution race.

Changes:
- `NestedJump` gains `User`/`Home` fields; `wrapWithJump` + `StartProcess` emit `--user`/`--env HOME=` when set.
- `ContainerChainFromDescriptor` + `AppendHopForFlatPath` fill them from the container's OCI spec (best-effort; an unreadable container falls back to the engine's own resolution — the pre-fix behavior).
- New tests: `TestWrapWithJump_PodmanExplicitUserHome` + `TestParseContainerUserHome`.

```
$ go run .   # ContainerChainFromDescriptor + StartProcess on a running container
jump.User="1000:1000" jump.Home="/home/user"
emitted argv: []string{"podman", "exec", "-i", "--user", "1000:1000", "--env", "HOME=/home/user", "charly-fix149-test", "sh", "-c", "id"}
```

The emitted argv carries the explicit `--user 1000:1000 --env HOME=/home/user`, and the live exec resolves `uid=1000 gid=1000 HOME=/home/user`.
