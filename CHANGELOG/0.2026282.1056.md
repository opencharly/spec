# 0.2026282.1056 — fix(schema): make the provider-class pattern structural so the class rule is reachable

## Summary

**Operator-decided change** (on `opencharly/plugin-box#29`): make the provider-class pattern structural so the closed-vocabulary rule is **reachable**.

`#ProviderClassPattern` derived from `#ProviderClassNames`:

```cue
#ProviderClassPattern: "^(" + strings.Join(#ProviderClassNames, "|") + "):[a-z0-9][a-z0-9_-]*$" @go(-)
```

**So an undeclared class was rejected BY CONSTRUCTION as malformed**, and the Go rule that names the class and the set - the rule an existing bed step asserts - **could never be reached for any undeclared class.** Measured:

```
$ charly box validate      # fixture: providers: [zzznotaclass:lobster]
candy "x": plugin capability "zzznotaclass:lobster" is malformed (want <class>:<word>)
                           ^ a pattern message, where the step expects UNKNOWN PROVIDER CLASS
```

Now:

```cue
#ProviderClassPattern: "^[a-z][a-z0-9-]*:[a-z0-9][a-z0-9_-]*$" @go(-)
```

**The ownership is split explicitly: the pattern owns SYNTAX, the Go rule owns the VOCABULARY.** `#ProviderClassNames` is **unchanged** and stays the ONE source for `spec.ProviderClasses` (charly's `providerClasses`, plugin-box's `validPluginClasses`), so nothing generated from the list moves.

**Two TEST files move with it, and they are the strictness witnesses the change relocates:**

- **`schema/plugin_requires_test.go`** — the malformed-rejection list **drops** `plugin_requires: [{capability: "bogus:x"}]`, because that class is *well-formed*; the genuinely malformed cases (an empty word, a bad source ref) stay.
- **`schema/plugin_test.go`** — the case `{"an unknown class is rejected", …, false}` is **flipped** to `{"a well-formed but undeclared class is accepted by the CUE (Go rule rejects it)", …, true}`.

*Both are the CUE gate's strictness assertions moving to the Go rule that can actually name the class and the set — the vocabulary witness is not deleted, it changes owner.*

**Prose moved with the line**, because the line makes two comments false: the note above `#ProviderClassNames` explained a drift-guard this change **retires** (a reader must not find a guard silently removed), and `#PluginCapability`'s comment claimed the class set is enforced **there**.

**The composition is preserved:** `#PluginCapabilityPattern: #ProviderClassPattern + "|" + #CommandParentPattern` still holds, because the structural form is anchored (`$`) and cannot swallow the three-segment `command:<word>:<parent>` form.
