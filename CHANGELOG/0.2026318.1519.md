# 0.2026318.1519 — feat(vm): re-export the eight shared vocabulary lists publicly

## Summary

`opencharly/spec#304` unit 8 (`vm`), leg 1 — the **contract side** of the split, on the operator's ruling that the shared vocabulary becomes public.

**Measured first, and it changed the plan.** The record's split had the plugin take the seven non-keeper defs (`#Vm`, `#VmBackend`, `#VmBackendName`, `#VmChecksum`, `#VmInstaller`, `#VmKeyInjection`, `#VmCharlyInstall`). Partitioning every def block and intersecting the `_<word>` references showed those seven cite **eight private vocabulary words**, and **all eight are also cited by the defs the resolve envelope pins in the contract** — `#VmSource`, `#VmNetwork`, `#VmSsh`, `#VmCloudInit`, the sixty `#Libvirt*`, `#VmKrun`, `#VmSnapshot`. A plugin's CUE module imports only the contract, and a private def cannot cross that boundary, so the body could not move while the keepers stay.

**The surgical form: eight public re-exports.** Each is a one-line pointer at the unchanged private derivation:

```cue
#VmBackendNameWord: _vmBackendNameWord
#VmBackendWord:     _backendWord
#VmMachineWord:     _machineWord
#VmCloudInitWord:   _cloudInitWord
#VmSmbiosWord:      _smbiosWord
#VmStrategyWord:    _strategyWord
#VmFirmwareWord:    _vmFirmwareWord
#VmKindWord:        _vmKindWord
```

**Why aliases rather than renames.** A rename would have moved the private defs into the public namespace and broken the S3 convention the vocabulary tests enforce (every table derives its own `_<x>Word`). Measured: renaming made `TestEveryTableDerivesItsWordList`, `TestEveryTableIsCitedAndEveryCitationResolves` and `TestInjectedRowReachesTheDerivedList` fail on the fixture's own references. The alias keeps the S3 shape intact — the tables and derivations are untouched — and adds only what a sibling needs.

**The next leg** is `plugin-substrate`'s body: the seven defs + the twin, citing `schema.#VmSource`, `schema.#VmSsh`, `schema.#VmCloudInit`, `schema.#LibvirtDomain` and these eight words.

### The re-exports, pinned (round 1's block)

The aliases had no test that would fail without them — the S3 tests exercise the private *tables* and pass unchanged, and `TestGenReproducible` only compares the committed Go to the generated CUE. `TestVmVocabularyReExports` resolves each public name and decodes it to a non-empty string list, so a removed or misspelled alias fails the lookup, and a pointer at the WRONG list fails the membership check — each name's list must carry one word only its own table has. Planted:

```console
$ go test -count=1 -run TestVmVocabularyReExports -v ./schema
=== RUN   TestVmVocabularyReExports
--- PASS: TestVmVocabularyReExports (0.06s)

$ # plant: the line `#VmKindWord: _vmKindWord` deleted, and separately aimed at _machineWord
--- FAIL: TestVmVocabularyReExports (0.06s)
    vm_vocab_reexports_test.go:38: #VmKindWord does not resolve in the shipped schema — a sibling plugin cites it, so it must

$ # plant the WRONG pointer instead: #VmKindWord: _machineWord
--- FAIL: TestVmVocabularyReExports (0.08s)
    vm_vocab_reexports_test.go:49: #VmKindWord = [q35 virt i440fx pc] — its own list must contain "container_disk", so the alias points at the RIGHT table

$ # restored byte-identical; suite green again
```

The private derivations cannot be compared by path (hidden labels are not addressable), so the test pins the surface the sibling actually cites rather than an unaddressable value.
