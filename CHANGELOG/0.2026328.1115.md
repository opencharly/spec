# 0.2026328.1115 — feat(perhost): split Update into the shared Lock and the lock-held Apply

## Summary

opencharly/spec#435 made `spec/perhost` the ONE reader/writer of the per-host
`charly.yml` and moved the git-ref cache onto it. One writer could not follow: the typed
deploy-overlay cycle (`deploykit.MutateDeployConfig`) has to hold the lock across a
**typed** read-modify-write — the caller's mutation runs against a freshly re-read
`*DeployConfig`, and `charly deploy reset` decides save-versus-remove under the same hold.
Neither can be expressed as one `perhost.Update`, so both re-derived the lock themselves:

- `deploykit/deploy_config_cycle.go` acquired `kit.AcquireFileLockWithin(path+".lock", true,
  deployConfigLockWait)` with its own `deployConfigLockWait = 10 * time.Second` — a copy of
  `perhost.LockWait` and a second statement of the lock path;
- `deploykit.SaveDeployConfig` re-implemented the whole document mechanics (read the file,
  set keys, marshal, tempfile, chmod, rename) because it is called *inside* that cycle and
  must not take the lock again.

This PR splits `perhost.Update` into the two halves it is already made of, and exports both:

| Function | Takes the lock | Does |
|---|---|---|
| `perhost.Lock(path)` | — | acquires `<path>.lock`, bounded by `LockWait` (the ONE definition of the lock path and bound) |
| `perhost.Apply(path, mutate)` | **no — the caller holds it** | read the CURRENT file, mutate its root, marshal, atomic replace |
| `perhost.Update(path, mutate)` | yes | `Lock` + `Apply`; unchanged behaviour |

`Apply` must not re-acquire: `flock` is per-open-file-description, so a second acquire inside
the same process waits for the first and fails at `LockWait`. That is exactly the trap the
next SDK change walks into (routing `SaveDeployConfig` and the cycle through these two), so
it is pinned here rather than in the consumer: `perhost_lock_test.go` proves that `Apply`
under a held `Lock` **writes and returns inside 5 s**, that an `Update` started while `Lock`
is held **cannot complete** and completes once it is released (i.e. the two share ONE lock),
and that a nil `mutate` is refused by both.

This closes opencharly/spec#436. The consumer change (SDK: `SaveDeployConfig` →
`perhost.Apply`, `AcquireDeployConfigLock` → `perhost.Lock`, the duplicated constant deleted,
plus a cross-writer concurrency test) is opencharly/sdk#631.
