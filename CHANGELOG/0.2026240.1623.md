# 0.2026240.1623 — feat(service): carry the portable lifecycle fields into the render context

## Summary

The consumer half of **#58**, and the second leg of batch **B2**.

#58 made `type`, `requires`, `restart_sec`, `watchdog_sec` and `unit_options` authorable on a
`#CandyService`. But `BuildServiceRenderContext` — the pure `ServiceEntry` → render-context
projection **every** init template renders against — dropped them, so nothing could reach a template.
The schema said yes and the renderer never saw it.

They are now carried verbatim, like the start hooks and for the same reason: each is an init-level
directive value, not a path to expand or an ordering list to merge.

## How tested

### Coverage that fails without the change

```
$ git stash && go test -count=1 ./spec/ -run TestBuildServiceRenderContextCarriesPortableFields
--- FAIL: TestBuildServiceRenderContextCarriesPortableFields (0.00s)
    Type = "", want notify — systemd Type= is unreachable
    Requires = [], want both entries — a hard dependency is unreachable
    RestartSec = "", want 5s
```

Two tests, and the second is the one that makes "purely additive" checkable rather than merely
claimed:

- **The fields survive the projection**, including `unit_options`' **list** form. systemd needs that
  for repeatable directives such as `RuntimeDirectory=`; collapsing it to a scalar would emit one
  unusable value instead of two lines, so the element type is asserted, not just the key.
- **An entry setting none of them leaves the context zero**, so an existing candy renders
  byte-identically. Without this, "additive" would rest on inspection.

## Not covered — what still makes these fields inert

**`plugin-init` + `charly`**: the templates. systemd needs `Type=`, `Requires=`, `RestartSec=`,
`WatchdogSec=` and a range over `unit_options.systemd`; OpenRC needs `need` in its `depend()` block,
`--respawn-delay` and `--healthcheck-timer`. Until that lands, these fields are authorable, carried,
and rendered nowhere — which is exactly why this PR claims nothing about emitted units.

**B2's third item, `wait_for:`**, remains its own unit, as set out in #58: nine hand-rolled
`while [ ! -e "$SOCKET" ]` loops exist today, and the honest gate for replacing them is deleting that
duplication with the affected beds staying green.
