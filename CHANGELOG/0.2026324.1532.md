# 0.2026324.1532 — feat(hostenv): resolve paths from the XDG base directory variables

## Summary

Path resolution now follows the **XDG Base Directory Specification**, and the XDG bases are
resolved in exactly one place.

- **`storeroot.XDG()` — the ONE base resolution.** It returns the five bases (`Data`, `Config`,
  `Cache`, `State`, `Runtime`), applying the specification's Unix defaults and its rule that a
  non-absolute value is invalid and MUST be ignored. Its error fires only when a base had to
  fall back to a RELATIVE default because `$HOME` was unavailable; an absolute variable
  resolves without `$HOME`, exactly as the previous `os.UserConfigDir`/`os.UserCacheDir`/raw-env
  reads did. `Dir` and `CacheDir` build charly's four roots from it (`CHARLY_CACHE_DIR` is
  unchanged), and `hostenv.ExpandHostHome` expands an operator-authored `$XDG_*` token from the
  same values. The runtime base is one decision: `XDG_RUNTIME_DIR` when absolute, otherwise the
  D-STORE-1 state base — the same value `Dir(RootRuntime)` uses. An unresolved base (the
  variable unset or relative while `$HOME` is unavailable) is left as a literal token rather
  than substituted with a relative path.
- **`hostenv.ExpandHostHome`** expands `$XDG_DATA_HOME`, `$XDG_CONFIG_HOME`, `$XDG_CACHE_HOME`,
  `$XDG_STATE_HOME` and `$XDG_RUNTIME_DIR` (both `$VAR` and `${VAR}`) alongside `~`, `$HOME`
  and `${HOME}`.
- **`ResolveVolumesPath` / `ResolveEncryptedStoragePath`** default to
  `$XDG_DATA_HOME/charly/{volumes,encrypted}` instead of a hardcoded `~/.local/share`; the
  override and config-file precedence is unchanged and expanded the same way. An absolute
  data variable answers without `$HOME`.
- **Tests.** `storeroot/xdg_test.go` pins every base, the defaults, the relative-value rule,
  the error contract, the `Dir`/`CacheDir` rewiring and the runtime fallback;
  `hostenv/xdg_paths_test.go` pins the expansion, the defaults, the relative rule, the
  volume/encrypted precedence and both resolvers on a `$HOME`-less host.

What this makes possible for the deployments: a bind-backed volume host written as
`$XDG_DATA_HOME/charly/models/<server>` or `$XDG_DATA_HOME/charly/volumes/<deploy>/<volume>`
moves with a relocated XDG data base on the next `charly config`, instead of pinning
`~/.local/share` in the authored config.

**Not changed:** the four roots' names and the cache semantics. `CHARLY_CACHE_DIR` still
relocates only the cache root, the runtime root still falls back to the state root when
`XDG_RUNTIME_DIR` is absent (D-STORE-1), and the content-addressed store is still the only
cache (D-STORE-3).
