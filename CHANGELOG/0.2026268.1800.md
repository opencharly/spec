# 0.2026268.1800 — feat(spec): per-invocation RunEnv — retire bed os.Setenv isolation

## Summary of changes

Retire the check-bed roster's **process-global `os.Setenv` isolation** in favour
of explicit per-invocation data, and fix three further defects exposed by running
the cutover live. This is the `spec` leg of the `check-bed-roster` program
(plan §4.2 / F8, RCA issues 1–2 and 5–7). The sdk + plugin consumers land
sdk-first after this is merged + tagged.

### 1. `RunEnv` — per-invocation environment on `context.Context`
`bed_session.go` isolated each bed with `os.Setenv(CHARLY_DEPLOY_CONFIG /
CHARLY_REPO_OVERRIDE / CHARLY_PREEMPT_LEASE)`. `os.Setenv` is process-global, so
under a roster — many beds as goroutines in **one process** — bed A's value is
inherited by bed B *and bed B's forked children*; two beds then contended on one
deploy-config lock and HUNG for the 30-minute image-build bound (RCA issues 1–2).
- `spec/runenv.go` — `RunEnv`, `WithRunEnv`, `RunEnvFrom`, `RunEnvGet` (ctx value
  wins, else `os.Getenv` — byte-identical for the legacy host CLI).
- `spec/deployconfig.go` — `DefaultDeployConfigPath(ctx ...context.Context)`
  resolves the ctx `RunEnv` `CHARLY_DEPLOY_CONFIG` before the process env.
- `lock/filelock.go` — `AcquireFileLockWithin` + `flockBoundedWithin`: a brief
  config read-modify-write passes a SHORT bound so a contended overlay write fails
  **fast** with the holder named, instead of waiting the 30-minute image-build
  bound. The now-unused `flockBounded` wrapper is deleted.

### 2. `ResolveBedForRoot` — root-qualify namespaced bed cross-refs (RCA issue 5)
A namespaced bed's `image:`/`from:` (and each member's, recursively) live in its
OWN namespace, but the run drives `charly box build <image>` /
`charly deploy add <name> <image>` from the project ROOT, where a bare
namespace-local ref does not resolve. Measured live:
`charly.check-sidecar-pod` failed `[image-build] unknown box "check-k8s-deploy-app"`.
`spec.UnifiedFile.ResolveBedForRoot(ref)` resolves the bed and rewrites every
namespace-LOCAL cross-ref to the root-qualified `ns.<leaf>` form **on a deep copy**
— the Member slice and each member node are cloned, so the stored tree is
unmutated and `charly box validate` still reads the authored refs.

### 3. `RunCharlySubcommandCtx` — carry RunEnv into forked children (RCA issue 7)
`deploykit.BringUpMembers`/`TearDownMembers` fork member children via
`proc.RunCharlySubcommand`, which inherited the parent PROCESS env. Once bed
isolation retired `os.Setenv`, those children resolved the **real** per-host
overlay and wrote the operator's state (observed live: bed entries landed in
`~/.config/charly/charly.yml`). `RunCharlySubcommandCtx(ctx, …)` merges the ctx
`RunEnv` OVER the inherited environment; the legacy `RunCharlySubcommand`
delegates with `context.Background()` (byte-identical inherit when no RunEnv).

**Additive / no schema change** — new helpers only; `DefaultDeployConfigPath`
stays call-compatible via its variadic tail. **No `#SchemaVersion` bump.**

**Closes / relates to:** part of the `check-bed-roster` cutover (plan §4.2).
