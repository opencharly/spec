# 0.2026262.1230 — cleanup(spec): remove the redundant charly protocol_version wire field

## Summary of changes

Removes charly's redundant `Capabilities.protocol_version` wire field and the `transport.ProtocolVersion` const. RDD established the field guards nothing.

**The question asked was: what is the point of ProtocolVersion?** Two distinct things share the name; only one is redundant:

1. **hashicorp/go-plugin's `HandshakeConfig.ProtocolVersion`** — go-plugin's OWN transport-family negotiation, checked by its `checkProtoVersion()` at Connect, *before* Describe. charly must carry it, and it is **kept, frozen at 2**.
2. **charly's own `Capabilities.protocol_version` + the equality gates** — a second, parallel version check. Both arms are dead:
   - **IN-PROC**: a compiled-in plugin advertises charly's OWN const (MVS unifies sdk), so the comparison was `x == x` — a tautology.
   - **OUT-OF-PROC**: go-plugin's handshake (1) already refused a transport-incompatible binary before Describe — the gate was **unreachable**.

The const was also never maintained as a gate: a **real** wire field was added (`CLISubcommand.hidden`, commit `4827829`) with **no** bump.

Concrete edits (4 files, +15/−26):

- `protocol/schema/plugin.cue` — drop the `protocol_version` field; **reserve field number 2**.
- `proto/plugin.proto`, `proto/plugin.pb.go` — regenerated by `task wire:gen`.
- `transport/plugin.go` — remove the const; `Handshake.ProtocolVersion` becomes the literal `2`.

**Why the handshake value is NOT removed.** RDD proved omitting it refuses already-built plugins whose WIREFRAME is compatible (`incompatible API version with plugin. Plugin version: 2, Client versions: [0]`).

**The real wireframe gate is unchanged and hard** — the CUE schema a plugin serves over Describe, spliced onto the host base (`reference "#Fleet" not found` on a real gap).
