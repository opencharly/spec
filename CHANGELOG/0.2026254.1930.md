# 0.2026254.1930 — feat(seam): ProjectLoader gains RepoOverrideDir (the CHARLY_REPO_OVERRIDE transit to core)

## Summary

Wave step 1 of 3 of the override-precedence seam NAMED in charly #587's merged body: `spec.ProjectLoader` gains `RepoOverrideDir(repoPath string) (string, bool, error)`.

**Why the seam exists.** charly #587 made the served-plugin-artifact report honest, but had to record a named follow-up instead of the wanted behavior: a `CHARLY_REPO_OVERRIDE` local tree cannot outrank the BAKED plugin probe in charly core, because core may not reach the parser itself — `charly/import_purity_test.go` forbids every `github.com/opencharly/sdk` import in core, and the parse lives in the sdk (sdk #251, tag v0.2026254.1740: `loaderkit.RepoOverrideDir(repoPath, envValue)`). The fix is a transit, never a re-derivation: spec declares the method, the loader plugin implements it by delegating, and core reaches it through the EXISTING `requireProjectLoader()` seam it already uses for `EnsureRepoDownloaded` / `ResolveMergedDeployTree`.

**The method** (full doc comment in the diff): returns the configured local override directory for `repoPath` — the `CHARLY_REPO_OVERRIDE` local-tree redirection `EnsureRepoDownloaded` already short-circuits on — or `("", false, nil)` when no override applies. A malformed entry, an empty override directory, or a missing/non-directory target is a hard error: the override was set deliberately, so a typo must fail loud rather than silently fall through to a remote fetch.

**The signature takes ONLY `repoPath`.** The env value is read on the implementation side, so a consumer cannot thread its own env read and re-derive the parse (R3 — a second parse anywhere is the divergence this seam exists to prevent). It also matches the sdk's own shape: `loaderkit.RepoOverrideDir(repoPath, seams.OverrideEnvValue)` keeps the env at the seam's edge, exactly as the plugin-loader must read it.

**The wave (this PR is step 1/3):**

1. **spec (this PR)** — declares the seam method + pins its signature.
2. **candy/plugin-loader** — implements it, delegating to `loaderkit.RepoOverrideDir` with the env read plugin-side. Same commit bumps the spec pin (plugin-loader currently pins `github.com/opencharly/spec v0.2026251.500`; its `f2_seam_test.go` `var _ spec.ProjectLoader = (*provider)(nil)` assertion requires the method, so the pin and the delegator move together — nothing builds against this method until then).
3. **charly** — `charly/plugin_loader.go` asks `requireProjectLoader().RepoOverrideDir(parsed.RepoPath)` before the baked-artifact probe; that file's own comment at the call site names this exact wave.

**No CUE / wire / generated change**: this is a typed compiled-in seam (like `EnsureRepoDownloaded` / `ResolveMergedDeployTree`), reached in-proc by core — no envelope, no generated artifact, so the diff is the interface method plus the signature pin.
