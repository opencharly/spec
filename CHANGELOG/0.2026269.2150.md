# 0.2026269.2150 — feat(checkstep)!: the candy owns its step kind + materialization (C7)

## Summary

C7 crutch-sweep, producer-first leg 1/5. Widen `spec/checkstep`'s `StepProvider` so the
**candy** owns BOTH halves of its typed install-step lowering, and delete the now-dead
descriptor / kind-name machinery.

`StepProvider` becomes:

```go
type StepProvider interface {
	StepKind() spec.StepKind
	MaterializeStep(op *spec.Op, runAsUser, candyName, pkgFormat string, distroTags []string) spec.InstallStep
}
```

- `StepKind()` returns the internal InstallPlan IR `spec.StepKind` directly — no candy-local
  `StepKindName` string enum for core to map.
- `MaterializeStep` builds the real `spec.InstallStep` from the op's `plugin_input` plus the
  four host-resolved ctx scalars.
- **Deleted:** `StepKindName` + `StepKindNameServicePackaged` / `StepKindNameSystemPackages`,
  `StepDescriptor`, `ServicePackagedDesc`, `SystemPackagesDesc`.

**RCA.** `charly/check_kit_adapter.go` held a per-kind `switch` (`kitStepKindToCharly`) plus a
per-kind materializer (`materializeStep`) in CORE. A core kind switch is an incomplete seam by
the kernel/plugin boundary law, and it existed only because `StepProvider` returned a
candy-local kind string plus a neutral descriptor, forcing core to map and rebuild. Widening
the interface removes the need for any core switch; the consumer legs (`sdk/kit`,
`candy/plugin-service`, `candy/plugin-package`, `charly`) follow producer-first.

Review round 1 addressed both BLOCKs: the stale consumer-leg "compiles UNCHANGED" claim
corrected (comment-only commit `354bc88`), and the attribution tier is now backed by a live
end-to-end run (below).
