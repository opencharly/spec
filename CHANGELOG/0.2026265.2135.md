# 0.2026265.2135 — fix(merge): delete the dead layered-config-stack wrapper

## Summary of changes

Deletes the dead layered-config-stack wrapper `merge.MergeConfigStack` and its test.

`merge.MergeConfigStack(system, user, project, …)` merges a three-layer stack into one `spec.UnifiedFile`. It is:

1. **Dead** — zero production callers anywhere in the ecosystem. `grep -rn MergeConfigStack` across opencharly/sdk, opencharly/charly, and every local repo returns only this function's own `merge_stack_test.go`. Neither charly nor sdk ever imported it; the live config stack is `sdk/loaderkit/config_stack.go`, which the loader actually drives. It rode along in spec#112 (§3.5) as a "wrapper" that was never wired.
2. **Wrong** — like the sdk stack before opencharly/sdk#270, it models the per-host **deploy overlay** (`~/.config/charly/charly.yml`) as a project document layer. That overlay is a `DeployConfig` — per-host runtime state — and merging it as a document layer puts a deploy-level member's top-level persisted copy next to the member its owner still declares nested, which `FoldMembers` rejects (`peer name "..." collides with an existing deploy/bed/peer entry`).

One canonical implementation (R3): `sdk/loaderkit/config_stack.go` owns the **project** stack (system + in-dir); the overlay's ONE application is the per-field deploy-node merge (`deploykit.MergeDeployConfigs` → `deploy.MergeDeployNode`), whose lookup recurses into the `Member` tree and cannot create a stray top-level key.

Concrete edits:
- `merge/merge_stack.go` — deleted (105 lines: `MergeConfigStack` + private `cloneUnified`/`cloneRawMap`/`cloneDeployMap`/`clonePluginKinds`).
- `merge/merge_stack_test.go` — deleted (134 lines).
- `merge/merge_unified.go` — **untouched**; `MergeUnified` is still the live document merge.
