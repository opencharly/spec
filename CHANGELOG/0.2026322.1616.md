# 0.2026322.1616 — feat(spec): give the #ResourceKind vocabulary its derivation (TODO 3.1, leg 1 of 3)

## Summary

TODO.md **3.1**, leg 1 of 3 (tracked in **opencharly/spec#380**) — the membership question "is this word a #ResourceKind?" leaves the consumers and comes home to the contract.

It was derived **twice, outside the contract, over one contract-owned list**, by two byte-identical five-line helpers in two repos:

```go
sdk/loaderkit/parse.go:35          resourceKindSet = sliceSet(spec.ResourceKinds)
charly/reserved_registry.go:46     resourceKindSet = setFromSlice(spec.ResourceKinds)
```

`spec` exported the vocabulary and no derivation, so both consumers hand-rolled one. `spec.ResourceKindSet()` is that derivation, once, in the module that owns the list.

**What legs 2 and 3 do — corrected by the reader sweep, which found more callers than the plan assumed.** The two helpers are general-purpose set builders over *any* vocabulary, not resource-kind helpers: `sliceSet` has six other call sites in `sdk/loaderkit/parse.go` (`StepKeywords`, `DocDirectives`, `AuthoringVerbs`, `KindWords`, the instrument modifiers) and `setFromSlice` has four others in `charly/reserved_registry.go` (`authoredOpFieldSet` and a two-vocabulary consistency comparison). So the legs replace **the resource-kind call site** with `spec.ResourceKindSet()`; the helpers are not deleted by this cutover, and any claim that they would be was wrong.

**A fresh map on every call, deliberately.** A set cached and handed to two consumers is a shared mutable table: a caller writing to its copy would silently change another caller's classification. That is the shape D-STORE-1 was about, so the invariant is tested, not assumed (second test below).

## What the contract says — cited, not assumed

`DESIGN.md` **is not silent** on this, and I checked before choosing the signature:

- **S3** (`DESIGN.md:869`): the vocabulary table is keyed by word and carries the data, "**the word list is derived**" from it, and `@vocab` names the module that owns the set. Deriving in the contract is therefore the row's own ordering, not an inversion.
- **C3** (`DESIGN.md:1074`): a vocabulary word is "**a typed word with `Valid()`**". **A membership set is not that**, and this PR says so rather than letting the signature speak for the contract. The generated artifact is today a bare `[]string`, and the typed-word form exists nowhere in this module yet:

```console
$ git -C spec grep -n ') Valid() bool' origin/main -- 'spec/*.go' | grep -v _test
$ echo $?

```

So this is a **helper over the generated list, not a new shape**: it declares no type and no vocabulary the schema does not already own. When the generator emits `type ResourceKind string` with `Valid()` (filed as **opencharly/spec#382** — the generator's typed-word shape, tracked there rather than parked here), membership becomes `ResourceKind(w).Valid()` and `ResourceKindSet` leaves with its last caller. Stated here so the next reader inherits the direction, not a gap.
