# 0.2026247.2009 — feat(schema): deploy update_gate: field — the R10 fresh-update change-class switch

## Summary

Adds the `update_gate:` field to the #Deploy node — the check-bed's declarative R10 fresh-update **change-class switch**. This is the missing declarative surface from the measured omarchy PR-eval gap: `charly check run --help` exposes only host/repo/dir flags and there was no bed-level way to declare the restart-only/skip change class (the eval lane restarts the clone instead of the full destroy+recreate for runtime-PR-injection evals).

Three legal values (closed enum, default `full`):
- `full` (default) — the canonical destroy+recreate gate: `charly update` rebuilds the venue from scratch (a VM domain is destroyed + recreated, a pod image rebuilt + container recreated, a group rebuilds every member image) and re-checks it. Today's behavior, zero regression.
- `restart-only` — replace the destroy/recreate with a plain venue RESTART (a VM boots its existing clone again, a pod restarts its container, a group cycles its members WITHOUT rebuilding images) and re-run the check-live pass against the restarted venue. The change class for runtime-PR-injection software-class evals: a rebuild cannot alter a runtime-injected artifact, so the full gate's ~38s destroy/recreate in the measured omarchy PR-eval lane proves nothing.
- `skip` — no update phase and no post-update pass (the declarative twin of `--no-rebuild`; `--no-rebuild` / `--anchor` still force skip structurally).

**Changes:** `schema/deploy.cue` +26 (the `update_gate?: *"full" | "restart-only" | "skip"` field, check-bed only like `snapshot:`), regenerated `spec/cue_types_gen.go` (`UpdateGate string` on the Deploy struct via `task cue:gen` — reproducible, guarded by the repo's TestGenReproducible) and `spec/deploy_update_gate_test.go` (+65) — B12 coverage: the compiled-schema test accepts the legal values + the defaulted absence and rejects an out-of-enum value, FAILING if the field is absent.
