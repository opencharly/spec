# 0.2026268.2256 — fix(spec): namespace-qualified deploy fold + exact-key node resolution

## Summary of changes

Make the merged-root deploy tree **namespace-aware** — one of the fixes for the
whole-roster failure (plan §4.1). `charly check run check-all-beds` selected 127
beds and **every namespaced VM-root bed failed** (`charly.check-agentteams-vm`,
`charly.check-helm-vm`, `charly.cachyos.check-cachyos-vm`, …). This leg fixes the
two `spec`-owned defects; the third (descent-stamp recursion) is sdk#291.

### RCA (measured live)
```
namespaced: DEBUG bedSetup charly.check-agentteams-vm: From="charly.agentteams-vm" Target="vm" Descent=<nil> IsVM=false
local:      DEBUG bedSetup check-agentteams-vm:        From="agentteams-vm"        Target="vm" Descent=&{Venue:ssh…} IsVM=true
```
Three namespace-blind defects:
1. **No qualified deploy fold** (THIS PR) — `uf.Deploy` is root-scope only, so
   `charly deploy add charly.check-agentteams-vm` found no entry (target → "pod").
2. **`ResolveNodePath` split the qualified key** (THIS PR) — a dotted path is a
   MEMBER path (`openclaw-stack.web.db`), so the qualified key was read as root
   `charly` + member `check-agentteams-vm` and missed.
3. **`StampDeployDescents` did not recurse namespaces** (sdk#291).

### What changed
- **`UnifiedFile.Deploys()`** — namespace-qualified deploy fold (local bare +
  `ns.name`, recursive, cycle-guarded), matching `Beds()`. ONLY `from:` is
  qualified: an `image:` is a box config ref that doubles as an OCI base whose LEAF
  the pod overlay resolves, so qualifying it broke the pod alias-tag path
  (measured: exit 125).
- **`deploy.ResolveNodePath`** — try the EXACT full key first; member descent only
  when the key is absent.

**Closes / relates to:** plan §4.1. The third defect is sdk#291.
