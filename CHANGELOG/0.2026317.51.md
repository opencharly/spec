The `kind: task` authored body lives with the plugin that serves it — `plugin-task`'s own CUE module, `candy/plugin-task/schema/task.cue`, since `opencharly/plugin-task#66` — so this deletes the contract module's twins and regenerates.

### What is deleted

From `schema/task.cue`: `#Task` and `#TaskValue`. The generated `spec.Task` type goes with them, and `spec.KindValueDefs` drops `task`.

10 → 9 kinds, and `task` is the one that left.

**`#TaskParamSpec` STAYS**, and it is the one def of this kind that cannot move: `plugin-pipeline`'s schema types a pipeline's `args:` as `{[string]: schema.#TaskParamSpec}` (`plugin-pipeline/candy/plugin-pipeline/schema/pipeline.cue:354`), and a plugin's CUE module can import only THIS contract module — never another plugin's. Moving it would let `kind: task` and `kind: pipeline` disagree about what an arg value is (R2). The file's header now says that, and why.

### The corpus moved BEFORE the defs were deleted

`spec/schema/task_test.go`'s four closedness cases existed only here. They moved to `plugin-task/candy/plugin-task/task_schema_corpus_test.go` in leg 1 (`opencharly/plugin-task#66`), judging the plugin's composed SERVED schema, so this PR deletes only what has a live replacement. That file's fifth test (`TestKindValueDefs_HasTask`) asserted this module's map entry for a body it no longer owns; it is replaced by the DELETION's own gate, `spec/task_test.go`:

- positive control: `#CandyValue` present and `KindValueDefs["candy"]` non-empty (a concatenation or generator failure would otherwise make every absence "pass" for the wrong reason);
- `#Task` and `#TaskValue` ABSENT;
- `KindValueDefs` carries no `task`;
- **`#TaskParamSpec` PRESENT** — the shared half that did not move.

### Two follow-through edits the deletion forced

- `spec/spec/pipeline_test.go` used `#TaskValue` as the **positive control** of unit 1's absence gate ("the schema does not carry #TaskValue — the absence checks below would be vacuous"). The control is now `#CandyValue`, a def this module owns and keeps.
- `schema/task_test.go` also defined the shared `compileShipped` fixture that several other tests in package `schema_test` use. It moves to `schema/compile_shipped_test.go` rather than going with the corpus — deleting it with the file would have been a build failure in unrelated tests, measured and fixed here.

## Change classification

**Breaking change + rollback:** `spec.Task` and `spec.KindValueDefs["task"]` disappear from the contract module. `plugin-task` stopped reading either in leg 1 (it decodes `params.Task` and declares its own `#TaskValue`), and `plugin-pipeline` never read them — it reads `#TaskParamSpec`, which stays. An out-of-tree consumer that pinned this module and named `spec.Task` would fail to compile, which is the intended hard cutover; the only in-tree site was the SDK, deleted in leg 2. Rollback is a revert of this commit; the defs return to the base and `plugin-task`'s copy still composes onto them (that is the state leg 1 measured with zero verdicts moved).
