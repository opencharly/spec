# 0.2026269.2203 — feat(schema): single-source the verb:oci containerDisk emit wire types

## Summary

Add `#ContainerDiskEmitRequest` / `#ContainerDiskEmitReply` to `schema/oci.cue` — the canonical verb:oci wire pair for the `container-disk-emit` op: turn a materialized guest disk into a bootable containerDisk OCI image (a single `application/vnd.oci.image.layer.v1.tar+gzip` layer with the disk at an in-image path, default `/disk/disk.img`, the KubeVirt / Cua Fleet contract) and push it to a registry.

This is the produce half of the Cua Fleet / KubeVirt support the containerDisk **consume** arm (`#171`, the `container_disk` `#VmSource` arm) already pulls. The emit engine lives in `candy/plugin-oci` (where the go-containerregistry stack is single-homed); this PR single-sources its wire contract in `spec` so the emit leg and its callers (`charly vm box publish`, the Cua Fleet surface) share ONE decoded type instead of hand-written copies that can drift — exactly the `#149` precedent for `#CacheTransferRequest` / `#CacheTransferReply`.

Purely **additive wire types** — they are never authoring kinds (never in `#Node`/`#Op`) and do not change any authored key, so there is **no `#SchemaVersion` bump** and nothing to migrate.

The `disk_path` / `in_image_path` / `labels` / `ref` / `insecure` / `layout_dir` fields map the emitter's inputs; `ref` / `digest` / `media_type` / `layer_size` / `layout_dir` map its result.
