# 0.2026269.4 — feat(schema): persist kubevirt_state via #SaveDeployStateInput

feat(schema): persist kubevirt_state via #SaveDeployStateInput

Closes the R5 gap found while building `plugin-kubevirt`: `#Deploy.kubevirt_state` (merged in spec#161) had no WRITER — `#SaveDeployStateInput`, the input `deploykit.SaveDeployState` persists through, lacked the field. This adds it (the kubevirt analogue of the existing `vm_state`), so the kind:kubevirt venue identity round-trips through the per-host overlay.

## Summary of changes

- **`schema/deploy.cue`** — `#SaveDeployStateInput.kubevirt_state?: #KubeVirtDeployState` (beside `vm_state` / `vm_cross_ref`).
- **`spec/cue_types_gen.go`** — regenerated (`SaveDeployStateInput.KubeVirtState`).

The sdk counterpart (`deploykit.SaveDeployState` writing `entry.KubeVirtState`) lands in a companion sdk PR.
