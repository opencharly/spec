# 0.2026295.2356 — feat(init): the container-venue init runtime contract and the extends merge

## Summary

The `spec` producer leg of the W3.8 cutover (opencharly/charly#1030, from the spike in #1027). A container can host a real init as PID 1, but the venue must be TOLD so — and the init vocabulary had nowhere to say it. This adds the declaration and the selection rule; the consumers (`plugin-init`, `sdk`, `charly`, `plugin-deploy-pod`) follow producer-first.

- **The container-venue runtime contract.** `#Init` / `#ResolvedInit` gain `requires_root`, `systemd_mode`, `stop_signal`; `#CapabilityInitDef` (the `ai.opencharly.init_def` label) carries them to the deploy, so the deploy reads the IMAGE rather than switching on an init-system name. `requires_root` is what keeps a systemd image at root in both the build's final `USER` and a deploy overlay; `systemd_mode`/`stop_signal` are the engine facts (`--systemd=always`, `SIGRTMIN+3`).
- **`extends:` — one authored service template, not two.** A variant that is the same init in another venue (`systemd-container` → `systemd`) inherits the base entry and overrides it. `ProjectInitConfig` resolves every chain before any consumer reads the map, rewrites the entry's `Raw` body so the service-render leg sees the inherited `service_schema`, and leaves an unknown base or a cycle completely inert (no partial merge). A document-level YAML alias cannot do this: the loader re-parses each top-level entry in isolation ("unknown anchor" — measured), which is why the merge is a resolve-time step.
- **Container-venue init selection.** `ResolveInitSystem` honors a composition's `init_system_hint` (an existing capability with no consumer until now) for a viable candidate — the hint is what selects an init that is neither bootc's `systemd` nor the default `supervisord`. It is honored only when the candidate exists, so the "resolved name is always an ActiveInit key" invariant holds.
- **`requires_capability` admits the `init_system:<name>` key**, including a hyphenated init name; the key grammar already existed in the aggregator.
- **`#Box.init` accepts `systemd-container`** — the enum has to list every vocabulary init (the `openrc` precedent, with a test).
- **`#EngineCapability.systemd_mode_arg`** — the engine's own spelling of its systemd-mode flag as DATA (podman `--systemd=always`), not a switch in the caller.

The new assertions carry controls that fail without the change (each measured by reverting the production code in the same tree):

- `TestResolveInitSystemHonorsAContainerInitHint` — the same composition with NO hint resolves to `supervisord`; with the hint, `systemd-container`. Removing the hint branch fails the second arm (`ResolveInitSystem(hint) = "supervisord"`). It also pins that an explicit box `init:` beats the hint and that a hint naming a non-candidate falls through.
- `TestApplyInitExtendsSharesTheOneTemplate` — the child inherits the base's `service_template`, keeps its own `entrypoint`, clears `Extends`, and its rewritten `Raw` decodes back to an authored `#Init` carrying the inherited template (the render leg's actual input).
- `TestApplyInitExtendsLeavesABrokenChainInert` — an unknown base and a cycle leave every entry exactly as authored (a cycle merged one arm before the whole-chain check was added; the test caught it).
- `schema/box_init_test.go` — `systemd-container` unifies with `#Box` and an unknown word is still rejected (the enum stays an enum).

`charly task cue-gen` was run twice on this tree; the second run changed nothing (the task's own `TestGenReproducible` step passed both times, and `git status` was byte-identical between runs).
