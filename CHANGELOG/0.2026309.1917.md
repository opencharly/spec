# 0.2026309.1917 — fix(schema): persist a pod deploy's authored engine selector

## Summary

`#SaveDeployStateInput` is the generic state patch a deploy substrate's
`PrepareVenue` ships back to the per-host overlay. For a `pod:` deploy it carried
every field except the authored `engine:` selector, so `charly deploy add` on a
node with `engine: containerd` persisted only `resolved_image`; `charly config`
then resolved the host-wide `engine.run` (podman) and emitted a podman quadlet,
and `charly start` ran `/usr/bin/podman run` (opencharly/charly#1109).

This is the producer leg of the fix. It adds `engine?: #EngineName @go(Engine)`
to the CUE source and regenerates `spec/cue_types_gen.go` with
`charly task cue-gen`. The field is optional and empty is omitted, so a consumer
can distinguish "no selection at this level" from "select podman" and the write
is a patch, never a clear.

Diff:
- `schema/deploy.cue` — the CUE source of truth.
- `spec/cue_types_gen.go` — regenerated, not hand-edited.
- `spec/save_deploy_state_engine_test.go` — proves the wire key carries
  `containerd` and that an unset engine stays absent (negative control).

The consumer leg that runs the live bed is the `plugin-deploy-pod` change
(producer→consumer order): `PrepareVenue` copies the deploy node's `Engine` into
this patch, `sdk.applyDeployState` applies it, and a `disposable: true` `pod:` bed
carrying `engine: containerd` is run through `charly check run` on this host's
rootless containerd 2.3.5 (`nerdctl info` reports `rootless`).

## Change classification

Additive optional wire field. Consumers that do not adopt the new module tag
decode the patch as before (the key is simply ignored); no authored `charly.yml`
key changes spelling, and no migration is owed. Consumers that adopt it get the
selector.

**Breaking change + rollback:** none — the field is optional, omitted when
unset, and old consumers ignore it. Rolling back this PR removes the field; the
consumer PRs would then be reverted first in reverse order (charly →
plugin-deploy-pod/plugin-fleet → sdk → spec).
