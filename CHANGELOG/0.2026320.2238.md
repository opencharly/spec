# 0.2026320.2238 — feat(schema)!: PORT the audit record from DESIGN.cue (P06 leg 1, redo)

## Summary

**The audit record, PORTED from `DESIGN.cue` — not re-designed.**

`PROGRAM/design-implementation.md` states the hierarchy: **`DESIGN.cue` is the single schema copy.** It already declares this contract in full (`DESIGN.cue:1146-1175`): `#AuditEvent`, `#AuditDetail`, `#Redacted`, `#AuditAppendInput`, and three word tables. This PR moves that declaration into the contract module so the code can be generated from it — **the names, the word sets and the field set are `DESIGN.cue`'s, verbatim.**

It replaces an earlier attempt (`spec#343`, closed) that *invented* a shape beside the declared one, and got it wrong three ways: a duplicate name (`#AuditRecord` for `#AuditEvent`), a struct where the design says a closed **word**, and worst of all a `#Redacted{secret: string}` that **holds** a name where the design holds **nothing**.

| | invented (closed) | `DESIGN.cue` | this PR |
|---|---|---|---|
| record type | `#AuditRecord` | `#AuditEvent` | **`#AuditEvent`** |
| redaction | `{secret: string}` | `{redacted!: true}` | **`{redacted!: true}`** |
| outcome | `{ok bool, message}` | `or(_auditOutcomeWord)` | **a word** |

**`#Redacted` is the one to look at.** `DESIGN.cue`'s comment: *"A record says a value was there without holding it."* The generated type is now:

```go
type Redacted struct {
	Redacted bool `yaml:"redacted,omitempty" json:"redacted"`
}
```

One field, a marker, **no place for a value to sit**. That is a structural guarantee; the closed PR offered a string field and asked a validator to police it.

## The prerequisite this needed: import hoisting

`schemaconcat` concatenates `schema/*.cue` into one package. CUE requires **every import to precede all declarations**, so the moment `#AuditEvent` wanted `... & list.MaxItems(32)` — which is what `DESIGN.cue` says — concatenation produced:

```
schemagen params: composing schema as package spec: expected label or ':', found 'STRING' "list"
```

**The tempting fix is to drop the bound. That is a scope reduction**, so instead the concatenator now hoists imports: it strips `import` declarations from each file (both `import "x"` and the parenthesized block form), deduplicates, sorts, and emits them once above every declaration. No spec schema used an import before this, so the path was untested; it is exercised now by the file this PR adds.

## Two defects this round found, in my own work

**1. The block form of `stripImportDecls` was broken.** It appended each *line* of a parenthesised `import ( "list" \n "strings" )` as a separate entry; the caller then sorted them and re-emitted one per line, producing `import "list"` / `"strings"` — invalid. A block is now ONE declaration, returned verbatim, with its parentheses. `schemaconcat/imports_test.go` pins it.

**2. The word-table count was wrong.** The body, the file table and the test all said four; `audit.cue` declares `_auditEvent`, `_auditOutcome`, `_detailCode`. The subtest that was supposed to check this was a **tautology over a hardcoded literal** (`if w == "" { t.Fatal() }`). It now OPENS `audit.cue`, counts the marked tables and asserts each word — so the prose and the file cannot drift again.

**And an existing gate caught what my own tests did not.** Running the whole package, not just my file:

```console
$ go test -count=1 ./schema/
--- FAIL: TestEveryTableDerivesItsWordList
    vocab_s3_test.go:224: table _auditEvent carries @vocab(""); every set in this module is
    compiled into the `spec` contract module, so the owner is `spec`
```

A contract rule I had never read: a vocabulary table declares its owner. Fixed as `@vocab(spec)` — unquoted; `@vocab("spec")` fails the same test with the quotes in the message.
