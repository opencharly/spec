# 0.2026320.16 — feat(ir)!: the candy views carry volumes and aliases as opaque bytes

## Summary

**The barrier.** `#CandyView.volumes`/`aliases` and `#ResolvedBoxView.aliases` were the **last three things in `spec`** naming `#CandyVolume` / `#CandyAlias` — so however opaque the MODEL became, those two defs could not leave for their owning plugin (`DESIGN.md` §3.1). They are bytes now:

```cue
// #ResolvedBoxView
	aliases?: bytes @go(Aliases,type=RawBody)
// #CandyView
	volumes?: bytes @go(Volumes,type=RawBody)
	aliases?: bytes @go(Aliases,type=RawBody)
```

Same reasoning the seven model fields followed (I1 / D-SCH-7), and it is the last layer: with the views converted, the authored defs have no referent in the contract except `#Candy` itself — which is exactly what a body owned by a plugin should look like.

**The three view fields, swept:**

| field | producer | consumers |
|---|---|---|
| `CandyView.volumes` | `loaderkit/scan_candy.go:325` (`v.Volumes = ly.Volume`) | `HasContent` (`:238`), `plugin-box`'s `inspect_list.go:365` (`box list volumes`) |
| `CandyView.aliases` | `loaderkit/scan_candy.go:329` (`v.Aliases = ly.Alias`) | `HasContent` (`:238`), `inspect_list.go:374` (`box list aliases`) |
| `ResolvedBoxView.aliases` | `deploykit/resolved_project.go:123` (`view.Aliases = append(…)`) | `plugin-box`'s `inspect_list.go:227` (`box inspect --format aliases`) |

## Change classification

Kind: a schema (IR) change in `spec`. It breaks consumers reading those three view fields as authored slices — **two repos**: `sdk` (`scan_candy` produces, `resolved_project` writes the box view, `HasContent` reads) and `plugin-box` (`inspect_list` reads the view for three `box inspect`/`list` commands).

**Breaking change + rollback:** consumers decode through `rawbody.Decode`. Rolling back restores the three slice types and regenerates; the wire is unchanged either way.
