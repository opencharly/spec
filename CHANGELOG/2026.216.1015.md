# 2026.216.1015 — a --repo cache fetched only one of its twelve submodules

`GitClone` populated exactly one submodule, `sdk`, selected by name. Everything
else a fetched project declares — `spec`, `plugins`, `docs`, the five
`box/<distro>` repos, the three `pkg/*` repos — stayed an empty directory.

The consequence was that `--repo` could not deliver the thing it exists for. A
`--repo` cache is a whole project someone drives with nothing but the `charly`
binary, and out-of-process plugin candies build STANDALONE in their own module
under `GOWORK=off`, resolving siblings through relative replaces. **86 of the 87
candy `go.mod` files carry BOTH** `replace github.com/opencharly/sdk => ../../sdk`
**and** `=> ../../spec`. With `spec/` empty, every one of those builds died on
`../../spec/go.mod: no such file`, so no out-of-process verb was reachable
through `--repo` at all. `box/<distro>` being empty removed the box definitions
too — main owns none.

The helper's own comment asserted the justification, and it was wrong on both
counts:

> Just `sdk` is initialized (the ONLY submodule a plugin build's go.work depends
> on), never the heavy `box/*` ones.

`spec` is equally required — that is the missing-file error above. And "heavy"
does not survive measurement: a shallow `--init --depth 1` of all twelve
submodules costs **~8s and 60MB**, against ~1s for the `sdk`+`spec` pair alone.
The cost the special case was guarding against does not exist at `--depth 1`.

`populateSDKSubmodule` is therefore replaced by `populateSubmodules`, which
initializes every submodule the repo declares, shallow and non-recursive —
exactly the configuration proven to build. A repo declaring none is still a
clean no-op. The `insteadOf` SSH→HTTPS rewrite is unchanged, so headless runs
still need no key.

Proven by mutation. Restoring the `sdk`-only argument to the otherwise-fixed
code fails `TestGitClone_PopulatesAllSubmodules` on precisely `spec/go.mod`,
`box/fedora/charly.yml` and `plugins/README.md` while `sdk` still passes —
characterizing the defect rather than merely detecting it. The test's `sdk`
probe alone would have passed both before and after, which is why the `spec`
probe is the load-bearing one.

End to end, from `/tmp` with a cold cache and no checkout anywhere, the fetched
cache now shows 12/12 submodules populated and
`charly --repo opencharly/charly mcp serve` — an out-of-process verb, built from
that cache — reports `serving 70 tools`.
