# 0.2026272.1512 — feat(spec)!: per-box candy-version scope + leveled diagnostics (INFO vs WARNING) (#735)

## Summary

The candy-version resolver arbitrated a bare ref **globally**: `spec.CandyCandidate`'s candidate
set was keyed by bare ref alone, so every independent box in an assembled closure merged into ONE
set. That made ~1602 spurious `Warning: candy … resolved to multiple git tags` lines in
`charly#733`'s bed and made R10's zero-warnings gate unreachable (`opencharly/charly#735` §9).

This PR is the **first leg** of a three-repo cutover (`spec` → `sdk` → `plugin-build`/`plugin-box`).
It is a CONTRACT change only — the arbitration logic lands in `sdk`.

**What it adds (the scope must travel with the fetch):**

- `spec.CandyCandidate.Referrers []string` — the SCOPE label(s) whose candy closure names the ref
  (`box=<qualified-name>` is the box key; `kind:local=<tpl>`, `layer=<name>`, `deploy=add_candy` for
  the other compositions).
- `spec.RemoteDownload.RefReferrers map[string][]string` — the same labels travel **with the fetch
  descriptor**, because the collector sees the reachability context and the post-fetch arbiter does not.
- `spec.ScanSeams.Warn` → `spec.ScanSeams.Diag`, carrying a `DiagLevel` as its **first argument**
  (`DiagInfo` for a RESOLVABLE skew — the arbiter always has a deterministic winner, so nothing is
  unresolved; `DiagWarning` **only** for a genuinely unresolvable set). ONE sink, ONE formatter, no
  parallel advisory channel.

**The regression this also prevents (found while implementing, R1/R2):** `Diagnostics.HasErrors()`
asked `Severity != "warning"`, so the moment the scan reported its resolvable skew at the new INFO
tier, **every resolvable closure would have failed `charly box validate`**. The PR declares the
CLOSED severity vocabulary in `spec/diag_severity.go` and reduces through ONE predicate,
`Diagnostic.IsError()`. `IsError` **enumerates the non-error tiers explicitly** (`info`, `warning` →
false); every other value — including an empty severity — is error (fail-closed). Adding a new
non-error tier requires editing that switch, which is the contract the comment states and
`diag_severity_test.go` pins. This is a required companion change, not an optional one.

**Authoritative semantics this serves** (the version rule, restated at `charly#735` §7):

| Situation | Correct behaviour |
|---|---|
| One box, two layers pin `pod-dbus` at different versions | newest **referenced** wins; note at **INFO** (resolvable) |
| **Two different boxes** pin `pod-dbus` at different versions | **NOT** a conflict → **silent** |
| One box, every layer pins the same version | no notice |
| A bare ref and a pinned ref differ | the bare ref resolves to the **newest referenced** — never newest-remote |
