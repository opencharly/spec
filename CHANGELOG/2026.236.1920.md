# 2026.236.1920 — feat(spec): PhaseTemplates.install — one venue-agnostic install body, venue wrapper at render

## Summary

R3 fix: the package-install logic (repo setup + key import + package install) was hand-maintained TWICE per format — `phase.install.host` and `phase.install.container` — and the copies drifted. Two live bugs from one root cause: the rpm host cell was bare (`check-fedora-vm` `No match for argument: charly`, fixed by charly#396) and the pac host cell is bare (`check-cachyos-vm` `target not found: charly`, in flight) — both "the repo is never added on the host venue" because the host copy missed the repo/key logic the container copy had.

This change makes the install body ONE venue-agnostic `install` cell written with `&& \` continuations (valid plain shell AND inside a Dockerfile RUN). `FormatPhaseTemplate` returns it verbatim for the host venue and prepends `RUN {{cacheMounts .CacheMounts}} \` for the container venue. The `host`/`container` cells remain only as venue-specific OVERRIDES for prepare/cleanup or a genuinely venue-divergent install.
