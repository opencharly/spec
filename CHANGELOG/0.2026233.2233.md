## ci: roll out org-wide bot-token validation flow

Replaces the per-repo inline validator with the thin org-wide
dispatcher (shared logic lives in `opencharly/.github`):

- Job renamed to `validate` (branch protection check becomes
  `validate / validate` — already updated).
- `workflow_dispatch` trigger added for manual re-validation.
- `.github/workflows/auto-merge.yml` (the obsolete
  check_run/workflow_run engine that never fired for
  approval-required runs) deleted.
- `tag-on-merge.yml` dispatcher added for org parity (tags every
  merged PR — the org rulebook's per-merge CalVer tag).

### Maintainer sign-off (T4 — gate coverage + permissions)

- **Fork-PR exclusion**: intended. Fork PRs cannot complete the
  org-wide flow (the CHANGELOG rename needs `contents: write`, which
  GITHUB_TOKEN lacks on fork PRs), so the gate skips them.
- **Permission escalation** (`contents: read` → `contents: write`,
  added `actions: write`): required to call the shared reusable;
  identical to all other org-wide dispatchers.
