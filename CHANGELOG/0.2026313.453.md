# 0.2026313.453 — feat(schemacompose): the one module-aware compose for a plugin's served schema

## Summary

The ONE module-aware compose for a plugin's served schema, in the contract module — the
shared half of opencharly/sdk#490.

**Why here and not in the sdk.** `charly/charly/import_purity_test.go` states it verbatim:
`github.com/opencharly/sdk` (root or any subpackage) "is for PLUGINS to import, never the
host". The host may import `github.com/opencharly/spec`; the sdk and every plugin import
this module. Both halves of the contract — the serve side and the host gate — must judge the
same schema with the same code, so the composer has to live where both may reach it. This
module already owns the family: `schemaconcat`, `schemaparams`, `cuetoolchain`, the embedded
schema source and the module declaration.

`ServedSchema` composes a plugin's concatenated schema body as one CUE module instance:

- the plugin's own `cue.mod/module.cue` when its FS ships one, used verbatim after one check
  (its `language.version` must be this module's);
- otherwise a declaration derived from this module's pinned `language.version`, naming
  `github.com/opencharly/spec@v0` as its one dependency.

`ServedText` composes the package-less body that travels on `Capabilities.schema_cue`: the
SAME compose under the derived declaration, because the wire carries no module declaration —
the declaration must be one both sides derive, which is what makes the two agree byte for
byte.

The dependency is served by a `modconfig.Registry` from the embedded CUE module this Go
module already carries, so the compose is offline: no network, no module cache, no
`cue.mod/pkg` vendoring, and no local `replace` (the pinned modfile schema has no path
field). The loader requires that dependency's source FS to implement `module.OSRootFS`, so
the module is materialized once at a content-named directory under the system temp root —
never the host tree — and every compose shares it. The registry matches on the base path,
since the loader asks with the major-suffixed path.

**Sequence.** opencharly/sdk#491 landed a first copy in the sdk (tag `v0.2026313.433`); the
sdk's next unit makes its public entry points delegate here and deletes that copy, so there
is ONE implementation. The host gate — per-unit compose, then unify, in
`charly/plugin_loader.go` — follows it.
