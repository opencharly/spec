## The fix — the issue's candidate 1, as a sibling fetch rather than an options type

```go
// whole project: unchanged signature, unchanged behaviour (submodules populated)
func DownloadRepo(repoPath, version string) (string, error)

// corpus/docs SOURCE: the repo's own tree, and nothing else
func DownloadRepoFiles(repoPath, version string) (string, error)
```

**Why this candidate, and why spelled this way.** The deciding criterion is that the
fetch should certify exactly what the reader needs and no more:

- `candywalk.RemoteResolver` is `func(repoPath, version string) (string, error)`, so a
  sibling with that exact signature **threads through the existing seam with no `sdk`
  change at all** — `candywalk.CollectEntitiesRemote(roots, refs.DownloadRepoFiles)`.
  An options type would have needed either a wrapper closure at every call site or a
  seam change in the SDK.
- `DownloadRepo` keeps its signature AND its submodule contract, so no `--repo` caller
  changes a line. Nothing is relaxed globally: the mode is a **per-fetch decision**.
- Candidate 2 (a per-ref marker in the pin contract) was rejected: it puts a reader's
  requirement into the REF, where every consumer of that ref inherits it. A ref names a
  repo at a version; what the fetch must certify is the CALLER's business.

**Two mechanisms make it a mode rather than a flag:**

1. **Its own cache key** — `<cache>/.files/<repo>@<version>`, one directory level below
   the whole-project `<cache>/<repo>@<version>`. Content decides the key: a tree export
   is not a usable `--repo` cache and a populated export is a superset, so sharing one
   key would make each caller re-download the other's entry on every run.
2. **Its own freshness predicate** — `repoCacheFreshMode`: a whole-project export must
   carry its submodule content (unchanged), while a files-only export is complete the
   moment its tree is there, because that is the entire content its reader asked for.

The mode directory rather than a `.files` **suffix** on the basename was itself decided
by measurement: `plugin-marketplace`'s `resolve.go` ranks two sources that publish one
identity by the CalVer it reads at the END of `Entity.SourceRoot`
(`@v<YYYY>.<DDD>.<HHMM>$`). A suffix made every fetched source unparseable and an
unparseable rank silently hands the identity to whichever twin still parsed. The
basename therefore stays `<repo>@<version>`, and the mode lives one level up.

  and still calls `refs.DownloadRepo` (`sources.go:152`, `catalog.go:290`), so it inherits
  the same population. Its own PR/tag chain; nothing here depends on it.
- **opencharly/plugin-marketplace#48** — `resolve.go` recovers a source's tag by parsing
  the cache-path basename, so a cache-layout change degrades the dedupe SILENTLY. This
  change's first cache-key design (a `.files` suffix) hit exactly that; the final layout
  (a `.files` directory, basename unchanged) preserves the shape it reads, and the issue
  asks for the structural read instead.
