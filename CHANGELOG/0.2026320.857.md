# 0.2026320.857 — feat(reader)!: the candy reader carries the RESOLVED twins

## Summary

The **second step** of the split `spec#337` began, and the one that makes it usable: `CandyReader.Alias` and `.Volume` now return the **resolved** twins instead of the authored defs.

```go
	Alias() []ResolvedCandyAlias
	Volume() []ResolvedCandyVolume
```

**Why the interface had to move.** A reader decodes a body that has **already been validated**, so the resolved form is what it needs. While the interface named `#CandyAlias`, every consumer of the interface held the authored def in place — and `sdk` aliases those types directly (`AliasYAML = spec.AliasYAML`), so a one-line change at the alias produced:

```
*specCandyAdapter does not implement spec.CandyReader (wrong type for method Alias)
	have Alias() []AliasYAML
	want Alias() []spec.CandyAlias
```

That error is the barrier in one line: **the contract's own reader interface was naming the shape that has to move.** Moving it here is what lets the sdk leg be a change of *target*, not a re-layer.

This is the same split the `vm` unit landed (`VmSpec = ResolvedVm`), applied to the reader contract it also touched.

## Change classification

Kind: a `spec` Go interface change. It breaks any `CandyReader` implementation that returns the authored slices — in this org that is `sdk`'s `specCandyAdapter` (the only production implementation) plus one test helper.

**Breaking change + rollback:** an implementor must return `[]ResolvedCandyAlias`/`[]ResolvedCandyVolume`. Rolling back restores the authored signatures; the wire is untouched either way, since both types are field-compatible JSON.
