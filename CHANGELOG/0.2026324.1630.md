# 0.2026324.1630 — feat(spec): carry a candy's declared var: onto BoxMetadata

## Summary

**A candy's declared `var:` now travels onto `BoxMetadata`**, so the check runner can supply a value for a variable it already knows by name.

**The defect this closes.** `#CandyFields.var` (`spec/schema/candy.cue:115`) declares a candy's template variables, and `#Op`'s own `config:` comment states the rule they follow — *"substitutes ${VAR} refs in content: at generate time (**candy var: ∪ auto-exports**)"*. **A `check:` step never got that union.** Its substitution base is `kit.ResolveCheckVarsRuntime`'s `buildTimeVars`, which reads exactly nine fields off `BoxMetadata` — `USER`, `HOME`, `UID`, `GID`, `IMAGE`, `DNS`, `INSTANCE` — and `var` was not among them.

**The symptom is worse than a missing value, and it is why this took a while to find.** The host's unresolved classifier *does* see the declaration, so the step does not fail `DEAD` (as an unknown name would); it returns:

```console
SKIP  check PROBE does a candy var reach a check step  [probe-var]  unresolved variables: PROBE_FLAG
```

**A variable the runner KNOWS and can never SUPPLY.** `sdk/kit/planrun.go:230` documents the split — an unknown name is a DEAD authoring error, a known-but-unsupplied one is a SKIP for *"inputs that genuinely don't apply to this run"* — and a candy-declared var is neither.

**This is leg 1 of three, producer-first.** Leg 2 (`sdk`) merges `meta.Vars` into `buildTimeVars`; leg 3 (`plugin-check`) needs nothing, because `ResolveCheckVarsRuntime` is the single builder. Until leg 2, this PR adds the field and changes no behaviour.

**Why it matters beyond the one case:** `opencharly/plugin-pipeline#69` cannot be graded at all without it — a bed has no way to be pointed at the worktree under test, because every `${…}` it might use is either auto-exported or unresolvable.

## Change classification

Kind: **an additive contract change** to `spec`. The new field is optional and defaults to empty, so an existing `BoxMetadata` producer or consumer is unaffected — no YAML needs a new key, and the generated Go field is `omitempty` on both tags.

**Breaking change + rollback:** not breaking. Nothing reads `Vars` until leg 2 lands; reverting this PR alone restores the previous behaviour exactly, because the field is never populated or consulted here.
