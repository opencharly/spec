# 0.2026321.739 — refactor(cache)!: StoreRoot asks the one resolver (P05, D-STORE-1)

## Summary

**One fact, one owner.** `D-STORE-1` (`DESIGN.md:2482`) says the roots are resolved by **ONE** resolver — `spec/storeroot`, re-exported by `sdk/storekit` — with the cache at `$XDG_CACHE_HOME/charly` and a single `CHARLY_CACHE_DIR` override. `spec/cache` resolved its own.

Now it asks:

```go
func StoreRoot() (string, error) {
	return storeroot.CacheDir()
}
```

**Why this is not a cosmetic dedupe.** Two resolvers that agree today disagree the moment either gains an override. The cache is the one root with a documented env override, so the second implementation is exactly the one most likely to drift — and it would drift silently, because both produce a plausible path.

**This is the successor to `spec#340`**, which the validator auto-closed at 5 BLOCK verdicts. Same commit, cherry-picked onto a fresh branch off the current `origin/main` (`af338d0`).

## Change classification

Kind: a behavioural change to one exported function in a contract module.

**Breaking change + rollback:** `cache.StoreRoot()` keeps its name, its signature `(string, error)` and its override behaviour — the old code honoured `CHARLY_CACHE_DIR` too. What changes is the **default**: without the override it now returns `os.UserCacheDir()/charly` (`~/.cache/charly`) instead of `filepath.Dir(spec.DefaultDeployConfigPath())/cache` (`~/.config/charly/cache`). So a caller that had populated the OLD default directory will find `StoreRoot()` pointing at a different tree, which is precisely the divergence this PR removes — and the reason it is a hard cutover rather than a quiet fix: two directories existed, only one can survive. Rollback restores the second resolver and both directories with it.
