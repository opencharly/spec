# 0.2026289.158 — docs(schema): an agent's body is authored at `.agents/agents/<name>.md`, not in the skills tree (D8)

## Summary

**The `skill` schema's prose stops putting an `agent`-type node inside the skills tree.** Two surfaces
carried the stale claim, and both are corrected here, together with the generated Go the CUE comments
are emitted into.

D8 (umbrella ledger §5, restated in §4.1) rules that a sub-agent definition is authored at
`<repo>/.agents/agents/<name>.md` — *"Agent definitions (`type: agent`) do **not** live under
`.agents/skills` … they are sub-agent definitions, not skills"*. The schema said the opposite:

```console
$ git -C <spec at origin/main> grep -n 'agent' schema/skill.cue schema/candy.cue | sed -n '1,6p'

schema/candy.cue:62:	// skills — the repo-relative skill/agent TREES this candy DECLARES, each holding one entry per
schema/candy.cue:63:	// name: <tree>/<name>/SKILL.md plus references/<stem>.md for a skill, and <tree>/<name>.md for
schema/candy.cue:64:	// an agent (type: "agent"). DEFAULT [".agents/skills"] — the Agent-Skills standard location, so
```

`<tree>` is the candy's `skills:` list, so that sentence places an agent's body at
`.agents/skills/<name>.md` — the harness's SKILLS tree, where six of `layer-charly-internals-extra`'s
sub-agent definitions would be loaded as skills. The `skills:` field is a list of **SKILL** trees and
does not govern the agent path, which is what makes a mixed repo — skills under a declared tree,
agents under `.agents/agents` — the legal shape rather than a half-move.

**This is the contract leg of a three-PR cutover, and the order is producer-first:**

1. **this `spec` PR** — the contract's prose names D8's path;
2. `opencharly/sdk` — `candywalk` grows the agent reader (`ReadAgentFile`), carrying the skill
   branch's fail-loud contract;
3. `opencharly/plugin-marketplace` — `extract`'s agent half and the generator's agent branch, with the
   `extract → read → emit == the corpus` round-trip test, whose `sdk` pin bump lands once (2) has a tag.

The comment names the path before its implementation exists; that window is declared here rather than
discovered later, and it is the same order the relocation's earlier legs used (`spec#247` →
`sdk#404` → the consumer). The consumers waiting on the chain are named, not promised:
`layer-charly-internals-extra#21` (2 skills **and** 6 agent nodes, filed by this leg) and
`pod-charly-automation#24` (one node left inline in `#25` for exactly this reason; commented).
