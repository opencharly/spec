# 2026.229.0947 — apk was a package format the vocabulary could not name

Placeholder CalVer (the pr-validator finalizes it at merge). Chosen after the newest
landed tag `v2026.228.0002`, with no filename or tag collision.

Two closed vocabularies knew about `rpm`, `deb`, `pac` and `aur`. Neither knew about
`apk`, so nothing downstream could describe an Alpine package at all.

## What the measurement showed

`FormatForDistroID("alpine")` returned `""`. `distroIDToFormat` is the single
distro-ID→format table, and `alpine` had no row — so no caller could resolve a package
format for an Alpine image, and every one of them read the empty string as "this distro
has no packaging".

`#BuildFormat` in `spec/schema/box.cue` is the closed enum behind a box's `build:` list.
A box declaring `build: [apk]` failed CUE unification with three conflicting-values
errors, plus a fourth on `distro:` that turned out to be a knock-on of the same failed
unification rather than a defect of its own:

```
build.0: conflicting values "rpm" and "apk"
build.0: conflicting values "pac" and "apk"
distro: conflicting values ["alpine"] and {[string]:#DistroPackages}
```

So the two authorities disagreed with each other in opposite directions: the enum
forbade the word, and the table had no meaning for it.

## The `apk` name is overloaded, and only one of the two senses belongs here

Worth stating because the collision looks like a reason not to make this change. This
repo already uses `apk` for **Android application packages** — a candy top-level key
(`apk:`, in `sdk/loaderkit`'s candy-key allowlist) and a check-verb input. That sense is
a different namespace from both surfaces touched here: `#BuildFormat` constrains a box's
`build:` list, and `distroIDToFormat` maps a distro ID to its OS package format. Neither
is reachable from the Android key, and the Android key is not reachable from either.
`apk` in the two rows added here means Alpine's package format, unambiguously.

## What changed

- `spec/schema/box.cue` — `#BuildFormat` gains `"apk"`. Regenerating is a no-op for the
  generated Go: the def carries `@go(-)`, so it produces no Go type, and `task cue:gen`
  on the changed tree touched only the two intended files.
- `spec/hostenv/hostdistro.go` — `distroIDToFormat` gains `"alpine": "apk"`.

## What is NOT claimed

`FormatForDistroID` answers "what package format does this distro use". It is **not** an
authority for "is this string a distro ID at all" — a neighbouring question it gets
mistaken for. Adding the `alpine` row makes the two questions agree for this one distro;
it does not make the table a distro-ID registry.
