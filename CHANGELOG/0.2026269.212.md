# 0.2026269.212 — fix(deploy+lock): discriminate the libvirt vm from the kubevirt venue by trait

fix(deploy+lock): split `SshVenue` from `IsVmVenue` by the `ExclusiveVenue` trait

Found while wiring the KubeVirt R10 beds (Phase 6 of the KubeVirt integration).

## R1 — the anomaly

`deploy.IsVmVenue` tested `node.Descent.Venue == "ssh"` **alone** and was the ONE
predicate every libvirt-domain consumer shared (`sdk/deploykit.BringUpMembers`/
`TearDownMembers`, `plugin-check`'s bed arm, `spec/lock.BedVmDomains`). But the
`ssh` venue is now shared by **two** substrates: the host-libvirt `vm` and
`kubevirt` (whose traits are `{Venue:"ssh", ImageBacked:true, BedTarget:true,
SupportsEphemeral:true, SupportsFromSnapshot:true}` — **no** `ExclusiveVenue`).

Consequence: a kubevirt deploy was classified as a host libvirt VM, so
`BringUpMembers`/the bed runner would run `charly vm build`/`vm create` against a
cluster-managed `VirtualMachine` CR, and `BedVmDomains` would take a host-global
libvirt domain lock for it. Venue ≠ substrate.

## Summary of changes

- **`deploy/deploy_ops.go`** — split the transport predicate from the substrate
  predicate, read BY TRAIT over the wire-stamped `node.Descent` (never by
  switching on the kind word — the kernel/plugin boundary law):
  - `SshVenue(node)` — the `ssh` transport hop (vm **and** kubevirt); the correct
    test for a caller that only needs an ssh executor.
  - `IsVmVenue(node)` — the host-libvirt vm: `SshVenue && ExclusiveVenue`.
    `ExclusiveVenue` is the host-resource lease boundary the traits table declares
    for `vm` and deliberately not for `kubevirt`.
- **`lock/bed_vm_domain.go`** — `BedVmDomains` repoints from the raw venue test to
  the shared `deploy.IsVmVenue`, so a kubevirt root/member contributes no
  host-global libvirt domain lock (R3 — one predicate).

A kubevirt node now correctly falls through to the default member arm —
`charly deploy add`/`del` — which the plugin-kubevirt lifecycle owns (no
`charly vm` involvement).

## How tested

### The discriminator, from its single source (raw, unedited)

```
$ git -C plugin-substrate show origin/main:candy/plugin-substrate/plugin.go | awk "/^var substrateTraits = map/,/^}/"
var substrateTraits = map[string]*spec.DeployTraits{
	"pod":        {Venue: "container", ImageBacked: true, ImageContext: true, BracketedLifecycle: true, BedTarget: true},
	"vm":         {Venue: "ssh", MachineVenue: true, ExclusiveVenue: true, BedTarget: true, SupportsEphemeral: true, SupportsFromSnapshot: true},
	"kubevirt":   {Venue: "ssh", ImageBacked: true, BedTarget: true, SupportsEphemeral: true, SupportsFromSnapshot: true},
	"local":      {Venue: "shell", MachineVenue: true, BedTarget: true},
	"kubernetes": {Venue: "shell", ImageContext: true, LeafOnly: true},
	"android":    {Venue: "parent", BedTarget: true},
	// kindcluster provisions node containers on the OPERATOR HOST engine at DEPLOY-ADD
	// (the deploy:kindcluster provider runs `kind create cluster` + applies the workload
	// itself) and manages NO charly-side container/VM lifecycle — so it is
	// EXTERNAL-IN-PLACE (venue "none", like android/exampledeploy), NOT a "shell"
	// service bed: the check runner must apply it in place during deploy add, never run
	// the pod-style `charly config`/`charly start` (measured: a shell venue made the
	// runner try `config` and fail with "image not found in local storage").
	// BedTarget: a disposable kindcluster bed runs a live cluster (the R10 beds).
	// SupportsEphemeral: the cluster is create/delete-able per run, and the ephemeral
	// TTL seam's reap-orphans liveness probe has a kindcluster arm.
	"kindcluster": {Venue: "none", ImageContext: true, LeafOnly: true, BedTarget: true, SupportsEphemeral: true},
}
```

(The `vm` row carries `ExclusiveVenue: true`; the `kubevirt` row does not — that one
bit is the entire discriminator.) `spec/spec/descent.go` copies those traits onto
`node.Descent` verbatim (`d.ExclusiveVenue = t.ExclusiveVenue`), so the predicate
reads the SAME value the provider declared.

**Why spec's own tests cannot read the live table.** `plugin-substrate` imports
`spec` (it declares `spec.DeployTraits`), so `spec` cannot import
`plugin-substrate` back to assert the table without an inverted dependency. The
derivation (`spec.DescentFromTraits`) IS in spec and IS tested here; the live trait
VALUES are asserted where the provider is compiled (the consumer) and in the live
bed.
