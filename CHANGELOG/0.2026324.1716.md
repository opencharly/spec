# 0.2026324.1716 — fix(refs): keep CHARLY_REPO_CACHE — no CHARLY_ environment variable is dropped

## Summary

Restores `CHARLY_REPO_CACHE` by **operator direction (2026-11-20): no CHARLY_ environment
variable is dropped.**

- **`refs.RepoCacheDir`** — when `CHARLY_REPO_CACHE` is set, its value is used **verbatim** as
  the remote-repo repos directory (its long-standing meaning); when unset, the `repos` entry
  under the one cache root is used (`CHARLY_CACHE_DIR/repos`, else
  `$XDG_CACHE_HOME/charly/repos`, D-STORE-1). A relative value stays relative.
- **`refs/cache_root_test.go`** — four arms: the variable wins verbatim, the cache-root
  fallback, the resolver's default, and the relative value verbatim.
- **DESIGN D-STORE-1** is amended in opencharly/opencharly#1210 to name this a **path-naming
  compatibility override, never a root override**: it moves only the repos directory and no
  root. That keeps the row's "single override `CHARLY_CACHE_DIR`" true for the roots.

Why restore rather than accept the deletion: spec#396 removed the variable on the reading that
D-STORE-1 admits one override, but the variable predates that row and names a **directory**,
not a root. Deleting it silently relocates an operator's repo cache and breaks every deployment
that sets it — which is exactly what the operator direction forbids.
