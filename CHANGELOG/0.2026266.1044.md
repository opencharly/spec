# 0.2026266.1044 — feat(cache): OCI Image Layout ArtifactStore — content-addressed, registry-portable

## Summary

Replaces `spec/cache.Store` (keyed, one-JSON-file-per-key) with **one content-addressed artifact store whose on-disk form is a standard OCI Image Layout** — `oci-layout` + `index.json` + `blobs/<alg>/<digest>`.

Each cached artifact is a real OCI **manifest**:
- `config` blob = the validity metadata (`resolved` / `components` / `validator`);
- `layers[0]` = the cached payload;
- `annotations` = the cache key (`ai.opencharly.cache.key`) + the tag (`org.opencontainers.image.ref.name`).

A **named cache is one OCI index**, so a whole store can be pushed to / pulled from an OCI registry unchanged (the `verb:oci` `cache-push`/`cache-pull` transport lands in the next, `plugin-oci` change). Docker cache principles throughout: content addressing, manifest/index entry point, tags for lookup, CAS blob reuse, and **no in-place mutation** (a write publishes new blobs + atomically swaps `index.json`).

The file backend uses **stdlib + `opencontainers/image-spec` + `opencontainers/go-digest` ONLY** — no `go-containerregistry` in the contract module (both promoted from indirect to direct).

**Changed files (14):** `cache/cache.go`, `cache/cache_test.go`; `refs/cache.go`, `refs/git.go`, `refs/cache_test.go`, `refs/git_test.go`, `refs/git_fresh_test.go`, `refs/submodule_cache_test.go`; `container/image_inspect.go`, `container/local_image_coneb.go`, `container/cache_test.go`, `container/engine_ops.go`, `container/engine_ops_test.go`; `go.mod`. The `container/engine_ops*.go` pair is the behavior-neutral lint fix described below; everything else is the cache cutover or its tests. (B15: 4 source commits + one or more tree-neutral body-only empty re-freeze commits, all non-changelog — intended as one squash-merge.)

The legacy `Store` API (`Open`/`OpenNamed`/`OpenLimited`/`Read`/`ReadTTL`/`WriteValue`) and the legacy void `Store.PutEntry`/`Store.Read`/`Store.Write` are **deleted in this change** (hard cutover, no shim). `Layout.PutEntry` is **retained** — it is the caller-controlled-`Resolved` write seam (the TTL-backdating test path), now returning an error; it is a new signature on the new type, not the legacy method. Consumers migrated **in this change**: `spec/refs` (submodule verdicts) and `spec/container` (image list, image labels). A second commit clears the module's `golangci-lint` findings — two in the changed files (`cache.go` staticcheck QF1008, `cache_test.go` SA4000) and **two pre-existing in `container/engine_ops.go` + `container/engine_ops_test.go`** (`gocritic` if/else-chain, `unconvert` double conversion); the latter are behavior-neutral (an `if/else-if` chain rewritten as a `switch`; a redundant `string()` on a `string`-typed value) and are fixed here because they block the module gate (R2).

### In-place mutation — the root cause this also removes

`repoCacheProvenanceVersion 2` **hard-rejects the legacy bare-commit sidecar**. A v1 export cannot certify its tree — the pre-cutover loader rewrote the fetched `charly.yml` **in place** (auto-migrating it to the consumer binary's schema CalVer) — so a v1 export is treated as *not cached* and re-fetched once pristine. `IsRepoCached` now enforces this, so **immutable-tag caches self-heal too** (the immutable short-circuit previously bypassed `repoCacheFresh` entirely). This is the proximate fix for the poisoned `~/.cache/charly/repos/github.com/opencharly/charly@main` (schema 261 in a 249 world) that failed `check-substrate`'s `deploy-add`.
