# 0.2026249.2215 — feat(spec): Threaded gains the deploy-substrate declared-fields channel (the #Deploy-schema twin of StructuralDeclaredFields)

## Summary

One data channel, zero hardcoded word lists: `Threaded.DeployDeclaredFields` maps a DEPLOY-SUBSTRATE word to the declared body FIELD NAMES of its registered input schema (for pod/vm/local/android/kubernetes that is the `#Deploy` family). The substrate-side twin of #104's `StructuralDeclaredFields`.

The sdk parse's in-substrate member scan (follow-up sdk PR) consults it so a substrate body's DECLARED `#Deploy` fields (`iterate`, `plan`, `record`, `disk_size`, `ram`, ...) stay DATA even when the field's VALUE SHAPE would classify as an in-substrate member — the proven sdk #221 parse regression: a pod primary body carrying the canonical ADE iterate pattern `iterate: {sandbox: ..., agent: [...], ...}` misparses because `agent` is a kind word, so the value-shape scan (`isEntityValue`) classifies `iterate:` as an in-substrate member named "iterate", `parseNode("iterate")` takes `agent` as ITS disc, and scalar `sandbox:` hard-fails "expected a mapping value, got yaml kind 8".

A substrate word absent from the map (no declared schema threaded) keeps the documented value-shape scan unchanged — the no-declared-schema fallback, mirroring #104's structural fallback.

No CUE schema change, no `cue:gen` (Threaded is a hand-written contract type); no migration.
