# 0.2026269.2355 — feat(schema): add kubevirt.source.disk_path_in_image

feat(schema): add `kubevirt.source.disk_path_in_image`

## Summary

A `kind:kubevirt` `container_disk` source may carry its disk at a path OTHER than
KubeVirt's scanned default (`/disk/disk.img`) — notably a charly VM box, whose
emission places the disk at `/disk.qcow2`. KubeVirt exposes `containerDisk.path` for
exactly this, but the schema had no way to author it.

Adds `disk_path_in_image?: string` to the `#KubevirtSource` `container_disk` arm
(CUE) and the matching `KubevirtSource.DiskPathInImage` field on the hand-built Go
union shape (`spec/union_types.go` — the union is `@go(-)`, per the #VmSource
precedent). Empty keeps KubeVirt's default `/disk` scan; set, the plugin renders the
VMI `containerDisk.path`.

Consumer: candy/plugin-kubevirt's `renderStorage` (a follow-up pin bump renders it),
which lets a charly VM box boot as a KubeVirt containerDisk without changing
plugin-vm's default box layout.

## R10 — this change class is BED-LESS (explicit)

This is a **schema field with no runtime path of its own**: it adds an authored
`disk_path_in_image` to `#KubevirtSource` and its hand-built Go union field. The
schema module has no deployable target, so there is nothing for a disposable bed to
exercise — the field has no runtime until a consumer renders it. Per the live-or-skip
rule, no bed is invented for a schema-only change.

The field's runtime render is proven at the consumer: candy/plugin-kubevirt's
`renderStorage` emits `containerDisk.path`, validated by its pin-bump follow-up (and
ultimately by the disposable `check-kubevirt-vm` bed, which authors
`disk_path_in_image: /disk/qcow2` for a charly VM box). The requirement was driven by
the real `check-kubevirt-vm` R10 runs (the box emission lands at `/disk.qcow2` under
plugin-vm's opt-in design, so KubeVirt needs the authored path).
