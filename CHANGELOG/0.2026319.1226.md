# 0.2026319.1226 — feat(loader): the seam exposes the gated entity validation

## Summary

`spec.ProjectLoader` gains `ValidateEntityCUEWithGates(kind, label, entity, gates)`.

Two constraints meet here, and one method resolves both:

1. **A kind whose authored body moved into a plugin validates only through its DECLARED gate.** The base table's entry for such a kind is whatever keeper remained — for `vm` it is `#ResolvedVm`, the **post-default envelope** (`autostart`, `firmware`, `backend` all required), which no authored document can satisfy. That is the red `charly`'s schema-tightening corpus hit (`autostart: field is required but not present`).
2. **The host may not import the sdk mechanism kits.** `charly`'s import-purity gate forbids `github.com/opencharly/sdk/loaderkit` in core — those kits are for plugins — so the host cannot call the SDK's function directly.

The seam is how the host reaches every other loader capability, so the gated validation travels over it too. `loaderkit` implements it (that kit is for plugins, and `plugin-loader` is a plugin), and `charly` calls it through the interface with the threaded snapshot.

This is the third consumer of `opencharly/opencharly#1048`'s authored-vs-wire distinction: the gate path (`spec#328`), the validation resolution (`sdk#527`), and now the seam the host reaches it through.
