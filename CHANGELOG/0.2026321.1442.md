# 0.2026321.1442 — feat(schema): give provide: an author — the 8 set surface, with the guard that keeps its window from drifting

## Summary

**`provide:` had no author. Now it has one, and a guard that keeps the window from drifting.**

`DESIGN.md:572` spells the authored form — `provide: {<type>: {<name>: <attributes>}}` — and `:567` says *"this node SETS it"*. `#Provide` already existed in the capability table (`schema/capability.cue:181`), derived from the same `_capability` rows as `#Need`/`#Use`. **What was missing was the key that lets a node author one**, measured:

```console
$ git -C spec grep -n -E '^\s*provide\??:' origin/main -- 'schema/*.cue'
(nothing)                      # no authored KEY lets a node write one
$ git -C spec grep -n '^#Provide' origin/main -- 'schema/*.cue'
schema/capability.cue:181:#Provide: {for t, c in _capability if c.provide != _|_ {(t)?: {[c.key]: c.provide}}}
$ git -C spec grep -n 'env_provide\|mcp_provide\|agent_provide' schema/candy.cue
145, 150, 151                  # the only AUTHORED provides are the legacy maps
```

**The distinction is the whole PR:** `#Provide` — the SHAPE — has existed all along at `capability.cue:181`, derived from the same `_capability` rows as `#Need`/`#Use`. What was missing is the **key** on a candy that lets a node author one. The shape and the author are different absences, and only the second was the gap.

The diff is one line, beside `need?:`/`use?:` and mirroring them exactly:

```cue
	provide?: #Provide @go(Provide,optional=nillable)
```

**Nothing beside the contract.** The shape is DESIGN's; the key is what was absent.

### The guard — R2 enforced, not commented

A node that authors BOTH surfaces is a schema error, and the error **carries the rule**:

```cue
	if provide != _|_ && (env_provide != _|_ || mcp_provide != _|_ || agent_provide != _|_) {
		// The field NAME is the message: CUE reports it in the conflict.
		"author either provide: or a legacy provide map, never both (spec#368)": string & 1
	}
```

This is what keeps the deprecation window from becoming permanent duplication. **Migration is allowed — old to new, one node at a time. Growing a second surface is not.**

(It first failed for the right reason: a bare `_|_` reports only `explicit error (_|_ literal) in source` and names nothing. A refusal a reader cannot understand is not a guard, so it became a named field carrying the rule and the issue number.)

### And the same refusal at the earliest possible layer

Authoring `provide: {secret: …}` is **refused at the schema**, because `secret` has no provide row in the capability table. That is the schema-level twin of `charly#1190`'s runtime `ErrNoProvideSurface` — **the same rule, caught one layer earlier, from the same contract row.** A shape with no provider cannot be authored, and cannot be resolved; both halves now say so.
