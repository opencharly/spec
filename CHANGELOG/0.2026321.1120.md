**feat(schema): port the authored capability-ask surface from DESIGN.cue**


The §8/§9 capability surface existed in DESIGN.cue and in NO shipped file: `grep -rn
'#Need|#Use|#Provide|#CandyNeed|#CandyUse|_capability' schema/*.cue` returned nothing and
#Candy carried no need?:/use?:. This moves DESIGN.cue's own declaration into the contract
module — the M4 host words (:217-244), the table and its shapes (:466-537), the M3 driver
table its driver_api row keys off (:113-146, :245-274), and the role vocabulary its last row
loops over (:1138) — and wires it: need?: #CandyNeed / use?: #CandyUse on #Candy and
#CandyModel with @go(Need,optional=nillable)/@go(Use,optional=nillable). NAMES, WORD TABLES
and FIELD SETS are DESIGN's; the primitives the module already declares (#Word, #Ref, #Text,
#Count, #Size, #AbsPath, #SecretUse) are REUSED, never re-declared.

Two syntactic deviations, both forced and both documented in the file: DESIGN writes its
embeddings with the postfix `...`, which CUE v0.16.1 refuses without
@experiment(explicitopen) (DESIGN.cue itself does not compile under this toolchain), so the
shapes are plain embeddings — verified equivalent, a leasable entry gains `exclusive: false`
and a non-leasable one does not; and each table is ONE declaration carrying its row pattern
inside the row literal, because the module's S3 gate reads a table as one struct literal
while `cue` still refuses to iterate a pattern into the derived list (measured: `_deviceWord`
is the eight host nodes, not the pattern).

THE FINDING (spec#355). The module's §10.1 S3 gate and DESIGN.cue were developed against
different shapes, and this port is the first place they meet. It carried five refusals, none
of them a defect in the port: the two-declaration table; four one-word tables (_isolation,
_privilege, _cpu, _storage are ROWS of _capability, not vocabularies); a filter-derived word
list (_leasableWord); and _capability/_role cited only inside comprehensions, which the
gate's source scan could not see. The gate now reads all four, each rule carrying the case
that earned it:

  - a table cited from INSIDE another table's rows is exempt from the single-row rule (it is
    that table's row); a standalone one-row table is still refused — control run and pasted
    below;
  - a `_xWord` defined as a list comprehension over another table resolves as a declared list
    rather than "no file declares it";
  - a `for k, v in _x` comprehension COUNTS AS A CITATION of `_x` (that is how `_role` reaches
    `_capability`, and how `_capability` reaches #Need/#Use/#Provide);
  - "the list derives from the table" is now asked of the table's EVALUATED key set, because
    the AST can see neither a comprehension's rows nor a pattern's — the mutation half still
    injects a row into every table and requires the derived list to gain it.

CONTROLS, so the new rules cannot be a rubber stamp: a standalone one-row table planted in
the schema still fails ("table _zzProbe has 1 row(s) — a one-word table is not a closed set of
words"); and a restated _capabilityWord (16 literal words) still fails ("_capabilityWord is
[...] but the _capability table's own keys are [...] — the list is restated, not derived").

THE GENERATOR GAP (spec#271), named honestly: `cue exp gengotypes` collapses every regex- or
disjunction-keyed map to `struct{}` — measured in isolation, `#A: {[#Word]: {count: int}}`
generates `type A struct {}` while `#D: {[string]: int}` generates `map[string]int64`. So
spec.Need/spec.Use/spec.Provide carry the 21 type keys correctly (pinned by
TestTheNeedUseProvideAreDerivedFromTheTable) but each per-type map is `struct{}`: a caller can
express THAT it needs a cpu and not WHAT it needs. The schema was NOT flattened to `[string]`
to work around it — that would make the generator's gap permanent in the contract.

THE COLLISION EVIDENCE, and why the port waited for two renames. Three of DESIGN's generic
words had been spent by other files on vendor detail, and CUE merges same-name definitions
SILENTLY: `_deviceWord` evaluated to 14 words (8 host nodes + 6 libvirt video devices) and
`_driverWord` to 17 (14 drivers + 3 libvirt fs drivers), `cue eval` exiting 0 for the merged
and the correct vocabulary alike — only a test that REFUSES the wrong value told them apart.
`_access` was the same. After spec#354 (`_access` → `_volumeAccessMode`) and spec#356
(`_device`/`_driver` → `_libvirtVideoDevice`/`_libvirtFilesystemDriver`) the shipped trees
carry DESIGN's alone:

  _deviceWord  -> ["kvm","render","fuse","tun","vhost_net","vsock","hwrng","kfd"]
  _driverWord  -> ["podman","docker","containerd","libvirt","qemu","krun","firecracker",
                   "kind","k3s","pi","tmux","secret_service","gpg","file"]
  _accessWord  -> ["exec","copy","log","console","display","forward","power"]

### The seven new primitives do not duplicate anything

The port adds `#Name`, `#EnvName`, `#Port`, `#Hostname`, `#InitNeutral`, `#TextSet` and `#NativeRow`. A CUE
definition merged silently with an existing same-name one would be the exact collision `spec#355` records,
so each is checked for a single declaration **inside the schema package every consumer compiles**:

```console
$ for d in '#Name' '#EnvName' '#Port' '#Hostname' '#InitNeutral' '#TextSet' '#NativeRow'; do
    printf '%s -> %s\n' "$d" "$(grep -rln "^$d:" schema/*.cue)"; done
#Name        -> schema/capability.cue
#EnvName     -> schema/capability.cue
#Port        -> schema/capability.cue
#Hostname    -> schema/capability.cue
#InitNeutral -> schema/capability.cue
#TextSet     -> schema/capability.cue
#NativeRow   -> schema/capability.cue
```

**One declaration each, all in `capability.cue`, and that is the whole of `schema/`.** `#Name` also appears in
`DESIGN.cue` itself, where it is narrower — but DESIGN.cue is the design source, not a member of the `schema`
package that `//go:embed *.cue` compiles, so it cannot merge with this one. That is why the grep's scope is
`schema/*.cue` and not the whole tree: **the merge `spec#355` records happens between files that share a CUE
package**, and `DESIGN.cue` is not one of them.

Had the port's `#Name` landed in a package that already had one, `go build` would still pass — which is why
the grep is the check and the build is not.

## What this PR does NOT deliver, stated plainly

`spec#271`: `cue exp gengotypes` collapses every regex-keyed map to `struct{}`, so `spec.Need`,
`spec.Use` and `spec.Provide` carry the right 21 type **keys** but **empty per-type entry bodies**. A caller
can express *that* it needs a cpu and not *what*. The schema was deliberately **not** flattened to
`[string]` to work around it, because that would make the generator's gap permanent in the contract. The
five consuming units can validate a `need:` document against CUE today; they cannot yet read entry payloads
through `spec.Need`. **That is `spec#271`'s scope, and the port is additive and safe to land now.**
